1"""The semantic and lexical bridge behind the public functions (design §3.4). 

2 

3An agent writes `FROM semantic_claims($1, 20)` and gets confirmed rows. The P1 

4statement ranks through the same PostgreSQL authority joins used by the rest 

5of the surface, then bounded hydration re-confirms exact identities before any 

6row is exposed. Nomination proposes; PostgreSQL disposes (D48). 

7 

8**Where this runs, and why.** The binding design places the bridge in the 

9executor because semantic invocations need a model-produced query vector before 

10untrusted procedural language, which this product does not install. The grammar 

11has already rewritten each accepted invocation into its own `MATERIALIZED` CTE, 

12and the executor 

13replaces that CTE with the confirmed rows before the statement is planned. The 

14caller-visible contract is unchanged — same call syntax, same columns, same 

15per-invocation caps, same confirmation before exposure — and the deviation is 

16recorded historically in `plan/implementation_notes/open_query_space_batch_c.md`. 

17"""

297def bounded_k(*, requested: object, settings: BridgeSettings) -> int: 

298 """The effective k, clamped to the tier's cap and the request's budget.""" 

299 if requested is None: 

300 k = settings.k_default 

301 elif isinstance(requested, bool) or not isinstance(requested, int): 

302 raise SandboxRejection( 

303 code=QueryErrorCode.INVALID_PARAMETER, message="k must be an integer" 

304 ) 

305 else: 

306 k = requested 

307 if k < 1: 

308 raise SandboxRejection( 

309 code=QueryErrorCode.INVALID_PARAMETER, message="k must be at least 1" 

310 ) 

311 k = min(k, settings.k_max) 

312 remaining = settings.total_nominations_max - settings.nominations_used 

313 if remaining <= 0: 

314 raise SandboxRejection( 

315 code=QueryErrorCode.QUOTA_EXCEEDED, 

316 message="the statement's nomination budget is spent", 

317 )
