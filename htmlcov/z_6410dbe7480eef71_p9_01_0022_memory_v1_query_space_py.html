1"""Create the versioned `memory_v1` invariant-compiled query-space schema. 

2 

3The open query space makes PostgreSQL the public data language: agents write 

4ordinary SQL against `memory_v1`, and the views below — not caller discipline 

5— compile the three row-level invariants that make an arbitrary query 

6trustworthy. 

7 

8- **D48 (deletion is fail-closed).** Every lineage path is an INNER JOIN or 

9 `EXISTS` chain through a surviving `documents` row (and, for version-derived 

10 rows, a non-tombstoned `document_versions` row; and, for current-content 

11 rows, the lineage's current version and current ready representation). The 

12 legacy permissive form — `LEFT JOIN documents ... WHERE d.doc_id IS NULL OR 

13 d.deleted_at IS NULL`, which lets an orphan through — appears nowhere here. 

14- **D41 (two clocks, one instant).** `facts_current` and 

15 `graph_edges_current` evaluate exactly one `statement_timestamp()` and emit 

16 it as `evaluated_at`, so every reference to a current relation inside one 

17 SQL statement answers at the same instant. Fact world-validity is half-open 

18 `[valid_from, valid_until)`; claim validity stays immutable source testimony 

19 and never answers what currently holds. 

20- **D54 (counting has one meaning).** `evidence_lineage` is the sole public 

21 input for evidence counts: one row per fact × current-testimony document 

22 lineage × stance. Repetition inside one document, and re-extraction of the 

23 same document, therefore cannot inflate a count. `support_state` is derived 

24 at read time from the open `support_withdrawn` review row exactly as the 

25 shipped query engine derives it; there is deliberately no stored column that 

26 could drift from that queue. 

27 

28Base tables stay private: the schema contains exactly the relations the 

29binding design enumerates, and nothing else. Three private helper views (in 

30`public`, never granted) carry the logic two public relations would otherwise 

31have to state twice: `v_memory_entity_survivor` resolves merge redirects, 

32because a merge is a redirect rather than a rewrite and relations are not 

33re-pointed in PostgreSQL; `v_memory_mention_current_content` is the one 

34definition of "this mention occurs in current content and resolves here", so a 

35mention count and the mention transcript cannot disagree; and 

36`v_memory_page_citation_visible` is the one definition of "this citation's 

37target is visible", so a page's membership gate and its per-link gate cannot 

38disagree.

130# ── private helper ──────────────────────────────────────────────────────── 

131# A merge is a REDIRECT (entities.merged_into), never a rewrite, and relations 

132# keep their original endpoint ids, so every entity reference must be resolved 

133# to its terminal survivor before it is exposed or joined. This helper is NOT 

134# part of memory_v1: it stays in the private schema and is never granted. 

135# 

136# The walk is FAIL-CLOSED. Acyclicity is not schema-enforced, so a chain can be 

137# a cycle (A merged into B, B merged into A), can run longer than the depth 

138# bound, or can point at an entity row that no longer exists. In every one of 

139# those cases the walk never reaches a row with merged_into IS NULL, and the 

140# final join to that terminal row therefore emits NOTHING: the entity resolves 

141# to no survivor and disappears from entities_current and from every relation 

142# that joins a survivor. The alternative — taking the deepest row reached — is 

143# fail-open: a two-node cycle would make each entity its own "survivor" and 

144# both would be exposed as if the merge had never happened. The operator 

145# quarantine report counts entities in this state so the omission is visible. 

146_HELPER_DDL = r"""CREATE VIEW v_memory_entity_survivor ( 

147 deployment_id, 

148 entity_id, 

149 survivor_entity_id 

150) AS 

151WITH RECURSIVE chain(deployment_id, entity_id, cur, depth) AS ( 

152 SELECT deployment_id, entity_id, entity_id, 0 FROM entities 

153 UNION ALL 

154 SELECT c.deployment_id, c.entity_id, e.merged_into, c.depth + 1 

155 FROM chain AS c 

156 JOIN entities AS e 

157 ON e.deployment_id = c.deployment_id 

158 AND e.entity_id = c.cur 

159 WHERE e.merged_into IS NOT NULL AND c.depth < 64 -- cycle / runaway guard 

160) 

161SELECT c.deployment_id, c.entity_id, c.cur 

162FROM chain AS c 

163JOIN entities AS terminal 

164 ON terminal.deployment_id = c.deployment_id 

165 AND terminal.entity_id = c.cur 

166 AND terminal.merged_into IS NULL; -- only a terminated chain resolves 

167COMMENT ON VIEW v_memory_entity_survivor IS 

168 'Private merge-redirect resolution: maps an entity id to the terminal survivor of its merged_into chain. Resolution is fail-closed because acyclicity is not schema-enforced: a chain that does not reach an unmerged entity within the depth bound — a cycle, an over-long chain, or a redirect to a missing row — yields no row at all, so the entity is absent from every survivor-joined relation rather than being exposed as its own survivor. Not part of memory_v1 and never granted to a query role.'; 

169"""
