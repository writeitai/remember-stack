1"""D140 effective periods, section keys, text origin, and version-grain references. 

2 

3Every schema object of the D140 design (effective time and section references) 

4lands in this one revision: 

5 

6- **Effective time.** ``document_versions.version_key`` (a caller-chosen, 

7 immutable version address, unique per lineage), the declaration ledger 

8 ``document_effective_periods``, the lineage mode ledger 

9 ``document_effective_time_events`` and the current-belief selection 

10 projection ``document_version_scope``. The projection is maintained by 

11 database triggers in the transaction of every write that can change it (a 

12 declaration or retraction, a mode event, a version becoming ready or current, 

13 a version or lineage deletion) through ``refresh_document_version_scope``, 

14 which rewrites one lineage's rows. The triggers are constraint triggers 

15 deferred to commit: the rewrite then sees the transaction's final state 

16 once, and its per-lineage lock is taken after every row lock the writer 

17 holds, so it cannot join a writer's lock order (an ingest holding the 

18 lineage row while a version finishes processing would otherwise deadlock). It is filled here for every existing 

19 lineage: all are undeclared, so each served version gets an unbounded range 

20 and every other version an empty one. 

21- **Public time-scope surface.** ``memory_v1.effective_intervals``, 

22 ``memory_v1.versions_in_scope`` and ``memory_v1.fact_in_scope_support`` 

23 (``SECURITY DEFINER`` owned by the view owner, since they read private 

24 ledgers), the views ``memory_v1.document_effective_periods_live`` and 

25 ``memory_v1.chunks_all_versions_live``, and the new trailing columns of 

26 ``sections_live`` (section key and content hashes) and ``chunks_live`` 

27 (text origin time). 

28- **Sections and chunks.** Nullable ``section_key``, ``own_content_hash`` and 

29 ``subtree_content_hash`` on ``document_sections`` (a key is unique within a 

30 structure generation) and nullable ``text_origin_at`` and 

31 ``reuse_identity_hash`` on ``chunks``. Existing rows keep NULL: sections are 

32 backfilled by a maintenance job, and pre-D140 chunks are never matched by 

33 the text-origin lookup. 

34- **References.** ``crossref_kind`` gains ``refers_to``, ``amends`` and 

35 ``implements``; ``crossref_binding`` and ``crossref_origin`` are new; 

36 ``document_reference_generations`` is new; ``document_crossrefs`` is 

37 recreated at version grain. No code on the prior revision writes that table, 

38 so the migration refuses a store in which it holds rows rather than guessing 

39 a version and generation for them. The enum is recreated rather than 

40 extended because the new table's CHECK constraints compare with ``amends``, 

41 and PostgreSQL forbids using an enum value added in the same transaction. 

42 The public view, the private graph source view (now one edge per lineage 

43 pair and kind among the references of the versions in force now) and the 

44 live property graph are recreated in the same transaction, with their grants. 

45 

46The downgrade refuses when any D140 data exists — a declaration or mode event 

47(live or retracted), a version key, or a reference generation — because none 

48of it can be re-derived. Otherwise it restores the prior objects exactly.

205CREATE FUNCTION refresh_document_version_scope(p_deployment_id uuid, p_doc_id uuid) 

206RETURNS void 

207LANGUAGE plpgsql 

208VOLATILE 

209SET search_path = pg_catalog, public, pg_temp 

210AS $$ 

211BEGIN 

212 -- Current belief is every live declaration and the latest mode event, 

213 -- evaluated at infinity: writers stamp rows with the instant they took 

214 -- after locking the lineage, which is later than this transaction's now(). 

215 -- One rewrite of a lineage at a time: concurrent writers of the same lineage 

216 -- would otherwise each delete the rows they can see and collide on insert. 

217 -- The triggers are deferred to commit, so this lock is taken after the 

218 -- transaction's own row locks and never inside another writer's lock order. 

219 PERFORM pg_advisory_xact_lock( 

220 hashtextextended( 

221 'document_version_scope:' || p_deployment_id::text || ':' || p_doc_id::text, 0 

222 ) 

223 ); 

224 DELETE FROM public.document_version_scope 

225 WHERE deployment_id = p_deployment_id AND doc_id = p_doc_id; 

226 INSERT INTO public.document_version_scope ( 

227 deployment_id, doc_id, version_id, in_force, periodised, selectable 

228 ) 

229 WITH lineage AS ( 

230 SELECT d.deployment_id, d.doc_id, d.current_version_id, 

231 public.document_periodised_at( 

232 d.deployment_id, d.doc_id, 'infinity' 

233 ) AS periodised 

234 FROM public.documents AS d 

235 WHERE d.deployment_id = p_deployment_id 

236 AND d.doc_id = p_doc_id 

237 AND d.deleted_at IS NULL 

238 ), 

239 intervals AS ( 

240 SELECT i.version_id, 

241 range_agg(tstzrange(i.effective_from, i.effective_until, '[)')) AS in_force 

242 FROM public.document_effective_intervals_at( 

243 p_deployment_id, ARRAY[p_doc_id], 'infinity' 

244 ) AS i 

245 GROUP BY i.version_id 

246 ) 

247 SELECT 

248 v.deployment_id, 

249 v.doc_id, 

250 v.version_id, 

251 CASE 

252 WHEN l.periodised THEN coalesce(i.in_force, '{}'::tstzmultirange) 

253 WHEN v.version_id = l.current_version_id THEN '{(,)}'::tstzmultirange 

254 ELSE '{}'::tstzmultirange 

255 END, 

256 l.periodised, 

257 v.status = 'ready' AND r.representation_id IS NOT NULL 

258 FROM lineage AS l 

259 JOIN public.document_versions AS v 

260 ON v.deployment_id = l.deployment_id 

261 AND v.doc_id = l.doc_id 

262 AND v.deleted_at IS NULL 

263 LEFT JOIN intervals AS i ON i.version_id = v.version_id 

264 LEFT JOIN public.document_representations AS r 

265 ON r.deployment_id = v.deployment_id 

266 AND r.version_id = v.version_id 

267 AND r.representation_id = v.current_representation_id 

268 AND r.status = 'ready'; 

269END 

270$$;

1747def _legacy_statements(*, sql: str, first: str) -> tuple[str, ...]: 

1748 """The statements of one legacy object: its CREATE and what follows it. 

1749 

1750 Collects from the statement starting with ``first`` up to (excluding) the 

1751 next ``CREATE TABLE``/``CREATE VIEW``, so a table keeps its comment and 

1752 indexes and a view its comment. 

1753 """ 

1754 from rememberstack.spine.migrations._helpers import _split_sql

1756 collected: list[str] = [] 

1757 for statement in _split_sql(sql=sql): 

1758 body = "\n".join( 

1759 line for line in statement.splitlines() if not line.startswith("--") 

1760 ).strip() 

1761 if collected: 

1762 if body.startswith(("CREATE TABLE", "CREATE VIEW", "CREATE PROPERTY")): 

1763 break 

1764 collected.append(statement) 

1765 elif body.startswith(first): 

1766 collected.append(statement)
