1"""Create the bounded graph helpers ``graph_neighborhood`` and ``graph_path``. 

2 

3Design §3.4 lists both as public SQL functions and §4.3 gives their bounds. 

4Which edges they walk depends on what was asked. With no instants supplied 

5they read `memory_v1.graph_edges_current`, so a traversal and a direct read of 

6the current graph can never disagree about what is current; a helper that 

7walked relations the current view adjudicates away would contradict the very 

8view it is a shortcut for. With `valid_at` or `believed_at` supplied they read 

9`memory_v1.graph_edges_visible_history` under both clocks, each applied as a 

10half-open interval per D41 — a relation that stopped holding exactly at the 

11asked instant no longer holds at it. 

12 

13Every bound is clamped inside the function, so it holds however the function is 

14called, and each traversal is ordered deterministically before it is cut off — 

15an unordered LIMIT would return a different subgraph on every run and make the 

16bound meaningless rather than merely tight. 

17 

18Traversal is undirected. A relation is an assertion about two entities, and an 

19agent asking "what is connected to this person" means both the relations where 

20they are the subject and the ones where they are the object; a direction-only 

21walk would silently answer half the question. The edge rows keep their real 

22subject and object, so a caller who cares about direction can still see it. 

23"""

134# The edge source is chosen by the question, not by convenience. With no 

135# instants the walk reads `graph_edges_current`, so a traversal and a direct 

136# read of the current graph never disagree about what is current — a helper 

137# that quietly walked adjudicated-away relations would contradict the view it 

138# is supposed to be a shortcut for. With either instant supplied the walk reads 

139# the history view under both D41 clocks, half-open.

141 SELECT 

142 c.deployment_id, c.relation_id, c.subject_entity_id, c.object_entity_id, 

143 c.predicate, c.fact_label, c.valid_from, c.valid_until, c.ingested_at, 

144 NULL::timestamptz AS invalidated_at, c.contradiction_group, c.confidence, 

145 c.evidence_count AS evidence_count_current, 

146 c.contradict_count AS contradict_count_current, 

147 c.support_state AS support_state_current 

148 FROM memory_v1.graph_edges_current AS c 

149 WHERE {function}.valid_at IS NULL 

150 AND {function}.believed_at IS NULL 

151 AND ({function}.predicates IS NULL 

152 OR c.predicate = ANY({function}.predicates)) 

153 UNION ALL 

154 SELECT 

155 h.deployment_id, h.relation_id, h.subject_entity_id, h.object_entity_id, 

156 h.predicate, h.fact_label, h.valid_from, h.valid_until, h.ingested_at, 

157 h.invalidated_at, h.contradiction_group, h.confidence, 

158 h.evidence_count_current, h.contradict_count_current, 

159 h.support_state_current 

160 FROM memory_v1.graph_edges_visible_history AS h, bounds AS b 

161 WHERE ({function}.valid_at IS NOT NULL 

162 OR {function}.believed_at IS NOT NULL) 

163 -- A null endpoint is an OPEN interval on both clocks. Treating a null

167 AND (h.invalidated_at IS NULL OR h.invalidated_at > b.as_of_believed) 

168 AND (h.valid_from IS NULL OR h.valid_from <= b.as_of_valid) 

169 AND (h.valid_until IS NULL OR h.valid_until > b.as_of_valid) 

170 AND ({function}.predicates IS NULL 

171 OR h.predicate = ANY({function}.predicates))

174_NEIGHBORHOOD_DDL = f""" 

175CREATE FUNCTION memory_v1.graph_neighborhood( 

176 start_entity_id uuid, 

177 max_depth integer DEFAULT 2, 

178 predicates text[] DEFAULT NULL, 

179 valid_at timestamptz DEFAULT NULL, 

180 believed_at timestamptz DEFAULT NULL, 

181 max_edges integer DEFAULT 100 

182) 

183RETURNS TABLE ( 

184 path_id bigint, 

185 hop integer, 

186 path_position integer, 

187 from_entity_id uuid, 

188 to_entity_id uuid, 

189{_EDGE_COLUMNS}, 

190 applied_valid_at timestamptz, 

191 applied_believed_at timestamptz 

192) 

193LANGUAGE plpgsql 

194STABLE 

195PARALLEL UNSAFE 

196SECURITY INVOKER 

197SET search_path = memory_v1, pg_catalog 

198SET join_collapse_limit = 1 

199SET from_collapse_limit = 1 

200AS $$ 

201#variable_conflict use_column 

202BEGIN 

203 IF (graph_neighborhood.valid_at IS NULL) 

204 <> (graph_neighborhood.believed_at IS NULL) THEN 

205 RAISE EXCEPTION 

206 'a bitemporal traversal takes both clocks or neither' 

207 USING ERRCODE = 'invalid_parameter_value'; 

208 END IF; 

209 RETURN QUERY 

210 WITH RECURSIVE bounds AS ( 

211 SELECT 

212 least(greatest(coalesce(max_depth, 2), 1), {_NEIGHBORHOOD_DEPTH_MAX}) 

213 AS depth_cap, 

214 least(greatest(coalesce(max_edges, 100), 1), {_NEIGHBORHOOD_EDGES_MAX}) 

215 AS edge_cap, 

216 -- Both instants or neither. Supplying one and letting the other default 

217 -- to now() answers a bitemporal question nobody asked: "as the world was 

218 -- then, as we believe it now" is a third thing, and returning it under 

219 -- the caller's one-clock request would misreport what it means. 

220 -- `statement_timestamp()`, not `now()`. `now()` is transaction start, 

221 -- while `graph_edges_current` evaluates at statement time, so a row 

222 -- selected by one instant was being labelled with an earlier one. 

223 coalesce(valid_at, statement_timestamp()) AS as_of_valid, 

224 coalesce(believed_at, statement_timestamp()) AS as_of_believed 

225 ), 

226 edges AS MATERIALIZED (\n@@EDGE_SOURCE@@\n ), 

227 walk AS ( 

228 SELECT 

229 e.relation_id, 

230 1 AS hop, 

231 graph_neighborhood.start_entity_id AS from_entity_id, 

232 CASE 

233 WHEN e.subject_entity_id = graph_neighborhood.start_entity_id 

234 THEN e.object_entity_id ELSE e.subject_entity_id 

235 END AS to_entity_id, 

236 ARRAY[e.relation_id] AS seen_relations, 

237 ARRAY[ 

238 graph_neighborhood.start_entity_id, 

239 CASE 

240 WHEN e.subject_entity_id = graph_neighborhood.start_entity_id 

241 THEN e.object_entity_id ELSE e.subject_entity_id 

242 END 

243 ] AS seen_nodes 

244 FROM edges AS e 

245 WHERE graph_neighborhood.start_entity_id 

246 IN (e.subject_entity_id, e.object_entity_id) 

247 UNION ALL 

248 SELECT 

249 e.relation_id, 

250 w.hop + 1, 

251 w.to_entity_id, 

252 CASE 

253 WHEN e.subject_entity_id = w.to_entity_id 

254 THEN e.object_entity_id ELSE e.subject_entity_id 

255 END, 

256 w.seen_relations || e.relation_id, 

257 w.seen_nodes || CASE 

258 WHEN e.subject_entity_id = w.to_entity_id 

259 THEN e.object_entity_id ELSE e.subject_entity_id 

260 END 

261 FROM walk AS w 

262 JOIN edges AS e 

263 ON w.to_entity_id IN (e.subject_entity_id, e.object_entity_id) 

264 CROSS JOIN bounds AS b 

265 -- A relation is walked at most once per branch: without this the walk 

266 -- oscillates across the same edge forever and the depth bound is the only 

267 -- thing that ends it, at exponential cost. 

268 WHERE NOT (e.relation_id = ANY(w.seen_relations)) 

269 AND w.hop < b.depth_cap 

270 -- Simple branches only: distinct parallel edges do not make revisiting 

271 -- an entity a new route, and cycles must not multiply the neighborhood. 

272 AND NOT ( 

273 CASE 

274 WHEN e.subject_entity_id = w.to_entity_id 

275 THEN e.object_entity_id ELSE e.subject_entity_id 

276 END = ANY(w.seen_nodes) 

277 ) 

278 ), 

279 cap_status AS MATERIALIZED ( 

280 SELECT 

281 (SELECT count(*) FROM walk) > b.edge_cap 

282 OR EXISTS ( 

283 SELECT 1 

284 FROM walk AS w 

285 JOIN edges AS e 

286 ON w.to_entity_id IN (e.subject_entity_id, e.object_entity_id) 

287 WHERE w.hop = b.depth_cap 

288 AND NOT (e.relation_id = ANY(w.seen_relations)) 

289 AND NOT ( 

290 CASE 

291 WHEN e.subject_entity_id = w.to_entity_id 

292 THEN e.object_entity_id ELSE e.subject_entity_id 

293 END = ANY(w.seen_nodes) 

294 ) 

295 ) AS reached 

296 FROM bounds AS b 

297 ), 

298 bounded AS ( 

299 SELECT w.*, row_number() OVER ( 

300 ORDER BY w.hop, w.relation_id, w.to_entity_id 

301 ) AS path_id 

302 FROM walk AS w 

303 ORDER BY w.hop, w.relation_id, w.to_entity_id 

304 LIMIT (SELECT edge_cap FROM bounds) 

305 ), 

306 result_rows AS MATERIALIZED ( 

307 SELECT 

308 bounded.path_id, 

309 bounded.hop, 

310 bounded.hop AS path_position, 

311 bounded.from_entity_id, 

312 bounded.to_entity_id, 

313 e.relation_id, 

314 e.subject_entity_id, 

315 e.object_entity_id, 

316 e.predicate, 

317 e.fact_label, 

318 e.valid_from, 

319 e.valid_until, 

320 e.ingested_at, 

321 e.invalidated_at, 

322 e.contradiction_group, 

323 e.confidence, 

324 e.evidence_count_current, 

325 e.contradict_count_current, 

326 e.support_state_current, 

327 b.as_of_valid AS applied_valid_at, 

328 b.as_of_believed AS applied_believed_at 

329 FROM bounded 

330 JOIN edges AS e ON e.relation_id = bounded.relation_id 

331 CROSS JOIN bounds AS b 

332 ), 

333 cap_state AS MATERIALIZED ( 

334 SELECT set_config( 

335 'rememberstack.graph_cap_reached', 

336 ( 

337 coalesce( 

338 current_setting('rememberstack.graph_cap_reached', true), 'false' 

339 )::boolean 

340 OR cap_status.reached 

341 )::text, 

342 true 

343 ) AS marker 

344 FROM cap_status 

345 ), 

346 marked_rows AS MATERIALIZED ( 

347 -- The left join deliberately produces one private marker row even when a 

348 -- tight budget leaves no public row. The outer filter removes it, while 

349 -- the executor can still read the transaction-local cap flag. 

350 SELECT result_rows AS row_value, cap_state.marker 

351 FROM cap_state 

352 LEFT JOIN result_rows ON true 

353 ) 

354 SELECT (mr.row_value).* 

355 FROM marked_rows AS mr 

356 WHERE (mr.row_value).path_id IS NOT NULL 

357 ORDER BY (mr.row_value).path_id; 

358END 

359$$; 

360"""

363CREATE FUNCTION memory_v1.graph_path( 

364 from_entity_id uuid, 

365 to_entity_id uuid, 

366 max_depth integer DEFAULT 4, 

367 predicates text[] DEFAULT NULL, 

368 valid_at timestamptz DEFAULT NULL, 

369 believed_at timestamptz DEFAULT NULL, 

370 max_paths integer DEFAULT 3, 

371 max_edges integer DEFAULT 100 

372) 

373RETURNS TABLE ( 

374 path_id bigint, 

375 path_length integer, 

376 path_position integer, 

377 step_from_entity_id uuid, 

378 step_to_entity_id uuid, 

379{_EDGE_COLUMNS}, 

380 applied_valid_at timestamptz, 

381 applied_believed_at timestamptz 

382) 

383LANGUAGE plpgsql 

384STABLE 

385PARALLEL UNSAFE 

386SECURITY INVOKER 

387SET search_path = memory_v1, pg_catalog 

388SET join_collapse_limit = 1 

389SET from_collapse_limit = 1 

390AS $$ 

391#variable_conflict use_column 

392BEGIN 

393 IF (graph_path.valid_at IS NULL) <> (graph_path.believed_at IS NULL) THEN 

394 RAISE EXCEPTION 

395 'a bitemporal traversal takes both clocks or neither' 

396 USING ERRCODE = 'invalid_parameter_value'; 

397 END IF; 

398 RETURN QUERY 

399 WITH RECURSIVE bounds AS ( 

400 SELECT 

401 least(greatest(coalesce(max_depth, 4), 1), {_PATH_DEPTH_MAX}) AS depth_cap, 

402 least(greatest(coalesce(max_paths, 3), 1), {_PATH_PATHS_MAX}) AS path_cap, 

403 least(greatest(coalesce(max_edges, 100), 1), {_PATH_EDGES_MAX}) AS edge_cap, 

404 -- Both instants or neither. Supplying one and letting the other default 

405 -- to now() answers a bitemporal question nobody asked: "as the world was 

406 -- then, as we believe it now" is a third thing, and returning it under 

407 -- the caller's one-clock request would misreport what it means. 

408 -- `statement_timestamp()`, not `now()`. `now()` is transaction start, 

409 -- while `graph_edges_current` evaluates at statement time, so a row 

410 -- selected by one instant was being labelled with an earlier one. 

411 coalesce(valid_at, statement_timestamp()) AS as_of_valid, 

412 coalesce(believed_at, statement_timestamp()) AS as_of_believed 

413 ), 

414 edges AS MATERIALIZED (\n@@EDGE_SOURCE@@\n ), 

415 walk AS ( 

416 SELECT 

417 CASE 

418 WHEN e.subject_entity_id = graph_path.from_entity_id 

419 THEN e.object_entity_id ELSE e.subject_entity_id 

420 END AS head, 

421 1 AS length, 

422 ARRAY[e.relation_id] AS relations, 

423 ARRAY[graph_path.from_entity_id] || ARRAY[ 

424 CASE 

425 WHEN e.subject_entity_id = graph_path.from_entity_id 

426 THEN e.object_entity_id ELSE e.subject_entity_id 

427 END 

428 ] AS nodes 

429 FROM edges AS e 

430 WHERE graph_path.from_entity_id IN (e.subject_entity_id, e.object_entity_id) 

431 UNION ALL 

432 SELECT 

433 CASE 

434 WHEN e.subject_entity_id = w.head 

435 THEN e.object_entity_id ELSE e.subject_entity_id 

436 END, 

437 w.length + 1, 

438 w.relations || e.relation_id, 

439 w.nodes || CASE 

440 WHEN e.subject_entity_id = w.head 

441 THEN e.object_entity_id ELSE e.subject_entity_id 

442 END 

443 FROM walk AS w 

444 JOIN edges AS e ON w.head IN (e.subject_entity_id, e.object_entity_id) 

445 CROSS JOIN bounds AS b 

446 -- Simple paths only: an entity appears once, so the walk cannot loop and 

447 -- a returned path is a real route rather than a tour. 

448 WHERE w.length < b.depth_cap 

449 AND w.head <> graph_path.to_entity_id 

450 AND NOT ( 

451 CASE 

452 WHEN e.subject_entity_id = w.head 

453 THEN e.object_entity_id ELSE e.subject_entity_id 

454 END = ANY(w.nodes) 

455 ) 

456 ), 

457 reached AS ( 

458 SELECT 

459 w.length, 

460 w.relations, 

461 w.nodes, 

462 row_number() OVER (ORDER BY w.length, w.relations) AS path_id, 

463 -- How many edges have been spent by the end of this path, in the same 

464 -- deterministic order the paths are returned in. 

465 sum(w.length) OVER ( 

466 ORDER BY w.length, w.relations 

467 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW 

468 ) AS edges_through 

469 FROM walk AS w 

470 WHERE w.head = graph_path.to_entity_id 

471 ), 

472 cap_status AS MATERIALIZED ( 

473 SELECT 

474 EXISTS ( 

475 SELECT 1 

476 FROM walk AS w 

477 JOIN edges AS e ON w.head IN (e.subject_entity_id, e.object_entity_id) 

478 WHERE w.length = b.depth_cap 

479 AND w.head <> graph_path.to_entity_id 

480 AND NOT ( 

481 CASE 

482 WHEN e.subject_entity_id = w.head 

483 THEN e.object_entity_id ELSE e.subject_entity_id 

484 END = ANY(w.nodes) 

485 ) 

486 ) 

487 OR (SELECT count(*) FROM reached) > b.path_cap 

488 OR EXISTS ( 

489 SELECT 1 

490 FROM reached AS r 

491 WHERE r.path_id <= b.path_cap 

492 AND r.edges_through > b.edge_cap 

493 ) AS reached 

494 FROM bounds AS b 

495 ), 

496 arrived AS ( 

497 -- The edge bound is spent on WHOLE paths. Cutting rows at the end would 

498 -- return a path whose reported length does not match the steps it came 

499 -- with — a route that does not connect, presented as one that does. A 

500 -- path that cannot fit within the bound is omitted entirely, which is a 

501 -- shorter answer rather than a wrong one. 

502 SELECT r.length, r.relations, r.nodes, r.path_id 

503 FROM reached AS r 

504 CROSS JOIN bounds AS b 

505 WHERE r.path_id <= b.path_cap 

506 AND r.edges_through <= b.edge_cap 

507 ), 

508 steps AS ( 

509 SELECT 

510 a.path_id, 

511 a.length, 

512 step.position::integer AS path_position, 

513 step.relation_id, 

514 a.nodes[step.position] AS step_from_entity_id, 

515 a.nodes[step.position + 1] AS step_to_entity_id 

516 FROM arrived AS a 

517 CROSS JOIN LATERAL unnest(a.relations) 

518 WITH ORDINALITY AS step(relation_id, position) 

519 ), 

520 result_rows AS MATERIALIZED ( 

521 SELECT 

522 s.path_id, 

523 s.length AS path_length, 

524 s.path_position, 

525 s.step_from_entity_id, 

526 s.step_to_entity_id, 

527 e.relation_id, 

528 e.subject_entity_id, 

529 e.object_entity_id, 

530 e.predicate, 

531 e.fact_label, 

532 e.valid_from, 

533 e.valid_until, 

534 e.ingested_at, 

535 e.invalidated_at, 

536 e.contradiction_group, 

537 e.confidence, 

538 e.evidence_count_current, 

539 e.contradict_count_current, 

540 e.support_state_current, 

541 b.as_of_valid AS applied_valid_at, 

542 b.as_of_believed AS applied_believed_at 

543 FROM steps AS s 

544 JOIN edges AS e ON e.relation_id = s.relation_id 

545 CROSS JOIN bounds AS b 

546 ), 

547 cap_state AS MATERIALIZED ( 

548 SELECT set_config( 

549 'rememberstack.graph_cap_reached', 

550 ( 

551 coalesce( 

552 current_setting('rememberstack.graph_cap_reached', true), 'false'

557 ) AS marker
