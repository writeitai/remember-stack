# API keys and sign-in

<AppliesTo products={["remember.dev"]} />

remember.dev has one credential for everything a program does: the
**API key**. The same key works with the Python SDK, the `remember` CLI,
plain HTTP requests to your project's deployment, the account API, and
[hosted MCP](/docs/cloud/hosted-mcp). People sign in to the console in the
browser, and agents can connect to hosted MCP by browser sign-in instead of
holding a key.

| Credential | Looks like | Reaches | Who gets it | Lifetime |
|---|---|---|---|---|
| API key | `rmb_…` | The deployments of the projects it covers, the account API, and `https://remember.dev/mcp` | Any member, for themselves | 90 days by default; 7, 30, 90, 180 or 365 |
| MCP connection | tokens held by your agent | `https://remember.dev/mcp` only | Any member who approves an agent | Access token 1 hour, refreshed; the connection lasts at most 180 days |
| Browser session | cookie | The console and the account API | Anyone who signs in | Until you sign out |

## The API key

An API key is a signed token. remember.dev and each deployment it covers
check the signature themselves, so your code talks to the deployment
directly with the key; no request is relayed through remember.dev. Every key
belongs to one organisation and acts for the person who created it.

A key records, when it is created:

- **Projects.** Either all projects you can access, or a selection of 1 to
  20 projects. For an owner, "all projects" means every project in the
  organisation, including ones created later. For a member it means the
  projects they are assigned to at that moment; projects assigned later are
  not added.
- **Permissions.** Any of the four below. A new key has `memory:read`,
  `memory:write` and `account:read` unless you change them; `account:manage`
  is added only when you choose it.
- **A default project**, used when a request names none. It is stored
  beside the key at remember.dev, not in the key.
- **A lifetime.** Every key expires. To keep access, create a new key
  before the old one expires.

The projects and permissions cannot be changed afterwards. To change them,
create a new key and revoke the old one.

| Permission | Allows |
|---|---|
| `memory:read` | Every read of a project's memory: search, the assured operations, the graph, SQL queries, the document list, readiness |
| `memory:write` | Ingest and deleting documents. It includes reading, so choosing it also adds `memory:read` |
| `account:read` | Who am I, projects and their status, usage and billing links; for owners also the balance, ledger and statements |
| `account:manage` | Create, list and revoke keys; through [hosted MCP](/docs/cloud/hosted-mcp#account-tools), also create projects and invite or remove members (owners only) |

A key never has more authority than its person has now. If you lose a
project assignment or leave the organisation, your keys lose that access
with you, whatever they say.

## Create a key in the console

1. Open **Settings → API keys** and choose to create a key.
2. Name it after where it will live, for example `ravi-laptop` or
   `ci-ingest`.
3. Choose the projects, the default project, the permissions and when it
   expires.
4. Copy the secret.

The secret is shown once, with ready-to-copy forms for the environment
variable, the Python SDK, the MCP header and curl. remember.dev stores only
a hash of it and cannot show it again. If you lose it, create a new key and
revoke the old one.

The list shows each key's name, projects, permissions, when it was created
and last used, and when it expires; keys that expire soon are marked.
Owners see and can revoke every key in the organisation; members see and
revoke their own.

## Use a key

Put the key in the environment. The SDK and the CLI find the project's
address themselves:

```bash
export REMEMBER_API_KEY=rmb_...
export REMEMBER_PROJECT=docs    # optional: another project the key covers
```

```python
import remember

memory = remember.Client(api_key="rmb_…")                  # the default project
docs = remember.Client(api_key="rmb_…", project="docs")   # another covered project
```

The key names projects, not addresses. The client asks remember.dev which
address serves the project, then talks to that address directly with the
same key. With plain HTTP, do the same yourself:

```bash
curl -s "https://remember.dev/app/api/v1/keys/self/project?project=docs" \
  -H "Authorization: Bearer $REMEMBER_API_KEY"
# {"project": "…", "name": "docs", "api_url": "https://<deployment-id>.dp.remember.dev"}

curl -s https://<deployment-id>.dp.remember.dev/deployment \
  -H "Authorization: Bearer $REMEMBER_API_KEY"
```

`project` takes a project id, slug or name; without it you get the key's
default project. Any valid key can ask, including one with only memory
permissions.

## Keys created by programs

A key with `account:manage` can create more keys, through
`POST /v1/orgs/{org_id}/keys` or the `create_api_key` MCP tool. Such a key:

- covers at most the projects, and holds at most the permissions, of the
  key or connection that created it; by default it gets the same projects
  and permissions without `account:manage`;
- cannot outlive the key that created it;
- is revoked when the key that created it is revoked.

A key created through an [MCP connection](/docs/cloud/hosted-mcp#account-tools)
expires no later than the connection and is revoked when the connection
ends. Create keys that should last in the console.

## Revoke a key

Choose **Revoke** next to the key in **Settings → API keys**. Every key it
created is revoked with it.

A key can also revoke itself, without a browser session:

```bash
curl -s -X DELETE https://remember.dev/app/api/v1/keys/self \
  -H "Authorization: Bearer $REMEMBER_API_KEY"
```

Repeating the request is harmless. `POST /oauth/revoke` with the form field
`token=<the key>` does the same (RFC 7009).

When a revoked key stops working:

- **At remember.dev** (the account API and hosted MCP): on its next
  request.
- **At a deployment**, on requests that reserve spend (ingest and every
  memory read): within about a second, because the deployment asks
  remember.dev before the work starts.
- **At a deployment**, on the few requests that reserve none (such as
  readiness, deployment information and deleting a document): when the
  deployment next fetches remember.dev's revocation list, which it does
  about once a minute. If it cannot reach remember.dev, a revoked key keeps
  working there for at most one hour; a deployment that has had no fresh
  list for an hour refuses every key until it gets one.

Keys are also revoked for you:

| Event | Keys revoked |
|---|---|
| You are removed from a project | Your keys that list that project |
| A project is closed | Every key that lists that project |
| You are removed from the organisation | All your keys in it |
| Your account is deleted | All your keys, in every organisation |
| The organisation is closed | Every key in it |

A key covering all projects is not revoked when one project is closed; it
keeps working for the others.

## Limits

| Limit | Value | Refusal |
|---|---|---|
| Key name | 1 to 100 characters | `422` |
| Projects listed in one key | 1 to 20 | `422`, `key.invalid_projects` |
| Keys created | 60 per hour, per person per organisation | `429`, `key.mint_rate_limited` |
| Live keys | 50 per person per organisation; 1,000 per organisation | `409`, `key.too_many_active` |
| Account API requests | 60 per minute per key | `429`, `key.rate_limited`, with `Retry-After` |
| Self-revocation | 30 per 5 minutes per key | `429` |
| Requests with an invalid or revoked key | 20 per 15 minutes per address | `429`, `key.too_many_failures` |

A deployment also limits each key's request rate; see
[Limits](/docs/cloud/limits#reading).

## `remember login`

`remember login` gets an API key onto a machine without you copying it. It
uses the standard device authorization flow: the terminal shows a code, you
approve it in a browser where you are signed in, and the key is written to a
credential file on that machine.

```bash
remember login
```

The CLI reads remember.dev's OAuth metadata
(`https://remember.dev/.well-known/oauth-authorization-server`) and uses the
device authorization, token and revocation endpoints it names. Pass
`--issuer` or set `REMEMBER_ISSUER` to sign in to another issuer.

Open the link the terminal prints and check that the code on the page
matches. The page offers the same choices as the console: organisation,
projects, default project, permissions and lifetime, with the same defaults.
Any member can approve a login for themselves.

What to expect:

- **One key.** Choose a default project with `remember switch <project>`, or
  pass `--project` to a command.
- **The CLI slows down when asked** and never waits more than 30 seconds
  between checks. Ctrl-C stops it and writes nothing.
- **Logging in again replaces the stored key.** The old key is recorded
  first, the new one is stored, and only then is the old one revoked. If the
  revocation cannot be confirmed, the next `remember` command retries it.

`remember logout` revokes the stored key and deletes the file. If the
revocation is not confirmed, the file is kept so you can retry.

## MCP connections

An agent connected to [hosted MCP](/docs/cloud/hosted-mcp) by browser sign-in
holds no API key. You approve it on a consent page with the same project and
permission choices as a key, and it receives tokens that work only at
`https://remember.dev/mcp`. **Settings → Connections** lists these
connections and disconnects them.

## Browser sign-in

You sign in to the console at `https://remember.dev/app` with:

- **Email and password.** Passwords need at least 8 characters with an
  upper-case letter, a lower-case letter and a digit. You must verify your
  email address before you can use the console; the verification link is
  valid for 48 hours. A password reset link is valid for 2 hours.
- **Google.** Sign in with a Google account.

The session is an HTTP-only cookie. **Settings → Security → Log out** signs
out and ends your sessions on every device. It does not end MCP
connections or revoke API keys.

When the console shows your memory, it asks the account API for a
short-lived, read-only credential for that one deployment (10 minutes; 3
minutes and upload-only when you upload a file) and calls the deployment
directly. Signing out does not reach those credentials; they expire on
their own.

## The credential file

`remember login` writes `credentials.json` to:

1. the directory in `REMEMBER_CONFIG_DIR`, if set;
2. otherwise `$XDG_CONFIG_HOME/remember/`, or `~/.config/remember/`.

The file is created with mode `0600` in a `0700` directory. The CLI refuses
to read it if it is readable by group or others, or if it is a symbolic
link. It holds one key, its id and expiry, and your default project. The
format is in the [CLI reference](/docs/reference/cli#credential-file).

### Which key the CLI and the Python client use

The CLI and the Python client choose the same way, setting by setting:

1. flags (`--api-key`, `--api-url`, `--project`) or `remember.Client`
   arguments (`api_key`, `base_url`, `project`);
2. environment: `REMEMBER_API_KEY`, `REMEMBER_API_URL`, `REMEMBER_PROJECT`;
3. the credential file.

A key from the credential file is sent only to remember.dev and to the
project addresses remember.dev returns for it. When you point a command at
another address with a flag or variable, the stored key is not sent there;
pass a key explicitly instead. See the
[Python SDK reference](/docs/reference/python-sdk#connecting).

## Keep keys safe

- Put a key in an environment variable or a secret store, never in code or
  a committed file.
- Create one key per machine or job, named after it, covering only the
  projects and permissions it needs, so you can revoke one without breaking
  the others.
- Do not paste a key into an agent's chat. Connect agents with
  [hosted MCP](/docs/cloud/hosted-mcp) and browser sign-in, or give a headless
  agent the key through its environment.
- If a key leaks, revoke it first, then create a replacement.

More in [Data handling and security](/docs/cloud/data-and-security).
