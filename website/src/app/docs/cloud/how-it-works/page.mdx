# How Remember Cloud works

Remember Cloud is the hosted product around the open-source engine. This page is the **cloud** model — org, project, deployment, and keys — not the engine’s store architecture ([that page](/docs/architecture) is Postgres, object storage, and git).

Isolation and spend leases: [Cloud architecture](/docs/cloud/architecture). What Cloud will not do from the CLI: [Managed vs self-hosted](/docs/cloud/managed-vs-self-hosted).

---

## 1. Organization → project → deployment

Three names the `remember` client already uses:

**Organization.** Billing and team seats live here. A control-plane credential carries `org_id`. `remember whoami` prints it. Programmatic reads go through `CloudClient`, which is bound to one organization for its lifetime.

**Project.** The named workspace the CLI switches. `remember switch <name-or-id>` rewrites the active entry in `~/.config/remember/credentials.json`: data-plane URL, data-plane token, and `deployment_id` when the cached project has one. Agent harness files written by `remember setup` do not embed those secrets; `remember mcp` reads the file at runtime.

**Deployment.** The running engine instance. A successful **deployment-audience** login stores `deployment_id` and talks to that instance’s HTTP API. `CloudClient.deployments()` GETs `/v1/orgs/{org_id}/deployments` and maps each row’s `id`, `state`, `data_plane_hostname`, and `data_plane_hostname_live`. The client’s own docstring describes that list as **zero or one today** — do not assume a many-deployment console from this page. A deployment is treated ready when `state` is `active` and `data_plane_hostname_live` is true.

Self-host has none of this hierarchy: one local deployment, no org, no `remember switch`.

## 2. Memory answers at its own address

`remember login` defaults to audience `deployment`. The token host may return `data_plane_hostname` and `data_plane_hostname_live`. If you did not pass `--api-url`, the CLI stores:

```text
https://{data_plane_hostname}
```

It refuses to invent a host: missing hostname asks for `--api-url`; a host that is not live yet asks you to retry. `--api-url` still wins when you set it (self-host and local overrides).

That URL is the **data plane**. Ingest, operations, query, and MCP go there directly. They are not proxied through the control plane. Published examples sometimes show a `*.dp.remember.dev` name; the advertised hostname is the authority.

`remember whoami` on Cloud prints the active project id (or the deployment UUID) and that data-plane URL. On self-host it prints `Identity: self-hosted (local)` and the local endpoint.

## 3. Two token audiences (never mix them)

| | Control-plane session | Data-plane / deployment |
| --- | --- | --- |
| Typical prefix | `umc_cp_` | `umc_dp` (credential-file default) |
| How you get one | `remember login --control-plane` (or `--audience control`) | `remember login` (default `--audience deployment`) |
| Where it is sent | Token host / control plane only | The deployment’s data-plane URL only |
| What it is for | Org status, listing deployments, billing reads | Ingest and query on that deployment |
| Revoke path the CLI calls | `DELETE /v1/control-tokens/self` | `DELETE /v1/api-tokens/self` |

A control-plane token is **never** forwarded to a project pod. A data-plane token cannot create projects, invite members, or read billing.

`CloudClient.from_env` requires `REMEMBER_CLOUD_TOKEN` (`umc_cp_…`) and `REMEMBER_CLOUD_ORG`. It rejects a deployment token. Its default base URL in code is `https://remember.dev/app/api` (override with `REMEMBER_CLOUD_URL`). Interactive CLI device-grant and CLI control-plane calls default to `https://api.remember.dev` (override with `--token-host` / `REMEMBER_CONTROL_PLANE_URL` / `REMEMBER_TOKEN_HOST`). Use the URL your environment actually issued; this page does not collapse the two defaults into one invented host.

The SDK data-plane client (`RememberClient` / `Client`) never reads the CLI credential file. Headless jobs use constructor arguments or `REMEMBER_DATA_PLANE_URL` + `REMEMBER_API_KEY`.

## 4. How a credential is issued

1. `remember login` POSTs `/v1/device/authorize` on the token host (`client_name=remember-cli`, audience `deployment` or `control`).
2. You approve the user code in the browser.
3. The CLI polls `/v1/device/token`.
4. On success it writes `~/.config/remember/credentials.json` (directory `0700`, file `0600`).
5. `remember logout` revokes stored bearers, then unlinks the file.

`CloudClient`’s error text names `POST /v1/orgs/<org>/control-tokens` as the mint path for a control token while signed in. That is what the client tells operators — not an inventory of every console button.

Expiry, when the token host sends `expires_at`, is stored and warned on stderr within 30 days. No expiry recorded means none was sent, not that the credential never expires.

## 5. Control-plane reads the client already makes

Verified paths on the **remember** Cloud client (not a full control-plane catalog):

| Client | Method | Path |
| --- | --- | --- |
| `remember balance` | GET | `/v1/orgs/{org_id}/billing/status` or `/v1/billing/balance` |
| `remember projects list` | GET | `/v1/orgs/{org_id}/deployments` or `/v1/deployments` |
| `CloudClient.billing_status` | GET | `/v1/orgs/{org_id}/billing/status` |
| `CloudClient.deployments` | GET | `/v1/orgs/{org_id}/deployments` |
| `CloudClient.ledger` | GET | `/v1/orgs/{org_id}/billing/ledger` |
| `CloudClient.spend_gate` | GET | `/v1/orgs/{org_id}/deployments/{deployment_id}/spend-safety/gate` |

Writes that create projects, invite members, or change billing are **not** implemented in the public CLI. They go to the console:

- [remember.dev/app](https://remember.dev/app)
- [remember.dev/app/projects](https://remember.dev/app/projects)
- [remember.dev/app/billing](https://remember.dev/app/billing)
- [remember.dev/app/team](https://remember.dev/app/team)

The CLI `--role` flag on `members invite` accepts `owner` or `member` and still only prints the team console URL. Treat those two names as the roles the CLI knows; do not take this page as a complete RBAC spec.
