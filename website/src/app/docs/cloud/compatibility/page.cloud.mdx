# What remember.dev serves

<AppliesTo products={["remember.dev"]} />

A remember.dev deployment is a RememberStack engine answering at its own
hostname. It serves the engine's HTTP API directly, with remember.dev's
authentication and limits in front. This page says which engine version
that is, what it serves, and where it differs from what the rest of these
docs describe.

## Engine version

| | Version |
|---|---|
| remember.dev deployments run | RememberStack **v0.17.2** |
| These docs describe | RememberStack **v0.17.2**, plus changes merged after it that are not released yet |

remember.dev chooses the engine version and upgrades deployments; you do
not. [Hosted MCP](/docs/cloud/hosted-mcp) serves the tool catalogue of the
same version.

`GET /deployment` on your deployment returns the build it is running.

## Served routes

With an [API key](/docs/cloud/tokens-and-sign-in) that covers the project,
your deployment at `https://<deployment-id>.dp.remember.dev` serves:

| Area | Routes | Notes |
|---|---|---|
| Ingest | `POST /ingest` | Text only; see [Ingest limits](/docs/cloud/limits#ingest) |
| Documents | `GET /documents`, `DELETE /documents/{doc_id}` | |
| Readiness | `POST /readiness` | |
| Search | `GET` and `POST /search/claims`, `GET` and `POST /search/chunks` | |
| Passages | `GET /chunks/{chunk_id}/adjacent`, `POST /chunks/adjacent` | |
| Assured operations | `GET /operations`, `POST /operations/{name}` | `resolve_entity`, `facts_context`, `claims_and_sources_context`, `combined_context` |
| Entities and facts | `GET /resolve`, `GET /lookup/relations`, `GET /lookup/observations`, `GET /transcript/relation/{relation_id}`, `GET /hydrate/relation/{relation_id}` | |
| Graph | `POST /graph/neighborhood`, `POST /graph/path`, `POST /graph/citation-path` | At most 2 graph queries at a time |
| SQL queries | `POST /query/sql`, `POST /query/sql/explain`, `GET /query/space`, `GET /query/space/search`, `GET /query/saved`, `GET /query/saved/{namespace}/{name}`, `POST /query/saved/{namespace}/{name}/run` | |
| Deployment | `GET /deployment`, `GET /healthz` | `/healthz` needs no key |

SQL queries run over the query space (`memory_v1`): prepared, read-only
views and functions. Every statement is parsed and checked against that
query space before it runs, and anything outside it is refused. See
[Explore memory with SQL](/docs/guides/sql).

Every memory read is charged and stops when the balance or a cap runs out;
see [Pricing](/docs/cloud/pricing#reads).

The routes behave as the [HTTP API reference](/docs/reference/http-api)
describes, except where this page says otherwise.

## Not served

| Route or feature | What happens |
|---|---|
| `POST /documents/search` | Added after v0.17.2. Not present on remember.dev yet (`404`); `remember documents search` gets the same answer, and hosted MCP has no `search_documents` tool |
| Document filters on search (`documents` in `POST /search/claims` and `POST /search/chunks`) and `source_path` on `POST /ingest` | Added after v0.17.2. Not available on remember.dev yet |
| The `adjacent_chunks` MCP tool | Added after v0.17.2. Hosted MCP does not list it; the routes under *Passages* above are served |
| Connectors (`/connectors…`) | The routes exist, but remember.dev does not run connectors for you and gives them no credentials. Push documents with ingest instead |
| Files other than UTF-8 Markdown and plain text | Refused before storage; see [Ingest limits](/docs/cloud/limits#ingest). A self-hosted engine can convert PDFs and other formats |
| Filesystem views of the corpus | Not offered on remember.dev |
| Direct database access | Not offered. Use SQL queries over the query space |

## Authentication

| | Self-hosted | remember.dev |
|---|---|---|
| Machine credential | Whatever you configure on the engine | API key `rmb_…`, signed, covering one, several or all projects of the organisation; 7 to 365 days |
| How to get one | You create it | Console (**Settings → API keys**), `remember login`, or another key with `account:manage`; see [API keys and sign-in](/docs/cloud/tokens-and-sign-in) |
| Scope | Configured | The key's permissions: `memory:read` gives the `read` scope, `memory:write` the `write` scope |
| Browser credentials | Not applicable | Short-lived read-only or upload-only credentials for the console |
| Hosted MCP calls | Not applicable | A 5-minute credential for one project and one permission, signed by remember.dev for each tool call |

Send the key as `Authorization: Bearer <key>`. An expired or revoked key is
refused by the deployment; see
[when a revoked key stops working](/docs/cloud/tokens-and-sign-in#revoke-a-key).

## Limits and errors that only exist on remember.dev

| Situation | Response |
|---|---|
| Body over 100,000,000 bytes | `413`, `body_too_large` |
| Text over 10,000,000 bytes | `413`, `source_bytes_limit_exceeded` |
| Binary file | `409`, `rate_class_unavailable` |
| Other text types, invalid UTF-8, markup | `422`, `rate_class_ambiguous` |
| Empty document | `422`, `empty_text` |
| Balance at zero, a cap reached, billing suspended, or the project parked | `423`, `dispatch_parked:<reason>`, for ingest and every memory read; see [Spend caps](/docs/cloud/spend-controls#what-stops-when-money-or-a-cap-runs-out) |
| Provider-cost safeguard reached | `423`, `dispatch_parked:<reason>`, or `403`, `dispatch_refused:<reason>` |
| Safeguard service unreachable | `503`, `spend_lease_unavailable` |
| Request rate or concurrency over the limit | `429`, `rate_limited` or `concurrency_limited`, with `Retry-After`; see [Limits](/docs/cloud/limits#reading) |
| Project closed | The hostname stops answering |

All of them are listed in [Limits](/docs/cloud/limits), and the money side in
[Spend caps and auto top-up](/docs/cloud/spend-controls).

## The retired bridge

Earlier, remember.dev relayed memory requests through
`https://remember.dev/app/api/dp/v1/…`. That path is gone. It answers
every request with `410` and the code `dp.bridge_removed`. Send requests to
your deployment's own hostname.

## Changes

The engine version remember.dev runs changes over time, and routes, error
codes or limits can change with it. Engine releases are listed in the
[changelog](/docs/project/changelog). Check `GET /deployment` to see which
build your deployment runs.
