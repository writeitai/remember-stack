# Releases and changelog

<AppliesTo products={["remember.dev", "self-hosted"]} />

Each release publishes the `remember` Python package to PyPI and the engine
image `ghcr.io/writeitai/remember-stack:<version>` to GitHub's container
registry. Release tags are `v<major>.<minor>.<patch>` on
`github.com/writeitai/remember-stack`. Up to 0.16.0 the Python package was
published as `rememberstack`.

The engine is pre-1.0. A minor version can change the API; changes that
need action from you are marked **Action needed**.

<Cloud>

remember.dev may run an earlier engine than the newest release. Which one it
runs today, and what that means for you, is on
[What remember.dev serves](/docs/cloud/compatibility).

</Cloud>

## 0.18.2 (November 2026)

A stock self-hosted deployment needs no action. Its database migrations, its
Compose file and its default conversion are unchanged.

**Processing.**

- **Behaviour change.** A file over its family's reading limit (100 MB for
  office documents and PDFs, 200 MB for spreadsheets) is no longer refused or
  carded when its route's converter fetches the file by a signed URL from S3
  storage. The engine reads nothing, so only the converter's own input limit
  applies. With the stock in-process converters the limits stay as before:
  an oversized PDF is refused and other oversized files become a card. See
  [File types](/docs/guides/file-types).
- An oversized file is carded without reading it into the worker's memory.
  The card itself is unchanged.

**Embedding the engine.**

- Conversion by reference. A converter can declare that it accepts a URL
  (`UrlConverter`). The worker then signs a short-lived GET URL for the raw
  object (`PresignedReadPort`, implemented by the S3 store) and never reads the
  bytes itself.
- `UploadIngestor.ingest_stored` registers a raw object that a client
  uploaded directly under `uploads/<id>`. The engine streams it once to hash
  and classify it, and keeps it at that key. On a deployment with managed
  text metering it is measured exactly as an upload is.
- `ingest_scope_routes` lets an ingest-scoped credential call named host
  routes.
- Route scopes and the health check now work for an API mounted under a path
  prefix. Before, narrow credentials there got `403`.

<Cloud>

- A spend-gate hold refused as too large answers `413` instead of
  `503 spend_lease_unavailable`.

</Cloud>

## 0.18.1 (November 2026)

Version 0.18.0 was never released. Its PostgreSQL image failed to build, so it
has no PyPI package and no GitHub release. Its engine image
`ghcr.io/writeitai/remember-stack:0.18.0` is on GHCR; do not use it. 0.18.1 has
the same changes.

**Self-hosted upgrades need action.** Read
[Upgrades and migrations](/docs/self-hosting/upgrades) before moving an
existing deployment. A 0.17 deployment upgrades in place: its data is kept and
`setup` migrates it. PostgreSQL is the exception (below).

**PostgreSQL 19 release candidate 1.**

- **Action needed.** The database image is now
  `ghcr.io/writeitai/remember-stack-postgres:19rc1-0.18.1`. Releases up to
  0.17.2 ran PostgreSQL 19 Beta 3, and a Beta 3 data directory does not open
  under RC 1. Move in two steps:
  1. Upgrade the engine to 0.18.1 while it still runs on the Beta 3 image.
     `setup` drops the Beta 3 property graphs.
  2. Dump the database and restore it into a new RC 1 volume.

  The order matters: a dump taken before step 1 holds definitions RC 1 cannot
  restore. [Upgrades](/docs/self-hosting/upgrades#postgresql-prerelease-versions)
  has the commands.
- The graph no longer uses SQL/PGQ, which RC 1 removed. One-hop neighbourhoods
  are plain joins over the same views, and they return the same results.
- **Action needed.** Readiness reasons are renamed:
  `graph_pgq_smoke_failed` is now `graph_one_hop_smoke_failed`, and
  `graph_pgq_guard_smoke_failed` is now `graph_one_hop_guard_smoke_failed`.
  Update any alerting that matches the old names.
- **Action needed.** The JSON output of `remember ops graph-catalog ensure` no
  longer has a `definitions` field. It no longer checks property graphs, and
  it checks the graph views instead.

**Workers.**

- **Action needed.** Workers run by class, not by stage. `worker --stage
  <stage>` is replaced by `worker --class convert|llm` with `--concurrency`.
  `convert` converts files one at a time. `llm` runs every other stage, with
  20 tasks in flight by default. The Compose file now has two worker services,
  `worker-convert` and `worker-llm`, in place of one per stage. Stop the old
  stack with `docker compose down --remove-orphans`, so the per-stage worker
  containers are removed. Size with `REMEMBERSTACK_SELFHOST_LLM_CONCURRENCY`
  and `REMEMBERSTACK_SELFHOST_CONVERT_CONCURRENCY`, or `--scale`; see
  [Scaling](/docs/self-hosting/scaling).
- A claimed task is a lease that its worker renews. If the worker dies, the
  task goes back to the queue once the lease expires, instead of staying
  `running` forever.
- Several deployments can run their migrations against one PostgreSQL server
  at the same time.
- Each worker item's log records `object_bytes_read` and
  `object_bytes_written` ([Observability](/docs/self-hosting/observability)).

**HTTP API.**

- **Behaviour change.** A request whose decoded path contains a control
  character, such as `%0A`, gets `400 invalid_path`. It is refused before
  authentication and routing.
- `POST /documents/search` finds documents by name, metadata and text.
  `documents` filters on `POST /search/claims` and `POST /search/chunks` limit
  a search to chosen documents. `source_path` on `POST /ingest` records where
  a file came from.
- Effective periods, version keys, section history and cross-references:
  read a document as it was in force on a date. See
  [Read a document as of a date](/docs/guides/versions-in-force).

<Cloud>

- Fixes to spend-gate classification. Section history with empty key segments,
  mounted paths and percent-encoded delimiters are now metered like any other
  read.

</Cloud>

**Processing.**

- **Behaviour change.** Every page of every PDF is OCR'd. A deployment
  without a Mistral OCR key parks PDFs as `no_route`.
  `REMEMBERSTACK_SELFHOST_CONVERSION_ROUTES` now adds to the stock route
  table instead of replacing it. It cannot route PDFs to a text-layer
  converter.
- Many more file types are ingested: office documents, HTML, e-books, email,
  notebooks, spreadsheets, delimited data and datasets. Code, logs and file
  cards are searchable, and claims are not extracted from them. See
  [File types](/docs/guides/file-types).
- The claims and facts layers can be switched off per deployment
  (`REMEMBERSTACK_SELFHOST_CLAIMS_LAYER`, `REMEMBERSTACK_SELFHOST_FACTS_LAYER`)
  and per request. Turning one back on processes the versions it skipped.
- Claims that refer to their own document by a phrase such as "this
  agreement" name the document.
- `REMEMBERSTACK_SELFHOST_RETRIEVAL_DATABASE_BUDGET_S` sets one retrieval
  operation's database time budget.
- `setup` accepts a database URL whose password is percent-encoded.

**Clients.**

- The `adjacent_chunks` MCP tool.
- A TypeScript client, `@rememberdev/client`, with the same methods as the
  Python client. It is available as repository source and is not published to
  npm.

**Embedding the engine.** A program can build an engine for a deployment
from explicit settings and run several in one process. It can run a named
task with `run_task`. Other options:

- one API app serving several deployments, which resolves, authenticates and
  admits each request against its own deployment;
- replaceable conversion routes;
- a forget-manifest bucket, so no deployment state is kept on local disk;
- credentials per bucket;
- `engine_options` for the database connection pool;
- a separate host, port and TLS settings for the SQL query role.

## 0.17.0 (22 September 2026)

**Existing deployments must be recreated.** The migrations for mutable fact
windows and multi-span claim evidence refuse a database that already holds
claims. Start from an empty deployment and send your sources again; see
[Upgrades and migrations](/docs/self-hosting/upgrades).

**One package: `remember`.**

- **Action needed.** The Python client, the CLI and the MCP server ship in
  one PyPI package, `remember`. The old `rememberstack` package is
  deprecated: its final version, 0.17.0, only forwards to `remember` and
  warns on import. Run `pip install remember` and change
  `import rememberstack` to `import remember`.
- **Action needed.** The engine is no longer installed with pip. Run it from
  the container image `ghcr.io/writeitai/remember-stack`.
- The `remember` package depends only on `httpx`, `pydantic` and
  `pydantic-settings`.
- New client class `remember.Client` (also `remember.RememberClient`) with an
  `api_key` argument, `from_env()`, `ingest_file()` and path support in
  `ingest()`.<Cloud> `remember.CloudClient` reads a remember.dev organisation's
  deployment, balance, ledger and spend gate.</Cloud>

**Assured operations renamed.**

- **Action needed.** `testimony_context` is now `claims_and_sources_context`,
  `fact_context` is now `facts_context`, and `answer_context` is now
  `combined_context`. `resolve_entity` is unchanged. The combined result is
  now `ContextBundle/v2`, whose evidence part is called
  `claims_and_sources`. Update names in HTTP calls, SDK calls, CLI commands
  and agent prompts.

**CLI.**

- New commands: `remember setup` (writes MCP configuration for Cursor,
  Claude Code, Claude Desktop, Codex and Antigravity), `remember doctor`<Cloud>,
  `remember whoami`, `remember switch`, `remember projects list`,
  `remember balance`</Cloud>.
- `remember query "<question>"` is short for `remember query text`, which
  runs `facts_context` (or `combined_context` with `--combined`).
- `remember query adjacent-chunks`.
- `remember review` and `remember budget` are retired.

<Cloud>

- `remember login --control` signs in with an organisation control-plane
  token. The credential file can now hold several projects and a
  control-plane token.

</Cloud>

**Retrieval.**

- New `adjacent_chunks`: read the passages immediately before and after a chunk
  (`GET /chunks/{id}/adjacent`, `POST /chunks/adjacent`, SDK, CLI).
- Name resolution at query time tries exact aliases, then fuzzy name
  matches, then profile similarity, and returns no candidate, one, or an
  explicit ambiguity.
- Fact labels no longer carry a bracketed date suffix; dates stay in the
  structured validity fields.

**Processing.**

- Claims can cite several separate spans of their source (multi-span
  evidence).
- In conversations, answers such as "Yep, that one" are resolved to what the
  question referred to, keeping ordinals and specific names.
- Relative dates ("last Friday") are written into the claim text as resolved
  dates.
- Images always get OCR and a visual description.
- Originals are kept, and documents whose media type has no converter are
  parked instead of failing; `remember ops resume-no-route` releases them
  once a route exists.
- Fact adjudication engine is configurable; OpenRouter requests rotate
  between providers when one is overloaded.
