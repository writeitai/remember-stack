# Releases and changelog

<AppliesTo products={["remember.dev", "self-hosted"]} />

Each release publishes the `remember` Python package to PyPI and the engine
image `ghcr.io/writeitai/remember-stack:<version>` to GitHub's container
registry. Release tags are `v<major>.<minor>.<patch>` on
`github.com/writeitai/remember-stack`. Up to 0.16.0 the Python package was
published as `rememberstack`.

The engine is pre-1.0. A minor version can change the API; changes that
need action from you are marked **Action needed**.

<Cloud>

remember.dev runs the latest release and upgrades deployments with each
release. What it serves is on
[What remember.dev serves](/docs/cloud/compatibility).

</Cloud>

## 0.22.1 (November 2026)

**New model defaults: GPT 6 Luna everywhere, Jev for facts.** Every chat seat
now defaults to `openai/gpt-6-luna`: the structure fallback, skeleton check,
section role and section summary (were `z-ai/glm-4.7-flash`), and claim
extraction, relation normalisation, entity resolution and the `prompt` fact
engine (were `openai/gpt-5.6-luna`). Fact adjudication now defaults to Jev
(`REMEMBERSTACK_FACT_ADJUDICATION_ENGINE=jev`), served through OpenRouter on
your OpenRouter key (`REMEMBERSTACK_TYPESAFE_ROUTE=openrouter`, the System One
route added in 0.21.3). No new key is needed. The default route is the one
`REMEMBERSTACK_OPENROUTER_ZDR=true` accepts, so a deployment with ZDR on runs
Jev under zero data retention, alongside the embedding ZDR routing and host
allowlist (`REMEMBERSTACK_OPENROUTER_EMBEDDING_PROVIDER_ONLY`) from the same
release. `GET /deployment` reports `model_bindings.systemone_route` as
`openrouter`. New work uses the new models; documents already processed are
not re-run. See [Models](/docs/self-hosting/models).

**Action needed (self-hosted)** only if you want the previous models. Set them
in `.env`: `REMEMBERSTACK_STRUCTURER_MODEL`, `REMEMBERSTACK_E2_EXTRACT_MODEL`,
`REMEMBERSTACK_E3_NORMALIZE_MODEL`, `REMEMBERSTACK_OBS_SMALL_MODEL` and
`REMEMBERSTACK_FACT_MODEL` to `openai/gpt-5.6-luna`;
`REMEMBERSTACK_SKELETON_CHECK_MODEL`, `REMEMBERSTACK_ROLE_MODEL` and
`REMEMBERSTACK_SUMMARY_MODEL` to `z-ai/glm-4.7-flash`; and
`REMEMBERSTACK_FACT_ADJUDICATION_ENGINE=prompt`. A deployment that already
runs Jev on the direct route must set `REMEMBERSTACK_TYPESAFE_ROUTE=typesafe`
to keep it.

**The CLI covers the whole public API.** New commands include
`remember readiness VERSION_ID... [--wait]`, `remember graph`, `lookup`,
`search`, `relation`, `resolve`, `deployment` and `processing-layers`, and the
document references, section history and effective-period commands. Every
public HTTP route is now reachable from the Python SDK, the TypeScript SDK
and the CLI. Agents with a shell should prefer the CLI; the MCP tool list is
unchanged. See the [CLI reference](/docs/reference/cli).

**Docs and verification.** The LoCoMo results cite each comparator's
published results and run setup. The docs site publishes `robots.txt`, its
icons and per-page social previews. CI now installs the published `remember`
package and runs the documented CLI, Python SDK and MCP workflows against
Compose.

## 0.22.0 (November 2026)

**Archive and forget replace delete.** Two verbs now take a document out of
memory. **Archive** (`POST /documents/{doc_id}/archive`, `archive_document`,
`remember documents archive`) hides the document and closes the facts only it
supported; **unarchive** is the exact undo. `include_archived` shows archived
documents in document lists, search and the context operations. A connector
that sees a source file disappear archives it, and the file coming back
unarchives it. **Forget** (`POST /documents/{doc_id}/forget`,
`forget_document`, `remember documents forget`, the `forget_document` MCP tool
with `confirm`) hides the document at once and then erases it in the
background, sweeping until nothing is left: claims, exclusive facts, entities
only it named, stored originals, corpus folders and compiled knowledge pages,
including their Git history. `GET /forgets` and `remember forget list|status`
follow each forget record; it waits as `waiting_for_redaction` only while a
page you wrote still cites the document. A forgotten document is refused on
re-ingest with `document_forgotten` unless that one request sets
`allow_forgotten`. See
[Documents and sources](/docs/concepts/documents-and-sources#forgetting-a-document).

**Action needed: `DELETE /documents/{doc_id}` is removed**, together with
`MemoryClient.delete_document`, `remember documents delete`, the
`delete_document` MCP tool and their TypeScript counterparts. Use archive for
a reversible removal and forget for erasure.

**Action needed (self-hosted).** Setup migrates to `p9_55_0076`. Documents
deleted under the earlier release become archives, and unfinished forgets
continue under the new forget records. The separate forget manifest store is
gone: remove `REMEMBERSTACK_SELFHOST_FORGET_MANIFEST_ROOT` and
`REMEMBERSTACK_SELFHOST_FORGET_MANIFEST_BUCKET_NAME` if you set them, and
forget no longer pauses the deployment or answers `503 forget_in_progress`.
After restoring a backup, run `remember ops forget-reapply --deployment <UUID>`
so forgets recorded since the backup are applied again. See
[Operating](/docs/self-hosting/operating).

**Agent tooling.** The RememberStack agent skill and guide are published
([Skills](/docs/start/skills)), the CLI can return machine-readable results
with actionable error messages, and the engine HTTP API boundary is documented
and verified.

**Error codes.** Coded failure reporting (D158) is complete, and the docs show
how to export logs.

## 0.21.3 (November 2026)

**More image formats.** The `image_ocr_description` route now reads static
WebP as uploaded, and converts GIF, TIFF, BMP, HEIC, AVIF and PSD to one PNG
before OCR and the description. One image per file is read (the first frame
or page, or a HEIC's primary image), and the result says when more were left
out. The conversion runs in a separate process limited to 1.5 GiB
of memory and 60 seconds; a file that exceeds either limit fails as
unreadable. Route each type you want read in
`REMEMBERSTACK_SELFHOST_CONVERSION_ROUTES`.
[File formats and converters](/docs/self-hosting/converters) lists what each
format keeps and its limits.

**Zero-data-retention routing for embeddings and Jev.**
`REMEMBERSTACK_OPENROUTER_ZDR` now also adds `zdr: true` to embedding
requests, and the new `REMEMBERSTACK_OPENROUTER_EMBEDDING_PROVIDER_ONLY`
restricts embeddings to the hosts you list. Jev fact adjudication can run
through OpenRouter with each deployment's own key
(`REMEMBERSTACK_TYPESAFE_ROUTE=openrouter`), under the same setting. To also
exclude endpoints with safety retention, enable ZDR only in your OpenRouter
account or key settings. **Action needed:** a deployment that sets
`REMEMBERSTACK_OPENROUTER_ZDR=true` and uses Jev now refuses to start unless
Jev runs on the `openrouter` route, against `https://openrouter.ai`, with
`REMEMBERSTACK_TYPESAFE_BACKUP=none`. Otherwise turn ZDR off.

**Upload detection.** UTF-16 CSV and TSV files that start with a byte-order
mark, `.eml` messages with an 8-bit body, legacy `.xls`, `.doc` and `.ppt`
files uploaded without a type, and SPSS Portable (`.por`) files are now
recognized and read instead of refused or carded. **Action needed:** a legacy
Office file whose internal streams do not identify Word, Excel or PowerPoint
is now refused with `ambiguous_office_format` even when its type is declared.
Re-save it in Office, or export it to a current format.

**Error codes.** More failures log one record with a stable `error_code`: the
worker, the lease reaper, provider errors, the live graph and managed metering.
[Observability](/docs/self-hosting/observability) shows how to send them to
Sentry, PostHog or OpenTelemetry.

## 0.21.2 (November 2026)

**Images on a metered deployment.** The `image_ocr_description` route (Mistral
OCR plus a vision-model description of each PNG or JPEG) can now run under a
managed meter. Each image is measured as one `image` unit before either
provider call, and processing waits for the hold to be approved, the same way
a PDF's pages are counted before OCR. Before this release a metered
deployment refused the route with `rate_class_unavailable`.

**Oversized images fail early.** On any deployment, an image larger than the
`image_ocr_description` route's byte ceiling (10 MB by default) now fails
before it is downloaded, measured or sent to a provider, as an oversized PDF
already did.

**Zero-data-retention routing for image descriptions.** Set
`REMEMBERSTACK_IMAGE_DESCRIPTION_ZDR=true` to add `zdr: true` and
`data_collection: deny` to the image description request, like
`REMEMBERSTACK_OPENROUTER_ZDR` for chat. To exclude endpoints with safety
retention as well, enable **ZDR only** in your OpenRouter account. Turning the
flag on refreshes each image's description once at its next conversion; the
OCR is reused.

**Error codes on log records.** Every ERROR log record from the engine's
`rememberstack.*` loggers now carries an `error_code` field, such as `worker_item_failed` or
`mcp_tool_failed`. A log handler can export it to group failures without
parsing messages; the default text format does not print it.

## 0.21.1 (November 2026)

**Managed storage capture failure codes.** `capture_storage_batch` now returns
a failure code for every scope it could not capture, such as
`capture_writer_class_unknown`, instead of an empty result. Free-text error
messages never leave: such failures report only the exception type.

**Benchmark harness.** LoCoMo answers can be graded again from saved runs with
a Mem0-style judge, using frozen ablation inputs. The published LoCoMo results
now report both judges: 94.09% with the Mem0-style judge and 90.26% with the
native one.

**Documentation.** The cloud pages now state the hosted file formats, limits
and available tools as remember.dev actually serves them.

## 0.21.0 (November 2026)

**Action needed (self-hosted): PostgreSQL 18.** PostgreSQL 18 is now the
reference server (it replaces the PostgreSQL 19 release candidate). Compose
uses `ghcr.io/writeitai/remember-stack-postgres:18-0.21.0`. A PostgreSQL 19
data directory cannot be opened by 18: start from fresh PostgreSQL 18 storage
and re-ingest. See [PostgreSQL server versions](/docs/self-hosting/upgrades#postgresql-server-versions).

**Document tags.** Register tags, assign them at ingest or later, rename and
delete them, find them in document lists, search results and SQL, and filter
`search` and `search_documents` by tag, and the three context operations
(`facts_context`, `claims_and_sources_context`, `combined_context`) through
their `documents` filter. See
[Tag documents](/docs/guides/tag-documents).

**Corpus folders.** Served document versions are published as type/topic/title
folders through ordinary processing work, with a verifying reconcile and
durable deletion. Setup migrates to `p9_53_0074`.

### Corpus consumption

Document search's `p3_path` resolves a type/topic/title folder only when the
selected version is served and its nullable publication marker matches current
export inputs. Readiness uses the same guard per requested version. Pending,
raw-only, updating, failed and historical results have no browse path.
Only the suffix remains stable across folder moves; the consumption skill and
MCP descriptions teach re-resolution and offline `find`. Corpus originals and
reader derivatives remain independent of claims/facts switches, and K stays a
separate repository.

The benchmark harness's fresh Full-v47 protocol attests publication markers,
ready-folder identities and frozen file inventories. This change establishes
no new benchmark result and does not reinterpret stored evidence.

## 0.20.0 (November 2026)

### Retrieval SQL and online schema upgrade

Native fact and entity-scoped claim/chunk retrieval share visibility work inside
each database statement. Source, version, deletion, identity and time rules still
apply before a result counts toward top-k. Existing stored content and vectors
are reused; this upgrade does not run ingestion or change model settings.

**Action needed (operators).** Run the native online migration to
`p9_48_0069`. Its preceding revision, `p9_47_0068`, adds a mention-to-chunk
B-tree on existing data: it builds partition indexes concurrently, then attaches
them. It also replaces the existing document-entity index online with a
deployment-aware ordered shape, preventing absent-member bridge checks from
scanning unrelated documents under skew. Allow disk space and I/O/WAL for the
new mention index and temporary coexistence of both document-index shapes.
An interrupted own index
build is checked and completed on rerun; a colliding index with a different
definition causes setup to fail. Offline `alembic upgrade --sql` is unsupported
for this catalog-driven revision.

Concurrent migration processes wait on one database-scoped session lock before
reading revision state. It survives concurrent-index commits; ordinary reads and
ingestion do not acquire it. Each revision commits separately, so index-attachment
locks are released before the view update. A later migration failure leaves
earlier revisions committed; returning to an earlier release requires its
pre-upgrade backup. The acquisition wait defaults to
60 seconds and is configurable through `migration_lock_timeout_seconds` in
`alembic.ini`; an expired wait fails setup explicitly. The new view definitions
also change the query-space manifest identity, so saved-query revalidation uses
that new identity.

## 0.19.1 (November 2026)

Database migrations and the processing receipt contract stay at 0.19.0.

**Native storage evidence for operators.** The engine provides a read-only
capture integration with an original PostgreSQL view, in-guard allocated
relation/index/TOAST/fork records, exact provider-origin matching, classified
component amounts, and complete committed terminal membership. Operators
supply qualified source/store/clock profiles, dedicated ordinary collector
connections, provider transport and durable evidence storage. One bounded
batch captures Projects at the same cut; immutable canonical pages support
exact replay. See the repository's
[storage-capture development documentation](https://github.com/writeitai/remember-stack/blob/main/docs/development/storage-capture-managed-assembly.md)
for the callable boundary and functional validation limits.

**Processing and concurrency.**

- Entity resolution preserves valid matches from its original snapshot while
  guarding concurrent creation. Fact projection reserves bounded pending
  batches, allowing unrelated work to proceed concurrently.
- Image descriptions request explicit visual detail, defaulting to `high`.
  Existing description checkpoints refresh once under the changed fingerprint;
  matching OCR checkpoints remain reusable. Set
  `REMEMBERSTACK_IMAGE_DESCRIPTION_DETAIL` to an explicitly supported provider
  value when choosing another observation resolution.
- Explicit provider-unavailable rejection envelopes follow the existing
  bounded OpenRouter retry policy.

**LoCoMo development harness.** Answer-model and prompt trials have explicit
provider policies and bounded parallel question budgets. Development subsets
and judge models are pinned in run identities. Evidence reads preserve
complete constraints, initiating dialogue and attachment context; historical
semantic grading and grounded negative answers are restored.

## 0.19.0 (November 2026)

A stock self-hosted deployment needs no action. Its new migration,
`p9_46_0067`, reshapes the managed-metering tables, which are empty unless the
deployment is metered, and adds the `admission` defer reason. The Compose file changes only its release
image tags. The changes below matter to metered deployments (a control plane
that approves usage before work runs) and to code that reads readiness or
worker outcomes.

**Managed metering moves to the convert stage (D150).**

- **Action needed (metered deployments).** Migration `p9_46_0067` refuses to
  run while `managed_ingest_measurements` still holds staged originals,
  because those bytes exist nowhere else. On 0.18.x, drain the meter outbox
  until no measurement holds staged bytes, then upgrade. A measurement
  releases its bytes when its control plane accepts it or when its document
  is hard-forgotten; a parked or refused one keeps them.
- **Action needed (control planes).** The meter's wire contract is now v3:
  - `rememberstack.ingest_measurement.v3` carries `cost_class`,
    `native_quantity`, `unit` and `format_family`. This release emits these
    classes:
    - `doc-scan`, counted in pages, for every PDF page;
    - `doc-text`, counted in normalized characters, for other readable files.
  - `rememberstack.document_version_outcome.v3` is `succeeded` or `failed`.
  - Processing profiles are named `<cost class>-<standard|claims|sources>-v1`.

  A control plane must accept v3 before any deployment runs 0.19.0.
- **Behaviour change.** A metered deployment no longer refuses files at
  ingest. It stores every file, measures it in the convert stage, before any
  paid model call, and waits for approval:
  - a PDF is counted by its pages, before OCR;
  - a file read locally is counted by the characters of its reading;
  - a card is free;
  - a file whose route can't be measured fails with
    `rate_class_unavailable`.

  The ingest-time `409 rate_class_unavailable`, `422 rate_class_ambiguous`
  and `413 source_bytes_limit_exceeded` refusals, and the 10 MB text cap, are
  gone. A metered deployment now keeps each file's own type, so CSV, code and
  logs take their own routes. A document first ingested under the old text-only
  classifier is processed again once, at its next version.
- **Unmetered deployments are unchanged.**

**Readiness and worker outcomes.**

- `defer_reason` on a pipeline stage has a new value, `admission`. The
  metered deployment has measured the file and is waiting for its control
  plane's approval. See [Wait for readiness](/docs/guides/wait-for-readiness).
- A worker run can end with the new outcome `admission_parked`.
- Code that matches these values exhaustively must handle the new ones.

## 0.18.3 (November 2026)

A stock self-hosted deployment needs no action: its database migrations are
unchanged, and its Compose file changes only the release image tags. The **Action needed** item applies only to programs
that embed the engine and call `ingest_stored`.

**Processing.**

- A PDF over the OCR provider's per-request limits (about 50 MB or 1,000
  pages) is no longer refused. It is split into page-range batches that each
  fit, every batch is OCR'd, and the pages are stitched back in order, so
  every page is still OCR'd and metered once. Below both limits the request
  and the result are unchanged. The engine's own 100 MB PDF reading limit
  still applies when it reads the file itself (the stock in-process path);
  within that, only a single page over the byte limit is refused. `PdfConverter.convert_path` and `MistralOcrConverter.convert_path`
  convert a PDF from a file on disk without reading it whole.

**Integration.**

- **Action needed.** `UploadIngestor.ingest_stored` deletes an object it
  refuses (size, content type, metering, a forgotten source), unless a
  content already keeps that key, and raises `StoredObjectRefusedError`. Its
  `refusal` holds the original error and `raw_object_deleted` says whether
  the object was deleted. Code that caught `ContentDetectionError`,
  `ManagedTextClassificationError` or `ForgottenSourceError` from
  `ingest_stored` catches `StoredObjectRefusedError` and inspects `refusal`.
- `UploadIngestor.discard_unregistered` deletes a directly uploaded object
  that never became a version, unless a content keeps its key, for sweeping
  abandoned uploads. Serialize it with `ingest_stored` of the same key.

## 0.18.2 (November 2026)

A stock self-hosted deployment needs no action. Its database migrations and its
default conversion are unchanged, and its Compose file changes only the release
image tags.

**Processing.**

- **Behaviour change.** A file over its family's reading limit (100 MB for
  office documents and PDFs, 200 MB for spreadsheets) is no longer refused or
  carded when its route's converter fetches the file by a signed URL from S3
  storage. The engine reads nothing, so only the converter's own input limit
  applies. With the stock in-process converters the limits stay as before:
  an oversized PDF is refused and other oversized files become a card. See
  [File types](/docs/guides/file-types).
- An oversized file is carded without reading it into the worker's memory.
  The card itself is unchanged.

**Embedding the engine.**

- Conversion by reference. A converter can declare that it accepts a URL
  (`UrlConverter`). The worker then signs a short-lived GET URL for the raw
  object (`PresignedReadPort`, implemented by the S3 store) and never reads the
  bytes itself.
- `UploadIngestor.ingest_stored` registers a raw object that a client
  uploaded directly under `uploads/<id>`. The engine streams it once to hash
  and classify it, and keeps it at that key. If the same content is already
  stored under another key, the earlier version answers and the engine
  deletes the new copy. `ingest` now does the same, so each content keeps
  one raw object, the one a hard forget purges. On a deployment with managed
  text metering a stored object is measured exactly as an upload is.
- `ingest_scope_routes` lets an ingest-scoped credential call named host
  routes.
- Route scopes and the health check now work for an API mounted under a path
  prefix. Before, narrow credentials there got `403`.

<Cloud>

- A spend-gate hold refused as too large answers `413` instead of
  `503 spend_lease_unavailable`.

</Cloud>

## 0.18.1 (November 2026)

Version 0.18.0 was never released. Its PostgreSQL image failed to build, so it
has no PyPI package and no GitHub release. Its engine image
`ghcr.io/writeitai/remember-stack:0.18.0` is on GHCR; do not use it. 0.18.1 has
the same changes.

**Self-hosted upgrades need action.** Read
[Upgrades and migrations](/docs/self-hosting/upgrades) before moving an
existing deployment. A 0.17 deployment upgrades in place: its data is kept and
`setup` migrates it. PostgreSQL is the exception (below).

**PostgreSQL 19 release candidate 1.**

- **Action needed.** The database image is now
  `ghcr.io/writeitai/remember-stack-postgres:19rc1-0.18.1`. Releases up to
  0.17.2 ran PostgreSQL 19 Beta 3, and a Beta 3 data directory does not open
  under RC 1. Move in two steps:
  1. Upgrade the engine to 0.18.1 while it still runs on the Beta 3 image.
     `setup` drops the Beta 3 property graphs.
  2. Dump the database and restore it into a new RC 1 volume.

  The order matters: a dump taken before step 1 holds definitions RC 1 cannot
  restore. [Upgrades](/docs/self-hosting/upgrades#postgresql-server-versions)
  has the commands.
- The graph no longer uses SQL/PGQ, which RC 1 removed. One-hop neighbourhoods
  are plain joins over the same views, and they return the same results.
- **Action needed.** Readiness reasons are renamed:
  `graph_pgq_smoke_failed` is now `graph_one_hop_smoke_failed`, and
  `graph_pgq_guard_smoke_failed` is now `graph_one_hop_guard_smoke_failed`.
  Update any alerting that matches the old names.
- **Action needed.** The JSON output of `remember ops graph-catalog ensure` no
  longer has a `definitions` field. It no longer checks property graphs, and
  it checks the graph views instead.

**Workers.**

- **Action needed.** Workers run by class, not by stage. `worker --stage
  <stage>` is replaced by `worker --class convert|llm` with `--concurrency`.
  `convert` converts files one at a time. `llm` runs every other stage, with
  20 tasks in flight by default. The Compose file now has two worker services,
  `worker-convert` and `worker-llm`, in place of one per stage. Stop the old
  stack with `docker compose down --remove-orphans`, so the per-stage worker
  containers are removed. Size with `REMEMBERSTACK_SELFHOST_LLM_CONCURRENCY`
  and `REMEMBERSTACK_SELFHOST_CONVERT_CONCURRENCY`, or `--scale`; see
  [Scaling](/docs/self-hosting/scaling).
- A claimed task is a lease that its worker renews. If the worker dies, the
  task goes back to the queue once the lease expires, instead of staying
  `running` forever.
- Several deployments can run their migrations against one PostgreSQL server
  at the same time.
- Each worker item's log records `object_bytes_read` and
  `object_bytes_written` ([Observability](/docs/self-hosting/observability)).

**HTTP API.**

- **Behaviour change.** A request whose decoded path contains a control
  character, such as `%0A`, gets `400 invalid_path`. It is refused before
  authentication and routing.
- `POST /documents/search` finds documents by name, metadata and text.
  `documents` filters on `POST /search/claims` and `POST /search/chunks` limit
  a search to chosen documents. `source_path` on `POST /ingest` records where
  a file came from.
- Effective periods, version keys, section history and cross-references:
  read a document as it was in force on a date. See
  [Read a document as of a date](/docs/guides/versions-in-force).

<Cloud>

- Fixes to spend-gate classification. Section history with empty key segments,
  mounted paths and percent-encoded delimiters are now metered like any other
  read.

</Cloud>

**Processing.**

- **Behaviour change.** Every page of every PDF is OCR'd. A deployment
  without a Mistral OCR key parks PDFs as `no_route`.
  `REMEMBERSTACK_SELFHOST_CONVERSION_ROUTES` now adds to the stock route
  table instead of replacing it. It cannot route PDFs to a text-layer
  converter.
- Many more file types are ingested: office documents, HTML, e-books, email,
  notebooks, spreadsheets, delimited data and datasets. Code, logs and file
  cards are searchable, and claims are not extracted from them. See
  [File types](/docs/guides/file-types).
- The claims and facts layers can be switched off per deployment
  (`REMEMBERSTACK_SELFHOST_CLAIMS_LAYER`, `REMEMBERSTACK_SELFHOST_FACTS_LAYER`)
  and per request. Turning one back on processes the versions it skipped.
- Claims that refer to their own document by a phrase such as "this
  agreement" name the document.
- `REMEMBERSTACK_SELFHOST_RETRIEVAL_DATABASE_BUDGET_S` sets one retrieval
  operation's database time budget.
- `setup` accepts a database URL whose password is percent-encoded.

**Clients.**

- The `adjacent_chunks` MCP tool.
- A TypeScript client, `@rememberdev/client`, with the same methods as the
  Python client. It is available as repository source and is not published to
  npm.

**Embedding the engine.** A program can build an engine for a deployment
from explicit settings and run several in one process. It can run a named
task with `run_task`. Other options:

- one API app serving several deployments, which resolves, authenticates and
  admits each request against its own deployment;
- replaceable conversion routes;
- a forget-manifest bucket, so no deployment state is kept on local disk;
- credentials per bucket;
- `engine_options` for the database connection pool;
- a separate host, port and TLS settings for the SQL query role.

## 0.17.0 (22 September 2026)

**Existing deployments must be recreated.** The migrations for mutable fact
windows and multi-span claim evidence refuse a database that already holds
claims. Start from an empty deployment and send your sources again; see
[Upgrades and migrations](/docs/self-hosting/upgrades).

**One package: `remember`.**

- **Action needed.** The Python client, the CLI and the MCP server ship in
  one PyPI package, `remember`. The old `rememberstack` package is
  deprecated: its final version, 0.17.0, only forwards to `remember` and

  `import rememberstack` to `import remember`.
- **Action needed.** The engine is no longer installed with pip. Run it from
  the container image `ghcr.io/writeitai/remember-stack`.
- The `remember` package depends only on `httpx`, `pydantic` and
  `pydantic-settings`.
- New client class `remember.Client` (also `remember.RememberClient`) with an
  `api_key` argument, `from_env()`, `ingest_file()` and path support in
  `ingest()`.<Cloud> `remember.CloudClient` reads a remember.dev organisation's
  deployment, balance, ledger and spend gate.</Cloud>

**Assured operations renamed.**

- **Action needed.** `testimony_context` is now `claims_and_sources_context`,
  `fact_context` is now `facts_context`, and `answer_context` is now
  `combined_context`. `resolve_entity` is unchanged. The combined result is
  now `ContextBundle/v2`, whose evidence part is called
  `claims_and_sources`. Update names in HTTP calls, SDK calls, CLI commands
  and agent prompts.

**CLI.**

- New commands: `remember setup` (writes MCP configuration for Cursor,
  Claude Code, Claude Desktop, Codex and Antigravity), `remember doctor`<Cloud>,
  `remember whoami`, `remember switch`, `remember projects list`,
  `remember balance`</Cloud>.
- `remember query "<question>"` is short for `remember query text`, which
  runs `facts_context` (or `combined_context` with `--combined`).
- `remember query adjacent-chunks`.
- `remember review` and `remember budget` are retired.

<Cloud>

- `remember login --control` signs in with an organisation control-plane
  token. The credential file can now hold several projects and a
  control-plane token.

</Cloud>

**Retrieval.**

- New `adjacent_chunks`: read the passages immediately before and after a chunk
  (`GET /chunks/{id}/adjacent`, `POST /chunks/adjacent`, SDK, CLI).
- Name resolution at query time tries exact aliases, then fuzzy name
  matches, then profile similarity, and returns no candidate, one, or an
  explicit ambiguity.
- Fact labels no longer carry a bracketed date suffix; dates stay in the
  structured validity fields.

**Processing.**

- Claims can cite several separate spans of their source (multi-span
  evidence).
- In conversations, answers such as "Yep, that one" are resolved to what the
  question referred to, keeping ordinals and specific names.
- Relative dates ("last Friday") are written into the claim text as resolved
  dates.
- Images always get OCR and a visual description.
- Originals are kept, and documents whose media type has no converter are
  parked instead of failing; `remember ops resume-no-route` releases them
  once a route exists.
- Fact adjudication engine is configurable; OpenRouter requests rotate
  between providers when one is overloaded.
