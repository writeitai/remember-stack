# What is not built yet

<AppliesTo products={["remember.dev", "self-hosted"]} />

This page lists what you might expect and will not find. Everything here is
absent from the current release; nothing here has a date.

## Ingest

- **Audio and video.** RememberStack stores audio and video and describes
  each file with a card, but no converter turns speech or video into text.
- **Email attachments.** An `.eml` file's attachments are listed by name and
  size; they are not read.
- **URLs.** You cannot ingest a web page by its address; fetch the page
  yourself and upload the file.
- **Connectors and watched folders.** Nothing pulls documents from another
  system or a folder automatically; the `remember connectors` commands and
  SDK connector methods call routes that no deployment serves, and the
  `connectors-watched-directory` install extra installs nothing.

## Documents

- **Erasing a document.** Deleting a document removes it from the memory
  but keeps its claims and stored original as history; the HTTP API, the
  SDK, the CLI and the MCP tools cannot erase a document's bytes.
- **Deleting one version.** You can delete a whole document, not a single
  version of it.
- **Document filters on facts and operations.** Claim and chunk search
  take a `documents` filter; the assured operations (`facts_context` and the
  others), fact lookups and the SQL query functions do not yet, and there is
  no `documents` filter over MCP because MCP has no claim or chunk search
  tool.
- **Metadata from other formats.** Word, PowerPoint, PDF and email files
  give their title, people and dates, and `.xlsx` workbooks their title,
  author and dates; HTML, EPUB and notebooks give only a title, and other
  formats give none.
- **References found in the text.** RememberStack does not yet find
  references itself (links, citations, "see section 4.2"); every reference
  `document_references` returns is one you supplied with
  `PUT /documents/{doc_id}/versions/{version_id}/references`.
- **Fact dates from effective periods.** Declaring when a version is in
  force decides which text and evidence a time-scoped read uses, but does
  not yet inform the validity window of the facts that text supports.
- **Periods, references and section history from the CLI and MCP.** The CLI
  declares periods only at `remember ingest`, and the MCP server only through
  `ingest`; neither can change periods later or supply references. The CLI
  has no section history or references command; the MCP server has the
  `section_history` and `document_references` tools.
- **Waiting for readiness from the CLI.** No `remember` command waits for a
  document to be processed; use the SDK's `wait_for_readiness` or the MCP
  `pipeline_readiness` tool.

## Knowledge

- **Compiled pages.** RememberStack does not write summary pages that
  combine what it knows about a topic; the envelope's `pages` field and the
  `compiled` grain exist but stay empty, and the `k` install extra installs
  nothing.
- **Opening a source from an agent.** No MCP tool returns a whole original
  source file; agents read passages through search and `adjacent_chunks`
  (a self-hosted engine can publish its sources as files, see
  [Filesystem views](/docs/self-hosting/filesystem-views)).

## Clients

- **Async Python client.** The `remember` package is synchronous only.
- **Other languages.** A Node.js [TypeScript/JavaScript client](/docs/reference/typescript-sdk)
  is available as repository source. There is no Go client; use the
  [HTTP API](/docs/reference/http-api).

## Hosted MCP on remember.dev

- **Newer tools.** The hosted server serves the tools of the engine version
  remember.dev runs (v0.17.2), which has no `search_documents`,
  `adjacent_chunks`, `section_history` or `document_references` tool. See
  [What remember.dev serves](/docs/cloud/compatibility).
- **Files by path.** The hosted `ingest` tool takes `text` or
  `content_base64`, not `path`; it has no access to your files.

</Cloud>

## Running the engine

- **Kubernetes.** There is no Helm chart or Kubernetes manifest; the
  supported deployment is Docker Compose
  ([Install with Docker Compose](/docs/self-hosting/install)).

<Cloud>

## remember.dev account

- **Projects, members and balance from the CLI.** The CLI has no commands
  for them; use the console or the account tools of
  [hosted MCP](/docs/cloud/hosted-mcp#account-tools).
- **Removing members and changing roles in the console.** The console and
  the REST API cannot remove a member; the `remove_member` tool of hosted
  MCP can. Nothing changes a role yet.
- **Service keys.** Every API key acts for a person, so a key used by CI
  stops working when that person leaves the organisation.

</Cloud>
