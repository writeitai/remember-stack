# Configuration

<AppliesTo products={["self-hosted"]} />

RememberStack is configured entirely through environment variables. There
is no configuration file inside the engine. This page explains how the
variables reach the containers, which ones matter first, and how to set
the rest. [Configuration variables](/docs/reference/configuration) lists
every variable with its default.

## How the engine reads settings

Each part of the engine reads its own group of variables when the process
starts, through typed settings classes (pydantic-settings). Each group has
a prefix:

| Prefix | Group |
|---|---|
| `REMEMBERSTACK_SELFHOST_` | The deployment, the API, authentication, pools and workers, converter routes |
| `REMEMBERSTACK_OPENROUTER_` | The model provider |
| `REMEMBERSTACK_MINIO_` | Object storage (any S3-compatible store; Compose runs SeaweedFS) |
| `REMEMBERSTACK_STRUCTURER_`, `_E2_`, `_E3_`, `_OBS_`, `_FACT_`, `_P1_` … | One pipeline model seat each ([Models and providers](/docs/self-hosting/models)) |
| `REMEMBERSTACK_MISTRAL_OCR_`, `REMEMBERSTACK_IMAGE_DESCRIPTION_` | [Converters](/docs/self-hosting/converters) |
| `REMEMBERSTACK_WORK_` | Retries and spend budgets |
| `REMEMBERSTACK_SENTRY_` | [Error tracking](/docs/self-hosting/observability) |

Three rules follow from this:

- **The engine reads only the process environment.** It does not open a
  `.env` file itself. In the Compose setup, Docker Compose reads `.env`
  and passes values into the containers.
- **Values are checked at start.** A malformed value (a non-UUID deployment
  id, a pool concurrency larger than its pool, a converter route naming an
  unknown converter) stops the process with an error that names the
  variable. It never starts half-configured.
- **Blank means unset.** Compose turns an unset `${VAR:-}` into an empty
  string; the engine treats an empty value as "use the default" for the
  optional settings.

## What Compose passes through

`compose.yaml` does not hand your whole `.env` to the containers. Each app
service gets a fixed `environment:` list, and only variables on that list
reach the engine. The list covers the deployment identity, storage, the
OpenRouter settings most people change, the model seats, Mistral OCR,
authentication by shared secret or signed keys, the graph and retrieval pools, the API
admission limits<Cloud>, the remember.dev-only billing settings</Cloud> and Sentry.

Anything else — for example `REMEMBERSTACK_IMAGE_DESCRIPTION_API_KEY`,
`REMEMBERSTACK_COST_EXPORT_BIND`, the worker rate settings, `REMEMBERSTACK_OPENROUTER_ZDR` or
`REMEMBERSTACK_WORK_BUDGETS` — has **no effect** if you only put it in
`.env`. The reference marks which variables Compose passes.

To set the others, keep them in a separate file and add a
`compose.override.yaml` next to `compose.yaml`. Compose merges that file
automatically.

`engine.env`:

```bash
REMEMBERSTACK_OPENROUTER_ZDR=true
REMEMBERSTACK_SELFHOST_WORKER_RATE_PER_S=5
```

`compose.override.yaml`:

```yaml
x-engine-env: &engine-env
  env_file: [engine.env]

services:
  setup: *engine-env
  api: *engine-env
  worker-convert: *engine-env
  worker-structure: *engine-env
  worker-chunk: *engine-env
  worker-embed-chunk: *engine-env
  worker-extract-claims: *engine-env
  worker-ground-claims: *engine-env
  worker-normalize-relations: *engine-env
  worker-adjudicate-observations: *engine-env
  worker-adjudicate-supersession: *engine-env
  worker-embed-claim: *engine-env
  worker-reconcile: *engine-env
  worker-label-relation: *engine-env
  projections: *engine-env
```

Keep in `engine.env` only variables that `compose.yaml` does not already
set: a value in a service's `environment:` list wins over the same variable
from `env_file`. The later pages reuse this file; where a setting matters to
only some services, they say which.

## Apply a change

```bash
docker compose up -d
```

Compose recreates every container whose configuration changed. `setup`
runs again first, then the API and workers restart with the new values.
A running process never picks up a changed variable on its own.

## What to change first

For a machine only you can reach, these settings matter:

| Variable | Why |
|---|---|
| `REMEMBERSTACK_OPENROUTER_API_KEY` | Nothing is processed without it. |
| `REMEMBERSTACK_SELFHOST_DEPLOYMENT_ID` | Replace the example UUID with your own before the first start. |
| `REMEMBERSTACK_POSTGRES_PASSWORD`, `REMEMBERSTACK_MINIO_ACCESS_KEY`, `REMEMBERSTACK_MINIO_SECRET_KEY` | `.env.example` ships none; generate them as in [Install](/docs/self-hosting/install#1-get-the-files). |

Compose publishes the API on `127.0.0.1` only. To let other machines reach
it, set `REMEMBERSTACK_SELFHOST_API_BEARER_TOKEN` and
`REMEMBERSTACK_SELFHOST_REQUIRE_API_AUTH=true`, then
`REMEMBERSTACK_SELFHOST_API_PUBLISH_ADDRESS`
([Opening the API to other machines](/docs/self-hosting/authentication#opening-the-api-to-other-machines)).

To accept more than Markdown and plain text, set
`REMEMBERSTACK_SELFHOST_CONVERSION_ROUTES` ([File formats and converters](/docs/self-hosting/converters)).

## Settings fixed after the first start

The first `setup` records these in the database, and later runs refuse to
start if they change:

- `REMEMBERSTACK_SELFHOST_DEPLOYMENT_ID`
- `REMEMBERSTACK_SELFHOST_DEPLOYMENT_SLUG`
- `REMEMBERSTACK_SELFHOST_DEPLOYMENT_NAME`
- `REMEMBERSTACK_SELFHOST_DEFAULT_LANGUAGE` (default `en`)
- the three bucket names, `REMEMBERSTACK_SELFHOST_RAW_BUCKET_NAME`,
  `…_ARTIFACTS_BUCKET_NAME` and `…_CORPUSFS_BUCKET_NAME`

The embedding model is not checked this way, but changing it has
consequences of its own; see [Models and providers](/docs/self-hosting/models#changing-the-embedding-model).

## The client side

The `remember` CLI and Python client read a separate, small set of
variables on your own machine, most importantly `REMEMBER_API_URL` and
`REMEMBER_API_KEY`. They are listed at the top of
[Configuration variables](/docs/reference/configuration#client).
