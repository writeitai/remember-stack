# Project Status

Current public release: [`v0.2.0`](https://github.com/writeitai/remember-stack/releases/tag/v0.2.0) on [PyPI](https://pypi.org/project/rememberstack/0.2.0/) and [GHCR](https://github.com/writeitai/remember-stack/pkgs/container/remember-stack).

## What ships today

### Core memory engine

- Full evidence spine: ingest → convert → structure → chunk → claim extract → entity resolve → fact adjudicate
- Immutable claims, adjudicated relations and observations, bi-temporal validity, supersession, contradiction groups
- Testimony currency and lineage-based evidence counting when documents change or extractors re-run
- Watched sources and versioned document lineages (including a local directory watcher)

### Retrieval and agent surfaces

- Search indexes, knowledge-graph snapshots, and a browsable corpus filesystem
- Four assured operations: `resolve_entity`, `testimony_context`, `fact_context`, `answer_context`
- Open query: sandboxed SQL, read-only Cypher, saved examples, schema discovery
- MCP assured-operation and open-query tools (stdio client transport)
- Self-accounting response envelopes (grain, freshness, contradictions, typed negatives)
- API, CLI, and MCP in lockstep; optional filesystem mounts and a deployment-rendered consumption skill
- Cold-agent skill checks so harnesses keep claims and facts straight

### Knowledge pages

- Compiled and authored markdown knowledge in git
- Mechanical routing and staleness; authored principles are never machine-rewritten

### Operations

- Docker Compose single-deployment self-host (Postgres, object storage, API, continuous workers)
- Work ledger with retries, dead-letter queue, optional spend ceilings
- Machine-verifiable readiness; projection rebuilds; hard-forget; portable restore order
- Optional observability exporters (off until configured)

### Packaging

- Client-first `rememberstack` wheel; `[server]`, connector, `[k]`, `[benchmark]`, and `[observability]` extras
- One semantic version across PyPI, GHCR image, and Compose

## Smoke-profile limits (be honest)

| Area | Status in default Compose smoke |
| --- | --- |
| Markdown ingest | Supported |
| PDF / HTML / media conversion | Engine-capable; register routes — not auto-wired in the smoke profile |
| Query-time entity resolve | Exact-name match; richer matching runs at write time |
| Competitive benchmark scores | Operator-run protocols; not a continuous public scoreboard |

## Planned for v0.3.0 (not in the v0.2.0 release)

- MCP memory write verbs: `ingest` + `pipeline_readiness` (async write; poll until ready). Documented on the [MCP reference](/docs/reference/mcp); not present in installs pinned to `0.2.0`.

## Intentionally not in the library

- Multi-tenant hosted control plane, billing, or dashboards
- Production SLA claims from these docs
- Automatic free-model routing for publication benchmarks
- Secret management product (use your own secret store)
