# remember.dev or self-hosted?

<AppliesTo products={["remember.dev", "self-hosted"]} />

Everything RememberStack does with your documents is in the open-source
engine: extraction, entities, facts, time, evidence and retrieval.
remember.dev runs that engine for you; it does not change it. The choice is
about who operates it, not about how well it remembers.

## What each involves

| | Self-hosted | remember.dev |
|---|---|---|
| **Memory engine** | RememberStack, Apache-2.0 | RememberStack, one isolated deployment per project |
| **What you run** | PostgreSQL 19 with eight extensions, S3-compatible object storage, the API and twelve pipeline workers | Nothing. You install the `remember` client. |
| **File formats** | Markdown, plain text, HTML, Word, PowerPoint and Excel by default; PDFs and images once you configure an OCR converter | UTF-8 Markdown and plain text, up to 10,000,000 bytes per document |
| **Model inference for the pipeline** | Your own OpenRouter account, plus a Mistral key for PDFs and images | Included in the processing charge |
| **Endpoint** | Wherever you run it | `https://<deployment-id>.dp.remember.dev`, over TLS, straight to your deployment |
| **Access for agents** | You configure bearer or signed-token authentication | API tokens from the console, `remember login`, and hosted MCP with browser sign-in |
| **Upgrades** | You pull the new image and run migrations | Handled for you |
| **Cost** | Your infrastructure and your model usage | Prepaid credits for an active project, processed text and stored data. Reading is not charged. See [Pricing](/docs/cloud/pricing). |
| **Surfaces** | Everything in this documentation | See [What remember.dev serves](/docs/cloud/compatibility) |
| **Help** | GitHub issues | Support in the console |

## What self-hosting takes

Self-hosting is a real option, and the full engine is yours to run. It is
also real work. The engine uses PostgreSQL 19, which is still in beta,
because it relies on the property-graph queries that version introduces. It
needs the pgvector, pg_textsearch, pg_partman, pg_trgm, fuzzystrmatch,
unaccent, btree_gist and pgcrypto extensions. The Compose file builds that
database for you.

Each document passes through twelve stages, and each stage runs as its own
worker. You provide model access for them, keep them healthy, and upgrade
them together. You are responsible for authentication, TLS, backups and
monitoring. [Requirements](/docs/self-hosting/requirements) lists every
piece.

## Choose self-hosted if

- your documents must stay on machines you control;
- you already operate PostgreSQL and containers and want to own the model
  bill directly;
- you need PDFs, images or Office files read directly; remember.dev accepts
  Markdown and plain text only;
- you want to read, change or extend the engine.

## Choose remember.dev if

- you want to send your first document today, not after a day of setup;
- you do not want to run a beta release of PostgreSQL;
- you want your coding agent connected with one URL and a browser sign-in;
- you would rather pay for processed text than run twelve workers.

## Switching later

The client, the operations and the results are the same on both, so your
code does not change when you switch. Only the endpoint and the token do.

Your stored memory does not move between them. remember.dev has no export,
and there is no import. Moving means sending your source documents again to
the new target. Keep your source files; they are the durable copy.
