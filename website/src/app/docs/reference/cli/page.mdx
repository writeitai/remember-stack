# CLI

<AppliesTo products={["remember.dev", "self-hosted"]} />

This page describes the `remember` CLI (v0.17.0), installed by `pip install remember`.

The `remember` command stores documents, asks the memory questions, connects
coding agents and signs you in to remember.dev. It comes with the `remember`
Python package:

```bash
pip install remember
remember --version
```

It needs Python 3.12 or newer. `uv tool install remember` installs it as a
standalone tool; `uvx remember …` runs it without installing.

The package also installs a second command, [`remember-status`](#remember-status).

## Commands at a glance

| Group | Command | What it does |
|---|---|---|
| Memory | [`ingest`](#remember-ingest) | Upload one file. |
| | [`query`](#remember-query) | Ask a question, or run SQL queries and saved queries. |
| | [`operations`](#remember-operations) | List or run assured operations by name. |
| | [`documents`](#remember-documents) | List documents, or delete one from the memory. |
| Agents | [`mcp`](#remember-mcp) | Serve the memory to a coding agent over MCP. |
| | [`setup`](#remember-setup) | Write MCP configuration for your coding agents. |
| | [`doctor`](#remember-doctor) | Check installation, credentials, connectivity and agent configuration. |
| Account | [`login`](#remember-login) | Sign in to remember.dev from the terminal. |
| | [`logout`](#remember-logout) | Revoke the stored tokens and delete the credential file. |
| | [`whoami`](#remember-whoami) | Show who you are signed in as and which project is active. |
| | [`switch`](#remember-switch) | Make another stored project the active one. |
| | [`projects list`](#remember-projects-list) | List your organisation's projects. |
| | [`balance`, `billing`](#remember-balance) | Show the organisation's credit balance. |
| Console only | [`projects create`, `members list`, `members invite`](#commands-that-point-to-the-console) | Print a link to the web console and exit with status 1. |
| Not served | [`connectors`](#remember-connectors) | Talks to routes no deployment serves yet. |
| Engine operators | [`ops`](#self-hosted-operations-remember-ops) | Pipeline repair inside the engine container. |

`remember` with no command prints help and exits with status 2.
`remember <command> --help` prints that command's flags.

## How the CLI finds your deployment

Every command that talks to a deployment (`ingest`, `query`, `operations`,
`mcp`, `connectors`, `doctor`) accepts the same three flags:

| Flag | Meaning |
|---|---|
| `--api-url URL`, `--url URL` | The deployment address. |
| `--token TOKEN` | The deployment token. A bare secret or a full `Bearer …` value. |
| `--self-hosted` | Marks the target as a self-hosted engine. Only `whoami`, `balance`, `projects`, `switch` and `members` use it; it does not change the address. |

Put flags after the subcommand: `remember query sql --api-url … "SELECT 1"`.

### Address

First match wins:

1. `--api-url` / `--url`
2. `REMEMBER_DATA_PLANE_URL`, then `REMEMBER_API_URL`, then `REMEMBERSTACK_API_URL`
3. The active project's address in the [credential file](#credential-file)
4. `http://127.0.0.1:8000`

### Token

First match wins:

1. `--token`
2. `REMEMBER_TOKEN`, then `REMEMBER_API_AUTHORIZATION`, then `REMEMBERSTACK_API_AUTHORIZATION`
3. The active project's token in the credential file. When the address came
   from a flag or the environment, the stored token is used only if that
   address has the same scheme, host and port as the stored project.
4. `REMEMBER_API_KEY`
5. No token

<Callout type="note">

A stored credential wins over `REMEMBER_API_KEY`. To force the key in
that variable, pass it with `--token` or put it in `REMEMBER_TOKEN`.

</Callout>

<Tabs>

<Tab label="remember.dev">

```bash
remember login
remember query "Who owns the billing migration?"
```

`remember login` stores the project's address and token, so you pass
neither afterwards.

</Tab>

<Tab label="Self-hosted">

```bash
export REMEMBER_API_URL=http://localhost:8000
export REMEMBER_TOKEN=<the token your engine accepts, if any>
remember query "Who owns the billing migration?"
```

</Tab>
</Tabs>

### Output

Commands print their results to standard output: JSON for memory commands,
plain text for account commands. Warnings and errors go to standard error, so
you can pipe the output into `jq` safely.

When the stored credential expires within 30 days, or has expired, memory
commands print a warning on standard error. When a replaced credential could
not be revoked, every command prints a warning until `remember login` or
`remember logout` retires it.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Success. |
| 1 | The request failed (network, HTTP error, rejected token), the credential file is unusable, a check in `doctor` failed, or the command only points to the web console. |
| 2 | Usage error: unknown command or flag, missing argument, or an argument the CLI could not parse (for example `--parameters` that is not a JSON array). Also `--token-host` that is not a usable URL. |
| 130 | `remember login` was interrupted with Ctrl-C. |

## Memory commands

### `remember ingest`

```text
remember ingest FILE [--mime MIME] [--title TITLE]
                     [--source-kind KIND --source-ref REF]
                     [--source-modified-at ISO8601]
                     [--versioning-mode {snapshot,living}]
                     [--source-version-ref REF]
                     [--api-url URL] [--token TOKEN] [--self-hosted]
```

Uploads one file and prints the new version as JSON:

```json
{"deployment_id":"…","doc_id":"…","version_id":"…","content_hash":"…","created":true}
```

`created` is `false` when these exact bytes are already stored for the same
document; nothing is processed again.

| Flag | Default | Meaning |
|---|---|---|
| `FILE` | required | Path of the file to upload. |
| `--mime` | from the file's extension (`.md` is `text/markdown`, `.pdf` is `application/pdf`; the full table is in [Ingest files](/docs/guides/ingest-files#the-mime-type)), else `application/octet-stream` | Media type. The engine processes only types it has a converter for; see [File formats and converters](/docs/self-hosting/converters). |
| `--title` | none | Human title. |
| `--source-kind`, `--source-ref` | none | The document's stable identity. Give both or neither. Re-ingesting with the same pair makes a new version of the same document. |
| `--source-modified-at` | none | When the source last changed, as an ISO 8601 timestamp with a UTC offset of zero, for example `2026-09-21T14:00:00+00:00`. Needs `--source-kind`/`--source-ref`. |
| `--versioning-mode` | `snapshot` | `snapshot` or `living`; `living` needs `--source-kind`/`--source-ref`. See [Updating a source](/docs/concepts/updating-sources). |
| `--source-version-ref` | none | The source system's revision label. Needs `--source-kind`/`--source-ref`. |

Exit status 2 when the source arguments break these rules or the timestamp is
not UTC; 1 when the file cannot be read or the upload fails.

```bash
remember ingest notes/2026-09-18-billing-sync.md \
  --title "Billing sync, 18 September" \
  --source-kind meeting-notes --source-ref billing-sync/2026-09-18
```

It prints the `IngestedVersion` as one JSON line. When the file's
conversion is parked waiting for a conversion route, the line has
`"parked":"no_route"` and the command also prints a warning to stderr that
names the release step (`remember ops resume-no-route`); the exit status stays 0,
because the file is stored. See
[File formats and converters](/docs/self-hosting/converters#files-no-route-accepts).

Ingest returns before processing ends. To wait, use the SDK's
`wait_for_readiness` or the MCP `pipeline_readiness` tool; the CLI has no
readiness command. See [Wait until a document is queryable](/docs/guides/wait-for-readiness).

### `remember documents`

```text
remember documents list [--limit N] [--cursor CURSOR]
                        [--status {ingesting,converting,structuring,ready,failed}]
                        [--api-url URL] [--token TOKEN] [--self-hosted]
remember documents delete DOC_ID [--api-url URL] [--token TOKEN] [--self-hosted]
```

`list` prints one page of documents as JSON, newest document first, in the
shape of [`DocumentPage`](/docs/reference/result-types#documentpage). Pass the
page's `cursor` to `--cursor` to read the next page; `cursor` is `null` on
the last page. `--limit` is 1 to 200 (default 50). `--status` keeps only
documents whose newest version has that status.

```bash
remember documents list --status failed | jq -r '.documents[] | "\(.doc_id) \(.title)"'
```

`delete` removes one document, every version of it, from the memory and
prints what changed:

```json
{"doc_id":"…","deleted_at":"2026-09-23T10:41:07.318000Z","claims_retired":12,"relations_closed":2,"observations_closed":1}
```

Its claims stop counting as evidence, and facts that only it supported are
closed with a recorded retraction. The claims and the stored original stay
as history. Deleting needs a `write` credential. Deleting a document that
does not exist, or is already deleted, prints
`error: API 404: document_not_found` and exits with status 1. See
[`DELETE /documents/{doc_id}`](/docs/reference/http-api/ingest#delete-documentsdoc_id).

```bash
remember documents delete a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b
```

### `remember query`

```text
remember query "QUESTION" [--combined]
remember query text "QUESTION" [--combined]
remember query sql STATEMENT [--parameters JSON] [--max-rows N]
remember query explain-sql STATEMENT [--parameters JSON]
remember query space [--pattern GLOB] [--include-examples]
remember query search-space QUERY [--k N]
remember query list-saved [--namespace NS] [--status STATUS]
remember query describe-saved NAMESPACE NAME [--version N]
remember query run-saved NAMESPACE NAME [--version N] [--parameters JSON] [--max-rows N]
remember query adjacent-chunks CHUNK_ID [--window {1,2}]
```

Every subcommand also takes `--api-url`, `--token` and `--self-hosted`.

#### Asking a question

`remember query "QUESTION"` is short for `remember query text "QUESTION"`.
It runs the `facts_context` operation and prints the result
[envelope](/docs/reference/result-types) as indented JSON. With `--combined` it runs
`combined_context` instead and prints both the facts and what sources said.

```bash
remember query "Who owns the billing migration?"
remember query --combined "Why did the cutover move to October?"
```

<Callout type="note">

The shorthand applies only when no argument after `query` is exactly a
subcommand name (`text`, `sql`, `explain-sql`, `space`, `search-space`,
`list-saved`, `describe-saved`, `run-saved`, `adjacent-chunks`). To ask
a one-word question such as "space", write `remember query text space`.

</Callout>

For other operation arguments (`time`, `entity_ids`, `k`), use
[`remember operations run`](#remember-operations).

#### SQL queries

SQL queries run over the query space (`memory_v1`): prepared, read-only views
and functions. The engine parses every statement and validates it against
the query space before it runs; anything outside it is rejected. Output is
the `QueryResult/v1` JSON object. See [Query space memory_v1](/docs/reference/query-space).

| Subcommand | Arguments | What it prints |
|---|---|---|
| `sql` | `STATEMENT`; `--parameters` (JSON array of positional values for `$1`, `$2`, …); `--max-rows` (integer, 0 or more) | The result rows and their provenance. |
| `explain-sql` | `STATEMENT`; `--parameters` | The plan, without running the statement. |
| `space` | `--pattern` (shell-style filter over view names); `--include-examples` | The views, functions, comments and limits. |
| `search-space` | `QUERY`; `--k` (default 10; the engine accepts 1–25) | Matching entries of the query space's own documentation, never your data. |
| `list-saved` | `--namespace`; `--status` | Saved queries. Without `--status`, active versions only. |
| `describe-saved` | `NAMESPACE NAME`; `--version` | One saved query's SQL, parameters and columns. |
| `run-saved` | `NAMESPACE NAME`; `--version`; `--parameters`; `--max-rows` | The result of one active saved query. |

`NAMESPACE` and `NAME` must match `^[a-z][a-z0-9_]*$`. A malformed
`--parameters` value exits with status 2.

```bash
remember query sql \
  "SELECT predicate, count(*) AS n FROM facts_current GROUP BY 1 ORDER BY 2 DESC LIMIT \$1" \
  --parameters '[10]'
```

#### `adjacent-chunks`

Prints the passages immediately before and after one chunk, in document order.
`--window` is 1 (default) or 2.

```bash
remember query adjacent-chunks 6f1c2d0e-… --window 2
```

### `remember operations`

```text
remember operations list [--api-url URL] [--token TOKEN] [--self-hosted]
remember operations run NAME [--arg KEY=VALUE]... [--api-url URL] [--token TOKEN] [--self-hosted]
```

`list` prints one JSON descriptor per line for the four assured operations,
with each one's input schema.

`run` runs one operation. Each `--arg` is `KEY=VALUE`; the value is parsed as
JSON when it can be, otherwise kept as a string. The result prints as one
line of JSON.

```bash
remember operations run facts_context \
  --arg query="billing migration owner" \
  --arg 'time={"mode":"history"}' \
  --arg k=25
```

An `--arg` without `=` exits with status 2. Operation names and arguments are
in [Assured operations](/docs/reference/assured-operations).

## Agent commands

### `remember mcp`

```text
remember mcp [--read-only] [--api-url URL] [--token TOKEN] [--self-hosted]
```

Runs an MCP server on standard input and output for a coding agent. It finds
the deployment the same way as every other command, so after
`remember login` it needs no flags. `--read-only` removes the `ingest` and
`delete_document` tools.

You rarely start it yourself; `remember setup` writes the agent
configuration that starts it. The tools, their parameters and the errors are
in [MCP tools](/docs/reference/mcp).

### `remember setup`

```text
remember setup [--cloud | --self-hosted] [--url URL] [--token TOKEN]
               [--agent {cursor,claude,codex,agy,all}] [--dir DIR] [--dry-run]
```

Writes MCP configuration so your coding agents start `remember mcp`.

| Flag | Default | Meaning |
|---|---|---|
| `--cloud` | chosen when you pick nothing and standard input is not a terminal | Configure for remember.dev. |
| `--self-hosted` | | Configure for an engine at `--url`, default `http://localhost:8000`. |
| `--url` | none | The deployment address. With `--self-hosted` or `--cloud` it is written into the agent configuration as `REMEMBER_DATA_PLANE_URL`. |
| `--token` | none | A token to store in the [credential file](#credential-file). Never written into agent configuration. With `--cloud` it requires `--url` unless you are already signed in. |
| `--agent` | `all` | Which agent to configure. `agy` is Antigravity; `claude` means Claude Code and Claude Desktop. |
| `--dir` | current directory | The project directory for project-level configuration. |
| `--dry-run` | off | Print what would change; write nothing. |

With neither `--cloud` nor `--self-hosted`, on an interactive terminal, the
command asks which backend to use; remember.dev is the default answer.

What it does, in order:

1. Finds the launcher. It prefers an installed `remember` binary; when that
   binary lives in a virtual environment or a cache, or when there is none,
   it uses `uvx remember mcp`. Paths are resolved to absolute paths so an
   editor started from a desktop launcher finds them. With neither
   `remember` nor `uvx` on `PATH` it exits with status 1.
2. Updates the credential file when you pass `--token` or `--self-hosted`
   (see the warning below).
3. Configures each agent. With `--agent all` it configures what it finds:
   Cursor if `.cursor/` exists in the directory, Antigravity if `.agents/`
   exists, Codex if `.codex/` exists or `codex` is installed, Claude Code if
   `claude` is on `PATH`, Claude Desktop if its configuration file exists
   (or, on macOS, the app is installed). If it finds none, it configures
   Cursor and Antigravity.

The exact files and their content are listed in
[MCP tools: configuration that `remember setup` writes](/docs/reference/mcp#configuration-that-remember-setup-writes).

<Callout type="warning">

`remember setup --self-hosted` rewrites the credential file: it adds a
project named `self_hosted` pointing at the engine, with the token from
`--token` (or an empty one), and makes it the active project. Afterwards
every command talks to the self-hosted engine. Run `remember switch` to
go back to a remember.dev project.

</Callout>

Existing configuration files must be valid JSON or TOML; otherwise the
command stops with status 1 and changes nothing in that file.

```bash
remember setup --self-hosted --agent cursor --dry-run
```

### `remember doctor`

```text
remember doctor [--api-url URL] [--token TOKEN] [--self-hosted]
```

Checks your setup and prints one line per check:

1. `remember` or `uvx` is on `PATH`.
2. The credential file: its location, whether its mode is `0600`, the
   signed-in identity, the active project and the token's expiry.
3. The deployment: `GET /deployment` with a 5-second timeout. The stored
   token is sent only when the address matches the stored project. A `401`
   or `403` is reported as an authentication failure. When `/deployment`
   answers anything else, it tries `GET /healthz`.
4. Agent configuration in the current directory: `.cursor/mcp.json`,
   `.agents/mcp_config.json`, `.codex/config.toml`, and Claude Desktop's
   configuration file. For each it checks the file parses, contains a
   `remember` server, and that server's command exists and is executable.

`[✓]` is a pass, `[-]` is informational, `[!]` is a failure. Exit status 1
when any check fails.

## Account commands

These commands concern remember.dev. Against a self-hosted engine they say
so and do nothing.

### `remember login`

```text
remember login [--token-host URL] [--api-url URL]
               [--audience {deployment,control} | --control-plane | --control]
```

Signs you in with a device code. The command prints a link and a short code;
you open the link, sign in to remember.dev, check that the code matches, and
approve. The command waits for the approval, then stores the token in the
[credential file](#credential-file).

| Flag | Default | Meaning |
|---|---|---|
| `--token-host` | see below | Where to request the token. |
| `--api-url` | the address remember.dev advertises for the deployment | Override the deployment address that gets stored. |
| `--audience` | `deployment` | `deployment`: a deployment token (`umc_dp_…`) with read and write access to one project's memory; you pick the organisation and project in the browser. `control`: a control-plane token (`umc_cp_…`) that can read organisation status, balance and projects, and cannot read memory or spend money. |
| `--control-plane`, `--control` | | Same as `--audience control`. |

Token host, first match wins: `--token-host`; `REMEMBER_CONTROL_PLANE_URL`,
`REMEMBER_TOKEN_HOST`, `REMEMBERSTACK_TOKEN_HOST`;
`https://remember.dev/app/api`. For remember.dev you pass none of them.

```bash
remember login
```

After approval it prints:

```text
[✓] Authenticated with Remember Cloud.
deployment_id: …
active_project: …
token_prefix: umc_dp
token_host: https://remember.dev/app/api
api_url: https://<deployment-id>.dp.remember.dev
expires_at: …
```

Behaviour worth knowing:

- A deployment login adds the project to the credential file and makes it
  active. Projects you signed in to before stay in the file; use
  `remember switch` to move between them.
- A control login adds the control-plane token next to your projects.
- When you sign in again to the same project, the new token replaces the old
  one and the old one is revoked after the new one is safely on disk. If the
  revoke cannot be confirmed, the old token is recorded and retried on the
  next `login` or `logout`; revoke it in the console if the warning persists.
- If remember.dev reports that the deployment's address is not live yet, the
  login fails and asks you to try again later, unless you pass `--api-url`.
- If `REMEMBER_API_URL` (or another address variable) points elsewhere, the
  command warns that it will override the stored address.
- The browser step has a time limit set by the server. When it runs out, or
  you deny the request, the command exits with status 1.

### `remember logout`

```text
remember logout [--token-host URL]
```

Revokes every stored remember.dev token (the active one, every stored
project's, and the control-plane token) and then deletes the credential file.
Tokens for `localhost`, `127.0.0.1` and `.local` addresses are not sent
anywhere. If a revoke is not confirmed, the file is kept and the command exits
with status 1. With no credential file it does nothing and exits 0.

### `remember whoami`

```text
remember whoami [--api-url URL] [--token TOKEN] [--self-hosted]
```

Prints the signed-in user id, email and organisation (when a control-plane
token is stored), the active project and its address. Exit status 1 when you
are not signed in. Against a self-hosted engine it prints
`Identity: self-hosted (local)` and the address.

### `remember switch`

```text
remember switch PROJECT [--api-url URL] [--token TOKEN] [--self-hosted]
```

Makes another project in the credential file the active one. `PROJECT` is a
project id or name as `remember projects list` shows it. It changes only the
local file; it cannot reach a project you have not signed in to. Exit status
1 when the project is not in the file.

### `remember projects list`

```text
remember projects list [--api-url URL] [--token TOKEN] [--self-hosted]
```

Prints a table: project id, name, status, and `*` for the active project.

- With a control-plane token stored (`remember login --control`), it asks
  remember.dev for the organisation's projects. The name column shows the
  first eight characters of the project id; remember.dev does not send
  project names on this route.
- Otherwise, or when that request fails, it lists the projects stored in
  the credential file.

Against a self-hosted engine it prints a single row, `local`.

### `remember balance`

```text
remember balance [--api-url URL] [--token TOKEN] [--self-hosted]
remember billing ...      (same command)
```

Prints `Current balance: €<amount> [<billing state>]` for your organisation.
It needs a control-plane token (`remember login --control`); without one it
prints the console address, `https://remember.dev/app/billing`, and exits
with status 1. Prices and credits: [Pricing and credits](/docs/cloud/pricing).

### `remember-status`

```text
remember-status [--org ORG_ID] [--url URL] [--quiet]
```

A separate command for scripts. It reads a control-plane token from
`REMEMBER_CLOUD_TOKEN`, the organisation from `REMEMBER_CLOUD_ORG` (or
`--org`) and the address from `REMEMBER_CLOUD_URL` (or `--url`, default
`https://remember.dev/app/api`). It does not read the credential file.

It prints the deployment state and id, whether its address is live, the
billing state and balance, and the spend gate's decision:

```text
deployment  active     3f0c…
endpoint    live       3f0c….dp.remember.dev
billing     ACTIVE     balance 42.50
spend       allow
```

| Exit | Meaning |
|---|---|
| 0 | A deployment exists and is live, billing allows spending, and the spend gate allows work. |
| 1 | Any of those is not true. |
| 2 | Missing token or organisation, rejected token, rate limited, or another error. |

`--quiet` prints nothing; use the exit status. The same checks in Python:
[`CloudClient`](/docs/reference/python-sdk#cloudclient).

## Commands that point to the console

These commands exist, do not change anything, print a link to the web
console and exit with status 1.

| Command | What it prints |
|---|---|
| `remember projects create NAME` | Create projects at `https://remember.dev/app/projects`, then run `remember login`. |
| `remember members list` | Manage members at `https://remember.dev/app/team`. |
| `remember members invite EMAIL [--role {member,owner}]` | Invite members at `https://remember.dev/app/team`. `--role` defaults to `member`. |

Against a self-hosted engine each says that projects and members are
remember.dev features. See
[Organisations, projects and members](/docs/cloud/organisations-and-projects).

## `remember connectors`

```text
remember connectors list
remember connectors add KIND --name NAME [--config KEY=VALUE]... [--credential-ref REF]
remember connectors pause CONNECTOR_ID
remember connectors status CONNECTOR_ID
```

These commands call `/connectors` routes that no deployment serves today.

## Self-hosted operations: `remember ops`

`remember ops` repairs and inspects a self-hosted engine's pipeline. It runs
only inside the engine container, and only when
`REMEMBERSTACK_INTERNAL_OPS=1` is set (`REMEMBER_INTERNAL_OPS` also works).
Elsewhere it prints an error and exits with status 1. The help output does
not list it.

```bash
docker compose exec -e REMEMBERSTACK_INTERNAL_OPS=1 api \
  remember ops inspect --deployment "$REMEMBERSTACK_SELFHOST_DEPLOYMENT_ID"
```

`--deployment` is the engine's deployment id
(`REMEMBERSTACK_SELFHOST_DEPLOYMENT_ID`).

| Subcommand | Flags | What it does | Output |
|---|---|---|---|
| `inspect` | `--deployment ID` | A bounded report of the pipeline: work in progress, dead letters, projections and freshness. | JSON |
| `cost-export` | `--deployment ID`, `--cursor CURSOR`, `--limit N` (default 100) | One page of the cost export, which holds no document content. Exit 2 when `--deployment` does not match the engine or the cursor is invalid. | JSON |
| `resume-no-route` | `--deployment ID` | Releases documents that were parked because no converter handled their media type, once a route now covers them. | `{"released": [...]}` |
| `replay` | `PROCESSING_ID`, `--deployment ID`, `--attempts N` (default 1), `--lane {steady,backfill}`, `--not-before ISO8601` | Reopens one dead-lettered work item with N more attempts. | JSON |
| `rebuild` | `--deployment ID`, `--snapshot-root PATH`, `--version VERSION` | Rebuilds the filesystem view snapshot. | JSON |
| `graph-catalog ensure` | none | Checks the database's graph metadata and repairs it when needed. | `{"ready", "changed", "problems_before", "problems_after", "definitions"}` |

When and why to use each: [Operating the pipeline](/docs/self-hosting/operating).

## Engine container commands

The engine image `ghcr.io/writeitai/remember-stack` has its own entry point,
`python -m rememberstack.profiles.selfhost`. `compose.yaml` runs each process
with one of these commands; you use them when you write your own
orchestration.

| Command | What it runs |
|---|---|
| `setup` | Applies database migrations and prepares the deployment. Runs once; the other services start after it succeeds. |
| `api` | The HTTP API. Listens on `REMEMBERSTACK_SELFHOST_API_HOST` (default `0.0.0.0`) and `REMEMBERSTACK_SELFHOST_API_PORT` (default `8000`). This is the image's default command. |
| `worker --stage STAGE` | One pipeline worker. `STAGE` is one of `convert`, `structure`, `chunk`, `embed_chunk`, `extract_claims`, `ground_claims`, `normalize_relations`, `adjudicate_observations`, `adjudicate_supersession`, `embed_claim`, `reconcile`, `label_relation`. Run one process per stage. |
| `meter-receipts [--once] [--limit N]` | Sends ingest usage receipts for managed hosting. `--limit` defaults to 100. In `compose.yaml` it belongs to the `managed` profile; a self-hosted engine does not need it. |
| `project --plane p3` | Builds the filesystem view snapshot once. In `compose.yaml` it belongs to the `operations` profile. |
| `mounts --root PATH [--raw-root PATH] [--artifacts-root PATH]` | Publishes the latest snapshot under a local directory. |

The pipeline stages are explained in
[The pipeline and readiness](/docs/concepts/pipeline); configuration in
[Configuration](/docs/self-hosting/configuration); snapshots and mounts in
[Filesystem views](/docs/self-hosting/filesystem-views).

## Credential file

`remember login` and `remember setup` store tokens in `credentials.json`.

Location, first match wins:

1. `REMEMBER_CONFIG_DIR` or `REMEMBERSTACK_CONFIG_DIR`
2. `$XDG_CONFIG_HOME/remember/`
3. `~/.config/remember/`

Protection:

- The directory is created with mode `0700` and the file with mode `0600`.
  The file is written to a temporary name and renamed, so a crash leaves
  either the old file or the new one.
- The CLI refuses to read a file that is a symbolic link or that group or
  other users can read, and exits with status 1. Fix it with
  `chmod 600 ~/.config/remember/credentials.json`.
- Commands that change the file take a lock (`.lock` in the same directory).

Next to it, `pending-revocation.json` lists replaced tokens that could not be
revoked yet (at most 20). `login` and `logout` retry them.

Format, version 1 (tokens shortened):

```json
{
  "version": 1,
  "active_project_id": "8c1d…",
  "projects": {
    "8c1d…": {
      "name": "billing-migration",
      "data_plane_url": "https://3f0c….dp.remember.dev",
      "data_plane_token": "umc_dp_…",
      "deployment_id": "3f0c…",
      "token_host": "https://remember.dev/app/api",
      "token_id": "…",
      "expires_at": "2027-09-23T10:00:00Z"
    }
  },
  "control_plane": {
    "url": "https://remember.dev/app/api",
    "access_token": "umc_cp_…",
    "org_id": "…",
    "token_id": "…",
    "expires_at": "…"
  },
  "api_url": "https://3f0c….dp.remember.dev",
  "access_token": "umc_dp_…",
  "token_host": "https://remember.dev/app/api",
  "token_type": "Bearer",
  "token_id": "…",
  "org_id": "…",
  "deployment_id": "3f0c…",
  "label": "billing-migration",
  "token_prefix": "umc_dp",
  "expires_at": "2027-09-23T10:00:00Z"
}
```

The top-level `api_url`, `access_token` and related fields repeat the active
project. `control_plane` is present only after `remember login --control`.
The file rejects unknown keys: a file written by a newer CLI can be refused
by an older one; `remember login` again fixes it.

The Python SDK never reads this file.

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `REMEMBER_DATA_PLANE_URL`, `REMEMBER_API_URL`, `REMEMBERSTACK_API_URL` | memory commands | Deployment address. |
| `REMEMBER_TOKEN`, `REMEMBER_API_AUTHORIZATION`, `REMEMBERSTACK_API_AUTHORIZATION` | memory commands | Deployment token, ahead of the credential file. |
| `REMEMBER_API_KEY` | memory commands | Deployment token, after the credential file. |
| `REMEMBERSTACK_API_TIMEOUT_SECONDS` | memory commands | Seconds per request; default 30. |
| `REMEMBER_CONTROL_PLANE_URL`, `REMEMBER_TOKEN_HOST`, `REMEMBERSTACK_TOKEN_HOST` | `login`, `logout` | Token host. |
| `REMEMBER_CONFIG_DIR`, `REMEMBERSTACK_CONFIG_DIR` | all | Credential file directory. |
| `XDG_CONFIG_HOME` | all | Base for the default credential directory. |
| `REMEMBERSTACK_INTERNAL_OPS`, `REMEMBER_INTERNAL_OPS` | `ops` | Enables `remember ops` inside the engine container. |
| `REMEMBERSTACK_MCP_INGEST_ROOTS`, `REMEMBERSTACK_MCP_PATH_READ_MAX_BYTES` | `mcp` | Path ingest; see [MCP tools](/docs/reference/mcp#ingest-from-a-path). |
| `REMEMBER_CLOUD_TOKEN`, `REMEMBER_CLOUD_ORG`, `REMEMBER_CLOUD_URL` | `remember-status` | Control-plane token, organisation, address. |
| `APPDATA` (Windows), `XDG_CONFIG_HOME` (Linux) | `setup`, `doctor` | Where Claude Desktop's configuration lives. |

Names are not case-sensitive. All client variables are in
[Configuration variables](/docs/reference/configuration).
