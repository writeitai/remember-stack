# CLI

Pagination follows the shared [Pagination and truncation](/docs/reference/http-api#pagination-and-truncation) contract (D154).

<AppliesTo products={["remember.dev", "self-hosted"]} />

This page describes the `remember` CLI (v0.22.1), installed by `pip install remember`.

The `remember` command stores documents, asks the memory questions and
connects coding agents<Cloud>. It also signs you in to remember.dev</Cloud>. It
comes with the `remember` Python package:

```bash
pip install remember
remember --version
```

It needs Python 3.12 or newer. `uv tool install remember` installs it as a
standalone tool; `uvx remember …` runs it without installing.

Use the CLI if your agent can run shell commands. Its help and results enter
the agent's context only when requested. MCP gives clients without a shell a
curated tool list whose descriptions and schemas take context on every turn.
See [MCP tools](/docs/reference/mcp).

## How the CLI finds your deployment

Commands that use the deployment API accept these connection and request flags.

| Flag | Meaning |
|---|---|
| `--timeout SECONDS` | HTTP request timeout for SDK-backed commands. Overrides `REMEMBER_TIMEOUT`, default 300 seconds. For `readiness --wait` it also sets the polling deadline. |
| `--api-url URL` | The deployment address. |
| `--api-key KEY` | The API key. A bare key or a full `Bearer …` value. |
| `--project PROJECT` | Which project to use, by id or name, when the key covers several.<Cloud> Only a remember.dev key uses it.</Cloud> |

The `doctor` health probe keeps its short five-second check. Remote MCP bridge
mode uses its fixed 300-second timeout; `--timeout` and `REMEMBER_TIMEOUT` apply
to the local-engine MCP path.

Put flags after the subcommand: `remember query sql --api-url … "SELECT 1"`.

Each setting is resolved on its own. First match wins:

| Setting | 1. Flag | 2. Environment | 3. [Credential file](#credential-file) | 4. Otherwise |
|---|---|---|---|---|
| Key | `--api-key` | `REMEMBER_API_KEY` | `key` | no key |
| Address | `--api-url` | `REMEMBER_API_URL` | `api_url` | `http://127.0.0.1:8000`<Cloud>, or the project's address for a remember.dev key</Cloud> |
| Project | `--project` | `REMEMBER_PROJECT` | `default_project` | none<Cloud>, or the key's default project</Cloud> |

The Python SDK resolves the same settings the same way
([Python SDK](/docs/reference/python-sdk#connecting)).

A key read from the credential file is only sent to the address stored beside
it<Cloud>, to remember.dev, or to a project address remember.dev returns for
that key</Cloud>. If `--api-url` or `REMEMBER_API_URL` names another address,
the command exits with status 2 and asks for the key explicitly, with
`--api-key` or `REMEMBER_API_KEY`. A key you pass explicitly is sent wherever
you point it.

```bash
remember query "Who owns the billing migration?"
```

`remember login` stores one key. Each command asks remember.dev which address

</Tab>

### Output

Pass `--json` before or after the command. A completed command writes one JSON
value to stdout, with the protocol streams listed below as exceptions. Diagnostics,
warnings and progress go to stderr. Check the exit status before using the result.

```bash
remember setup --json --self-hosted --agent cursor --dry-run
remember --json tags list
remember --json --version
```

| Command | JSON output |
|---|---|
| Memory commands and engine `ops` | Their documented result object. `operations list` and `connectors list` return arrays in JSON mode, including `[]` when empty. They keep one object per line in default mode. |
| `setup` | `backend` (`cloud` or `self_hosted`), `dry_run` and the `harnesses` array. Harness IDs are `cursor`, `agy`, `codex`, `claude_code` and `claude_desktop`. JSON mode skips the backend question and requires an existing hosted key, `--headless`, or `--dry-run` for hosted setup. |
| `doctor` | `version`, overall `ok` and `checks`. Each check contains `name`, `ok` and `detail`. A failed check still produces the report and exits nonzero. |
| `login` | `issuer`, `key_id` and `expires_at` after approval. Instructions and the short browser approval code go to stderr. Complete the browser step while the command polls. |
| `whoami` | `api_url` for a stored self-hosted connection. For a hosted key, `issuer`, `key_id`, `expires_at`, `projects`, `permissions`, `default_project` and `account` when available. |
| `switch` | `project` (the new default project's ID) and `name`. |
| `logout` | `removed` is true when the stored entry was removed and false when no entry was present. |
| `unmount` | `{"unmounted":true}` on success. |
| `--version` | `version`. |
| `mcp`, `mount` | MCP stdout carries its JSON-RPC messages in stdio mode. Mount stdout carries newline-delimited JSON events as they happen. `--json` gives command-level failures the same stderr format as other commands. |
| `--help` | Command help text. |

In JSON mode a failure emits a JSON object under `error` on stderr. Read
`code`, `retryable` and `agent_action` to choose the next step. Other stderr
lines can contain progress or warnings. See [CLI and MCP errors](/docs/reference/errors#mcp-tool-errors).

For SQL result reports, read `termination_reason` to tell whether the
statement completed. See [SQL query results](/docs/reference/http-api/query#how-results-and-errors-come-back).

For a confirmed permanent forget in a script, pass `--yes`. Without that flag,
JSON mode exits with `confirmation_required` before sending the request.

When the stored key expires within 30 days, or has expired, memory commands

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Success. |
| 1 | A request failed, the credential file is unusable, a `doctor` check failed, or `readiness --wait` stopped on a dead-lettered stage or timed out.<Cloud> Also when remember.dev cannot resolve the project.</Cloud> |
| 2 | Usage error: unknown command or flag, missing argument, or an argument the CLI could not parse (for example `--parameters` that is not a JSON array). Also a stored key refused for the address you named. |

<Cloud>

`remember login` exits with status 130 when it is interrupted with Ctrl-C.

</Cloud>

## Memory commands

### `remember ingest`

```text
remember ingest FILE [--filename NAME] [--mime MIME] [--title TITLE]
                     [--source-kind KIND --source-ref REF]
                     [--source-modified-at ISO8601]
                     [--versioning-mode {snapshot,living}]
                     [--source-version-ref REF]
                     [--version-key KEY]
                     [--effective-from ISO8601 [--effective-until ISO8601]]
                     [--tag TAG]... [--allow-forgotten]
                     [--api-url URL] [--api-key KEY] [--project PROJECT]
```

Uploads one file and prints the new version as JSON:

```json
{"deployment_id":"…","doc_id":"…","version_id":"…","content_hash":"…","created":true,"mime":"text/markdown","title":"…","versioning_mode":"snapshot","parked":null,"version_key":null}
```

`created` is `false` when these exact bytes are already stored for the same
document; nothing is processed again.

| Flag | Default | Meaning |
|---|---|---|
| `FILE` | required | Path of the file to upload. |
| `--filename` | the file's own name | The name the document is stored under. The media type still comes from `FILE`'s extension unless you pass `--mime`. |
| `--mime` | from the file's extension (`.md` is `text/markdown`, `.pdf` is `application/pdf`; the full table is in [Ingest files](/docs/guides/ingest-files#the-mime-type)), else `application/octet-stream` | Media type. The engine processes only types it has a converter for; see [File formats and converters](/docs/self-hosting/converters). |
| `--title` | none | Human title. |
| `--source-kind`, `--source-ref` | none | The document's stable identity. Give both or neither. Re-ingesting with the same pair makes a new version of the same document. |
| `--source-modified-at` | none | When the source last changed, as an ISO 8601 timestamp with a UTC offset of zero, for example `2026-09-21T14:00:00+00:00`. Needs `--source-kind`/`--source-ref`. |
| `--versioning-mode` | `snapshot` | `snapshot` or `living`; `living` needs `--source-kind`/`--source-ref`. See [Updating a source](/docs/concepts/updating-sources). |
| `--source-version-ref` | none | The source system's revision label. Needs `--source-kind`/`--source-ref`. |
| `--version-key` | none | Your permanent name for this version, unique within the document, for example `edition-2`. A new key always creates a version. Needs `--source-kind`/`--source-ref`. |
| `--effective-from` | none | When this version's text comes into force (included), as an ISO 8601 timestamp with a UTC offset of zero. Needs `--source-kind`/`--source-ref` and `--versioning-mode snapshot`. |
| `--effective-until` | none | When it stops being in force (excluded), later than `--effective-from`. Omitted: until the next declared start. |
| `--tag` | none | A registered tag, by name or id, to add to the document. Repeat it for several. Ingest only adds tags; see [Tags](/docs/reference/http-api/ingest#tags). |
| `--allow-forgotten` | off | Add back content of a [forgotten](#remember-forget) document. Without it such a file is refused (`error: API 409: …document_forgotten…`); with it, it is accepted once that forget is no longer erasing and comes back under a new `doc_id`. See [Adding forgotten content back](/docs/reference/http-api/ingest#adding-forgotten-content-back). |

What a key and a period do: [Versions in force](/docs/reference/http-api/ingest#versions-in-force).

Exit status 2 when the source arguments break these rules, a timestamp is
not UTC, or a period is malformed; 1 when the file cannot be read or the
upload fails, including a `409` for a key or period start already used by
another version, and a `422` for a tag that is not registered
(`error: API 422: unknown tags: …`).

```bash
remember ingest notes/2026-09-18-billing-sync.md \
  --title "Billing sync, 18 September" \
  --source-kind meeting-notes --source-ref billing-sync/2026-09-18

remember ingest travel-policy-2026.md \
  --source-kind intranet --source-ref policy/travel \
  --version-key edition-2 --effective-from 2026-01-01T00:00:00+00:00
```

It prints the `IngestedVersion` as one JSON line. When the file's
conversion is parked waiting for a conversion route, the line has
`"parked":"no_route"` and the command also prints a warning to stderr that
names the release step (`remember ops resume-no-route`); the exit status stays 0,
because the file is stored. See
[File formats and converters](/docs/self-hosting/converters#files-no-route-accepts).

Ingest returns before processing ends. Pass the returned `version_id` to
[`remember readiness --wait`](#remember-readiness).

### `remember readiness`

```text
remember readiness VERSION_ID... [--wait] [--timeout SECONDS] [--poll-interval SECONDS] [--require-p3]
```

Check up to 1,000 version UUIDs from ingest. The command requires the pipeline,
search index (`p1`) and live graph to be ready. Add `--require-p3` to also
require publication to the corpus.

Without `--wait` the command checks once, prints the readiness report as JSON
and exits 0 even if the report says `"ready": false`. With `--wait` it checks
immediately and waits 15 seconds between successful checks by default. Set a
positive `--poll-interval` to change the minimum gap between checks. The wait
deadline defaults to 1,800 seconds. An explicit `--timeout` sets both the wait
deadline and the maximum HTTP request timeout. `REMEMBER_TIMEOUT` sets the
HTTP request timeout when you omit the flag.

A stage marked `failed` can retry, so polling continues. Temporary connection
failures, request timeouts, and retryable server errors such as HTTP `503` or
`524` also keep the wait going, with backoff within the original deadline.
A `dead_letter` stage or a non-retryable error such as HTTP `401` stops the
wait immediately. For a `dead_letter` stage, stderr names the version and stage.

At the deadline the command exits with status 1. Stdout contains the last
successful report if one was received. Stderr carries `readiness_timeout` and
includes the last retryable request error if there was one. Add `--json` to
read errors as JSON. See [Wait until a document is queryable](/docs/guides/wait-for-readiness).

### `remember documents`

```text
remember documents list [--limit N] [--cursor CURSOR]
                        [--status {ingesting,converting,structuring,ready,failed}]
                        [--include-archived]
                        [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents search [QUERY] [--family FAMILY]... [--author NAME_OR_ADDRESS]...
                          [--recipient NAME_OR_ADDRESS]...
                          [--created-from T] [--created-to T]
                          [--modified-from T] [--modified-to T]
                          [--language LANG] [--include-archived]
                          [--thread-ref REF] [--doc-id DOC_ID]...
                          [--tag TAG]... [--any-tag TAG]... [--not-tag TAG]...
                          [--versions {current,all}] [--limit N] [--cursor CURSOR]
                          [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents archive DOC_ID [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents unarchive DOC_ID [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents forget DOC_ID [--yes] [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents tag DOC_ID [--add TAG]... [--remove TAG]...
                              [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents tag DOC_ID --set TAG [--set TAG]...
                              [--api-url URL] [--api-key KEY] [--project PROJECT]
remember documents section-history DOC_ID SECTION_KEY [--time JSON] [--limit N] [--cursor CURSOR]
remember documents references (--doc-id DOC_ID | --chunk-id CHUNK_ID) [--section-key KEY]
                              [--direction {incoming,outgoing,both}] [--kind KIND]...
                              [--time JSON] [--limit N] [--cursor CURSOR]
remember documents reference-generations DOC_ID VERSION_ID
remember documents set-references DOC_ID VERSION_ID FILE
remember documents set-effective-periods DOC_ID VERSION_ID --periods JSON
remember documents clear-effective-periods DOC_ID
```

`list` prints one page of documents as JSON, newest document first, in the
shape of [`DocumentPage`](/docs/reference/result-types#documentpage). Pass the
page's `next_cursor` to `--cursor` to read the next page; `next_cursor` is `null` on
the last page. `--limit` is 1 to 200 (default 50). `--status` keeps only
documents whose newest version has that status. `--include-archived` also
lists archived documents, each with `archived_at`.

```bash
remember documents list --status failed | jq -r '.documents[] | "\(.doc_id) \(.title)"'
```

`search` finds documents by name, metadata and text and prints a
[`DocumentSearchPage`](/docs/reference/result-types#documentsearchpage) as
JSON. Repeat `--family`, `--author`, `--recipient` and `--doc-id` to list
several; any listed value matches. `--tag` keeps documents that carry every
listed tag, `--any-tag` those that carry at least one, and `--not-tag` those
that carry none; each is repeatable, and a tag that is not registered is an
error. `--include-archived` also returns archived documents, each with
`archived_at`. Dates are ISO 8601 with a timezone, for
example `2025-01-01T00:00:00+00:00`. With a `QUERY` the results are ranked and
there is no next page; without one they are newest ingested first and
`--cursor` reads the next page. `--limit` is 1 to 200 (default 50), used as
the ranked result count with a query and the page size without one. A query
with `--cursor` is refused before sending a request. See
[`POST /documents/search`](/docs/reference/http-api/ingest#post-documentssearch).

```bash
remember documents search "q3 sales" --family spreadsheet | jq -r '.documents[] | "\(.doc_id) \(.file_name)"'
remember documents search --author alice@acme.com --created-from 2025-01-01T00:00:00+00:00
remember documents search --tag kind:decision --any-tag project:billing --any-tag project:support
```

`archive` archives one document, every version of it: the memory stops
believing it, and it stays readable as history. It prints what changed:

```json
{"doc_id":"…","archived_at":"2026-09-23T10:41:07.318000Z","claims_retired":12,"relations_closed":2,"observations_closed":1}
```

Its claims stop counting as evidence, and facts that only it supported are
closed with a recorded retraction. `list` and `search` leave it out unless
you pass `--include-archived`. Archiving an archived document prints the same
`archived_at` with zero counts. See
[`POST /documents/{doc_id}/archive`](/docs/reference/http-api/ingest#post-documentsdoc_idarchive).

`unarchive` undoes an archive exactly and prints
`{"doc_id":"…","claims_restored":12,"facts_reopened":3}`: the claims the
archive retired count again, and the facts it closed reopen when they have
support again. A document that is not archived prints zero counts. See
[`POST /documents/{doc_id}/unarchive`](/docs/reference/http-api/ingest#post-documentsdoc_idunarchive).

Both need a `write` credential. For a document that does not exist, both
print `error: API 404: document_not_found` and exit with status 1.

```bash
remember documents archive a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b
remember documents unarchive a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b
```

`forget` erases one document, every version of it, and everything derived
only from it, for good. It first asks for confirmation on the terminal; any
answer but `y` or `yes` forgets nothing and exits with status 1, and `--yes`
skips the question. It prints the forget record, in the shape of
[`Forget`](/docs/reference/result-types#forget):

```json
{"forget_id":"…","doc_id":"…","status":"erasing","requested_at":"2026-11-24T10:41:07.318000Z","completed_at":null,"blocking_k_paths":[],"last_error":null}
```

The document is gone from every read at once; what was derived from it is
erased in the background, which [`remember forget status`](#remember-forget)
follows. There is no undo: the content can only be ingested again with
`remember ingest --allow-forgotten`. Forgetting the same document again prints
its existing record. A document that does not exist prints
`error: API 404: document_not_found` and exits with status 1. See
[`POST /documents/{doc_id}/forget`](/docs/reference/http-api/ingest#post-documentsdoc_idforget).

```bash
remember documents forget a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b --yes
```

`tag` changes the tags of one document in one step and prints its tags
afterwards, in the shape of
[`DocumentTags`](/docs/reference/result-types#documenttags). `--add` and
`--remove` take a tag name or id and can each be repeated. `--set` replaces
the document's whole set instead and cannot be combined with them (exit
status 2); `--set ''` removes every tag. Every tag must be registered; see
[`remember tags`](#remember-tags). An unregistered tag prints
`error: API 422: unknown tags: …` and exits with status 1, and nothing
changes. See
[`POST /documents/{doc_id}/tags`](/docs/reference/http-api/ingest#post-documentsdoc_idtags).

```bash
remember documents tag a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b --add kind:decision --remove kind:draft
```
```json
{"doc_id":"a1f3e0b4-1c2d-5e6f-8a9b-0c1d2e3f4a5b","tags":["kind:decision","project:billing-migration"]}
```

#### Section history and references

`section-history` follows a section key across document versions. It defaults
to history and shows the effective intervals and section state for each
version. Use `--time` to select a narrower scope.

`references` lists links into and out of a document or chunk. With
`--doc-id`, you can add `--section-key` to keep references for that section
and its descendants. `--direction` defaults to `both`. Repeat `--kind` to keep
any of the listed kinds. By default the read uses the current document
scope, or the chunk's in-force intervals up to now with `--chunk-id`.
Both commands take a page size of 1–200 (default 50). Pass the returned
`next_cursor` to `--cursor` to continue.

`--time` takes a JSON object. Use `{"mode":"current"}` for the current
version, `{"mode":"history"}` for all history, or `{"mode":"at","at":"2026-09-24T12:00:00Z"}`
for what was in force at an instant. Use `mode: "overlap"` with `from` and
`to` to read a time window. See [Section history and references](/docs/reference/http-api/sections-and-references).

`set-references` replaces the entire supplied set for one version with an
NDJSON file. Write one [reference object](/docs/reference/http-api/ingest#put-documentsdoc_idversionsversion_idreferences)
per line. Blank lines are ignored. An empty file supplies an empty set.
`reference-generations` prints the version's generations newest first,
including their status and validation errors. Check for an `active` generation
after submitting a set.

#### Effective periods

`set-effective-periods` replaces all declarations for one version. Give
`--periods` a JSON array with an `effective_from` for each period and an
optional `effective_until`. Use ISO 8601 UTC instants. The start is inclusive,
the end exclusive. Omit the end to use the next declared start in the document.
Use `[]` to leave this version with no in-force period while keeping declared
effective time for the document.

`clear-effective-periods` retracts the declarations for every version of the
document. Current reads then use the newest processed version. The engine
preserves the declaration history. See [Versions in force](/docs/guides/versions-in-force).

### `remember forget`

```text
remember forget list [--api-url URL] [--api-key KEY] [--project PROJECT]
remember forget status FORGET_ID [--api-url URL] [--api-key KEY] [--project PROJECT]
```

`list` prints every forget record of the deployment, oldest first, as a
[`ForgetList`](/docs/reference/result-types#forgetlist). `status` prints one
[`Forget`](/docs/reference/result-types#forget) record: `status` is `erasing`,
`waiting_for_redaction` (the authored knowledge pages in `blocking_k_paths`
still cite the document) or `complete`. An unknown `FORGET_ID` prints
`error: API 404: forget_not_found` and exits with status 1.

```bash
remember forget status 6c1d2e3f-4a5b-4c3d-9e8f-7a6b5c4d3e2f | jq -r .status
```

### `remember tags`

```text
remember tags list [--query TEXT] [--api-url URL] [--api-key KEY] [--project PROJECT]
remember tags create NAME --description TEXT [--api-url URL] [--api-key KEY] [--project PROJECT]
remember tags update TAG [--name NAME] [--description TEXT]
                         [--api-url URL] [--api-key KEY] [--project PROJECT]
remember tags delete TAG [--api-url URL] [--api-key KEY] [--project PROJECT]
```

Manage the deployment's tags: names such as `project:billing-migration` that
you assign to documents, each with a description of what it means. What tags
are for: [Tag documents](/docs/guides/tag-documents).

| Command | Prints | Notes |
|---|---|---|
| `list` | [`TagList`](/docs/reference/result-types#taglist) | `--query` keeps tags whose name or description contains it, ignoring letter case. |
| `create NAME --description TEXT` | the new [`Tag`](/docs/reference/result-types#tag) | `--description` is required. A name already registered in any letter case prints `error: API 409: a tag named '…' is already registered` and exits with status 1. |
| `update TAG` | the changed `Tag` | `TAG` is the name (any letter case) or id. Give `--name`, `--description` or both; neither exits with status 2. Documents keep the tag; the old name stops working. |
| `delete TAG` | the deleted `Tag` | Removes the tag from every document that carries it. |

A `TAG` that is not registered prints `error: API 404: unknown tags: …` and
exits with status 1. The commands print one JSON line.

```bash
remember tags create project:billing-migration \
  --description "Documents about moving invoicing to the new billing provider."
remember tags list --query billing | jq -r '.tags[] | "\(.name)  \(.description)"'
```

### `remember query`

```text
remember query "QUESTION" [--combined] [--tag TAG]... [--any-tag TAG]... [--not-tag TAG]...
remember query text "QUESTION" [--combined] [--layers LIST] [--tag TAG]... [--any-tag TAG]... [--not-tag TAG]...
remember query sql STATEMENT [--parameters JSON] [--max-rows N] [--layers LIST]
remember query explain-sql STATEMENT [--parameters JSON] [--layers LIST]
remember query space [--pattern GLOB] [--include-examples]
remember query search-space QUERY [--k N]
remember query list-saved [--namespace NS] [--status STATUS]
remember query describe-saved NAMESPACE NAME [--version N]
remember query run-saved NAMESPACE NAME [--version N] [--parameters JSON] [--max-rows N] [--layers LIST]
remember query adjacent-chunks CHUNK_ID [--window {1,2}]
```

Every subcommand also takes `--api-url`, `--api-key` and `--project`.

`--layers` narrows a read to some of the deployment's
[processing layers](/docs/concepts/retrieval#narrowing-a-read-to-layers): a
comma-separated subset of `sources`, `claims` and `facts`, for example
`--layers sources,claims`. Without it a read uses every layer the deployment
serves.

#### Asking a question

`remember query "QUESTION"` is short for `remember query text "QUESTION"`.
It runs the `facts_context` operation and prints the result
[envelope](/docs/reference/result-types) as indented JSON. With `--combined` it runs
`combined_context` instead and prints both the facts and what sources said.

```bash
remember query "Who owns the billing migration?"
remember query --combined "Why did the cutover move to October?"
remember query "Who owns the cutover?" --tag project:billing-migration
```

`--tag`, `--any-tag` and `--not-tag` (each repeatable) read only documents
that carry every `--tag`, at least one `--any-tag` and no `--not-tag`, as on
[`remember documents search`](#remember-documents). Facts then come only
from those documents' support, while contradictions from other documents
stay in the answer, marked `"in_documents_filter": false`; see
[The documents filter](/docs/reference/assured-operations#the-documents-filter).
An unregistered tag is refused with `unknown_tag`.

<Callout type="note">

The shorthand applies unless the word right after `query` is exactly a
subcommand name (`text`, `sql`, `explain-sql`, `space`, `search-space`,
`list-saved`, `describe-saved`, `run-saved`, `adjacent-chunks`). To ask
a one-word question such as "space", write `remember query text space`.

</Callout>

For other operation arguments (`time`, `entity_ids`, `k`), use
[`remember operations run`](#remember-operations).

#### SQL queries

SQL queries run over the query space (`memory_v1`): prepared, read-only views
and functions. The engine parses every statement and validates it against
the query space before it runs; anything outside it is rejected. Output is
the `QueryResult/v1` JSON object. See [Query space memory_v1](/docs/reference/query-space).

| Subcommand | Arguments | What it prints |
|---|---|---|
| `sql` | `STATEMENT`; `--parameters` (JSON array of positional values for `$1`, `$2`, …); `--max-rows` (integer, 0 or more) | The result rows and their provenance. |
| `explain-sql` | `STATEMENT`; `--parameters` | The plan, without running the statement. |
| `space` | `--pattern` (shell-style filter over view names); `--include-examples` | The views, functions, comments and limits. |
| `search-space` | `QUERY`; `--k` (default 10; the engine accepts 1–25) | Matching entries of the query space's own documentation, never your data. |
| `list-saved` | `--namespace`; `--status` | Saved queries. Without `--status`, active versions only. |
| `describe-saved` | `NAMESPACE NAME`; `--version` | One saved query's SQL, parameters and columns. |
| `run-saved` | `NAMESPACE NAME`; `--version`; `--parameters`; `--max-rows` | The result of one active saved query. |

`NAMESPACE` and `NAME` must match `^[a-z][a-z0-9_]*$`. A malformed
`--parameters` value exits with status 2.

```bash
remember query sql \
  "SELECT predicate, count(*) AS n FROM facts_current GROUP BY 1 ORDER BY 2 DESC LIMIT \$1" \
  --parameters '[10]'
```

#### `adjacent-chunks`

Prints the passages immediately before and after one chunk, in document order.
`--window` is 1 (default) or 2.


### `remember search`

```text
remember search claims QUERY [--k N] [--channel {semantic,bm25}] [--documents JSON] [--time JSON]
```

Search claims or source passages and print an evidence envelope. `--k` is

Use `--documents` for a JSON object of [document filters](/docs/reference/result-types#documentsearchfilters).

```text
remember resolve NAME [--context-entity-id ENTITY_ID]...
```

Print entity candidates for a name. Repeat `--context-entity-id` for up to eight

### `remember lookup`

```text
remember lookup relations [--subject-entity-id ENTITY_ID] [--predicate PREDICATE]
                          [--object-entity-id ENTITY_ID] [--valid-at INSTANT] [--limit N] [--cursor CURSOR]
remember lookup observations ENTITY_ID [--limit N] [--cursor CURSOR]
remember lookup observations ENTITY_ID --property-query QUERY [--k N]
```

`relations` pages relations matching the given subject, predicate and object
filters. Pass an ISO 8601 instant with a timezone to `--valid-at` to read
relations that held then. Without it the command reads current relations.

`observations` browses live observations for one entity. Use `--property-query`
to rank observations by text. `--k` is 1–400 (default 10) for ranked results.
For either browse command, `--limit` is 1–200 (default 50), and the response's
`next_cursor` continues the browse. See [Entities and facts](/docs/reference/http-api/entities-and-facts).

### `remember graph`

```text
remember graph neighborhood ENTITY_ID [--hops N] [--predicate PREDICATE]...
                            [--valid-at INSTANT] [--believed-at INSTANT]
                            [--limit N] [--cursor CURSOR] [--include-paths]
remember graph path FROM_ENTITY_ID TO_ENTITY_ID [--max-hops N] [--predicate PREDICATE]...
                    [--valid-at INSTANT] [--believed-at INSTANT]
remember graph citation-path FROM_DOC_ID TO_DOC_ID [--max-hops N]
```

`neighborhood` reads up to four hops around an entity (default two).
It pages results with `--limit` (1–500, default 100) and `--cursor`. Add
`--include-paths` to include paths to the returned neighbors.

`path` finds shortest paths between two entities. `citation-path` follows
directed document references from one document to another. Both accept a
`--max-hops` of 1–6, default four for `path` and six for `citation-path`.

For entity traversal, repeat `--predicate` to keep edges with any of the
given predicates. `--valid-at` selects when facts held, and `--believed-at`
selects when the engine held that belief. Supply ISO 8601 instants with a
timezone. See [Graph](/docs/reference/http-api/graph).

### `remember relation`

```text
remember relation hydrate RELATION_ID
remember relation transcript RELATION_ID
```

`hydrate` follows a relation's evidence to source documents. `transcript`
reads the bounded record of decisions that changed the relation. Use a

## Agent commands

### `remember mcp`

```text
remember mcp [--read-only] [--layers LIST] [--api-url URL] [--api-key KEY] [--project PROJECT]
remember mcp --transport http [--bind HOST:PORT] [--read-only] [--layers LIST] [--api-url URL]
```

<Cloud>

```text
remember mcp [--read-only] [--remote-url URL] [--api-key KEY]
```

</Cloud>

Runs an MCP server for a coding agent. By default it speaks on standard input
and output and finds the deployment the same way as every other
command<Cloud>, so after `remember login` it needs no flags</Cloud>.
`--transport http` serves the same tools over HTTP at
`http://127.0.0.1:8765/mcp` instead (`--bind` picks another loopback address or port).
`--read-only` removes the tools that change memory: `ingest`,
`archive_document`, `unarchive_document`, `forget_document` and the tag tools that change tags. `--layers` narrows every read of the session to those
[processing layers](/docs/concepts/retrieval#narrowing-a-read-to-layers) and
leaves out the tools that read only other layers.

<Cloud>

With a remember.dev key and no `--api-url`, it relays the agent's messages to
the MCP endpoint remember.dev advertises for the key instead of serving the
tools itself. `--remote-url` or `REMEMBER_MCP_URL` names another endpoint;
the stored key is only sent to the advertised one, so another endpoint needs
the key passed explicitly. `--remote-url` cannot be combined with `--api-url`,
`--project` or `--transport http`.

</Cloud>

You rarely start it yourself; `remember setup` writes the agent
configuration that starts it. The two transports, the tools, their parameters
and the errors are in [MCP tools](/docs/reference/mcp).

### `remember setup`

```text
remember setup [--self-hosted] [--api-url URL] [--api-key KEY] [--mcp-url URL]
               [--agent {cursor,claude,codex,agy,all}] [--dir DIR] [--dry-run]
```

<Cloud>

```text
remember setup --cloud [--issuer URL] [--headless]
               [--agent {cursor,claude,codex,agy,all}] [--dir DIR] [--dry-run]
```

</Cloud>

Writes each coding agent's MCP entry for Remember.

| Flag | Default | Meaning |
|---|---|---|
| `--self-hosted` | | Configure for an engine at `--api-url`, default `http://127.0.0.1:8000`. |
| `--api-url` | none | The engine address. It implies `--self-hosted` and is written into stdio entries as `REMEMBER_API_URL`. |
| `--api-key` | none | With `--self-hosted`: the engine's key, stored in the [credential file](#credential-file) and never written into agent configuration. |
| `--mcp-url` | none | The URL of your own `remember mcp --transport http` server. It implies `--self-hosted`. Agents that accept a URL entry connect to it; the others get a stdio entry. |
| `--agent` | `all` | Which agent to configure. `agy` is Antigravity; `claude` means Claude Code and Claude Desktop. |
| `--dir` | current directory | The project directory for project-level configuration. |
| `--dry-run` | off | Print the entries it would write; write nothing. |

<Cloud>

| Flag | Default | Meaning |
|---|---|---|
| `--cloud` | | Configure for remember.dev, or for the issuer given with `--issuer`. |
| `--issuer` | `REMEMBER_ISSUER`, else `https://remember.dev` | The key issuer to use. |
| `--headless` | on when `CI` is set | For machines without a browser: agents send the key from `REMEMBER_API_KEY` instead of signing in. |

`--cloud` asks the issuer for its MCP endpoint (`remember_mcp_endpoint` in
its metadata) and points each agent at it. With no stored key and no
`REMEMBER_API_KEY`, it runs [`remember login`](#remember-login) first,
except with `--headless` or `--dry-run`. With `--json`, setup directs the caller
to run login separately when a key is needed. Only a key minted by the selected
issuer counts: a stored key from elsewhere (or a self-hosted entry) is
replaced by that login, and a `REMEMBER_API_KEY` from elsewhere is refused. It refuses `--api-key`,
`--api-url` and `--mcp-url`: a remember.dev key comes from `remember login`
or `REMEMBER_API_KEY`. With neither `--cloud` nor a self-hosted flag, on an
interactive terminal, the command asks which backend to use; remember.dev
is the default answer. When standard input is not a terminal, it chooses
`--cloud`.

</Cloud>

What it does, in order:

1. Finds the launcher. It prefers an installed `remember` binary; when that
   binary lives in a virtual environment or a cache, or when there is none,
   it uses `uvx remember mcp`. Paths are resolved to absolute paths so an
   editor started from a desktop launcher finds them. With neither
   `remember` nor `uvx` on `PATH` it exits with status 1.
2. Chooses the agents. With `--agent all` it configures what it finds:
   Cursor if `.cursor/` exists in the directory, Antigravity if `.agents/`
   exists, Codex if `.codex/` exists or `codex` is installed, Claude Code if
   `claude` is on `PATH`, Claude Desktop if its configuration file or
   directory exists (or, on macOS, the app is installed). If it finds none,
   it configures Cursor and Antigravity.
3. For a self-hosted engine, stores the engine address and key in the
   credential file (see the warning below).
4. Writes one entry per agent. For a self-hosted engine the entry starts
   `remember mcp` with `REMEMBER_API_URL`. With `--mcp-url`, Cursor, Claude
   Code and Codex get a URL entry instead; Claude Desktop and Antigravity
   keep the stdio entry. A key, if any, is never written: a URL entry refers
   to the `REMEMBER_API_KEY` variable, which you set in the agent's
   environment.<Cloud> For remember.dev, Cursor, Claude Code and Codex get the
   endpoint URL and sign you in through the browser (for Codex, run
   `codex mcp login remember` once, as the command prints), and the other agents
   start `remember mcp` as a bridge to that endpoint. With `--headless`,
   Cursor and Codex send `REMEMBER_API_KEY` as the bearer token, and Claude
   Code gets the bridge.</Cloud>

Claude Code and Codex count as accepting URL entries only when their
installed command line supports them: `claude mcp add --help` must list
`--transport`, and `codex mcp add --help` must list
`--bearer-token-env-var`. Otherwise they get the stdio entry, which works
everywhere.

The exact files and their content are listed in
[MCP tools: configuration that `remember setup` writes](/docs/reference/mcp#configuration-that-remember-setup-writes).

<Callout type="warning">

`remember setup --self-hosted` replaces the credential file with the engine's
address and the key from `--api-key` (or no key). Afterwards every command
talks to that engine.<Cloud> When a remember.dev key is stored, the command
refuses; run `remember logout` first.</Cloud>

</Callout>

Existing configuration files must be valid JSON or TOML and must not be
symbolic links; otherwise that agent is not configured and the command exits with status 1. A failure in
one agent does not stop the others. Running the command again with the same
flags leaves the files unchanged.

```bash
remember setup --self-hosted --agent cursor --dry-run
```

## Account commands

### `remember login`

```text
remember login [--issuer URL]
```

Signs you in with a device code. The command prints a link and a short code;
you open the link, sign in to remember.dev, check that the code matches, and
choose which projects and permissions the key gets. The command waits for
your approval, then stores one API key in the
[credential file](#credential-file). The key is never printed.

The issuer is `--issuer`, else `REMEMBER_ISSUER`, else
`https://remember.dev`. The command reads the issuer's OAuth metadata at
`/.well-known/oauth-authorization-server` and runs the standard device
authorization grant (RFC 8628) against the endpoints it names.

```bash
remember login
```

Behaviour worth knowing:

- Waiting honours the server's pace: it slows down when asked, respects
  `Retry-After`, and never waits more than 30 seconds between checks.
- When you sign in again, the old key is revoked only after the new one is
  safely stored. The old key is first recorded in `pending-revocation.json`;
  if the command is interrupted, or the revocation cannot be confirmed, the
  next `remember` command finishes the job. A key that was never replaced is
  simply forgotten from that record, not revoked.
- The browser step has a time limit set by the server. When it runs out, or
  you deny the request, the command exits with status 1 and the stored key
  is unchanged. Ctrl-C exits with status 130 and writes nothing.

### `remember logout`

```text
remember logout
```

Revokes the stored key at remember.dev (RFC 7009) and deletes the credential
file. A key remember.dev no longer knows counts as revoked. If the revocation
is not confirmed, the file is kept and the command exits with status 1. With
no credential file it does nothing and exits 0. A stored self-hosted address
and key are simply deleted.

### `remember whoami`

```text
remember whoami
```

Prints what the stored key says about itself: the issuer, key id, expiry,
projects and permissions, and your default project. It never calls a
deployment. When the key has the `account:read` permission, it also prints
remember.dev's account view of the key. Exit status 1 when you are not
signed in.

### `remember switch`

```text
remember switch PROJECT
```

Makes `PROJECT` (an id or a name) the default project for the stored key.
It asks remember.dev once to check that the key covers the project, then
stores the project's id. No new key is created. Exit status 1 when the key
does not cover the project.

### `remember projects`

| Command | Result |
|---|---|
| `remember projects list` | Covered projects you can access, with project slot usage and the `is_owner` flag. |
| `remember projects show PROJECT_ID` | One project's details, including its monthly cap, activation state and deployment. |
| `remember projects create --name NAME [--monthly-cap CREDITS] [--idempotency-key KEY]` | The new project ID and its activation payment outcome. Omit the cap for no project limit. |
| `remember projects set-cap PROJECT_ID (--monthly-cap CREDITS \| --clear)` | The project with its new cap or with the cap cleared. |
| `remember projects activate PROJECT_ID [--idempotency-key KEY]` | The activation payment outcome for an unpaid project. |

Use `account:read` for `list` and `show`. Writes require an organisation
owner's key with `account:manage`. The key must cover an existing project
to change its cap or activate it. Pass credit amounts as decimals
such as `25.00`.

`create` and `activate` use the organisation's credit balance when it covers
activation, or charge its saved card. The command reports the payment method
and remember.dev starts provisioning immediately. If the organisation has
neither enough credits nor a saved card, the command prints a Checkout URL
for a person to complete payment. Both outcomes exit 0.

With `--json`, both print the issuer's response. It includes `project`,
`payment` (`credits`, `saved_card` or `checkout`), and
`requires_human_action`. Only `checkout` payments set that flag to `true`
and provide a payment URL in `checkout.url`. The `checkout` field may be
null or omitted for automatic payments.

Use the same `--idempotency-key` to retry the same request. Each invocation
without it generates a fresh key. When `activate` opens a new Checkout,
it replaces the earlier unpaid link.

An organisation owner controls project creation and cap changes in
**Settings → Agent permissions**. Creating with a cap requires both
switches. If a switch blocks the request, the command exits 1 with
`agent_permission_disabled`. The JSON error's `agent_action` includes the
issuer's instruction and Settings URL.

### `remember keys`

```text
remember keys list
remember keys create --name NAME [--permission SCOPE]... [--project PROJECT_ID]...
remember keys create --name NAME --all-projects
remember keys revoke KEY_ID
```

All three commands require `account:manage`. List shows key metadata. A
member sees their own keys and an owner sees the organisation's keys.

metadata and the secret in `key`. Capture it at creation to use it later.

`projects` and `keys` use the credential from `remember login` by default.
Each subcommand also accepts `--api-key`, ahead of `REMEMBER_API_KEY` and the

## Credential file

`remember setup --self-hosted` stores the engine address and key in
`credentials.json`<Cloud>, and `remember login` stores your remember.dev key
there</Cloud>. The CLI and the Python SDK both read it, after flags (or
arguments) and environment variables.

Location, first match wins:

1. `REMEMBER_CONFIG_DIR`
2. `$XDG_CONFIG_HOME/remember/`
3. `~/.config/remember/`

Protection:

- The directory is created with mode `0700` and the file with mode `0600`.
  The file is written to a temporary name, synced and renamed, so a crash
  leaves either the old file or the new one.
- The CLI refuses to read a file that is a symbolic link or that group or
  other users can read, and exits with status 1. Fix it with
  `chmod 600 ~/.config/remember/credentials.json`.
- Commands that change the file take a lock (`.lock` in the same directory).

Format, version 2, for a self-hosted engine:

```json
{
  "version": 2,
  "api_url": "http://127.0.0.1:8000",
  "key": "<the engine's key, or null>",
  "issuer": null,
  "key_id": null,
  "expires_at": null,
  "default_project": null
}
```

<Cloud>

After `remember login`:

```json
{
  "version": 2,
  "issuer": "https://remember.dev",
  "key": "rmb_…",
  "key_id": "…",
  "expires_at": "2027-09-23T10:00:00+00:00",
  "default_project": null,
  "api_url": null
}
```

Next to it, `pending-revocation.json` lists replaced keys whose revocation is
not confirmed yet (at most 20). Every `remember` command retries them.

A file in any other shape is refused. `remember setup --self-hosted` replaces
it<Cloud>, and so does `remember login`</Cloud>.

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `REMEMBER_API_URL` | memory commands | Deployment address. |
| `REMEMBER_API_KEY` | memory commands | API key, ahead of the credential file. |
| `REMEMBER_PROJECT` | memory commands | Project id or name for a key that covers several projects. |
| `REMEMBER_CONFIG_DIR` | all | Credential file directory. |
| `XDG_CONFIG_HOME` | all | Base for the default credential directory. |
| `REMEMBERSTACK_INTERNAL_OPS`, `REMEMBER_INTERNAL_OPS` | `ops` | Enables `remember ops`. The engine image sets it. |
| `REMEMBERSTACK_MCP_INGEST_ROOTS`, `REMEMBERSTACK_MCP_PATH_READ_MAX_BYTES` | `mcp` | Path ingest; see [MCP tools](/docs/reference/mcp#ingest-from-a-path). |
| `APPDATA` (Windows), `XDG_CONFIG_HOME` (Linux) | `setup`, `doctor` | Where Claude Desktop's configuration lives. |

<Cloud>

For remember.dev:

| Variable | Used by | Meaning |
|---|---|---|
| `REMEMBER_ISSUER` | `login` | The key issuer; default `https://remember.dev`. |
| `REMEMBER_MCP_URL` | `mcp` | A remote MCP endpoint to relay to; see [`remember mcp`](#remember-mcp). |

</Cloud>

Names are not case-sensitive. All client variables are in
[Configuration variables](/docs/reference/configuration).
