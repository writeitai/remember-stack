# TypeScript SDK

Pagination follows the shared [Pagination and truncation](/docs/reference/http-api#pagination-and-truncation) contract (D154).

<AppliesTo products={["remember.dev", "self-hosted"]} />

`@rememberdev/client` is the asynchronous Node.js memory client. It stores
and searches documents, queries facts and sources, reads graphs, checks pipeline
readiness, and includes methods for optional deployment-side connector configuration. It supports
Node.js 22 or newer, ESM and CommonJS. Use it in an application backend.

## Build and install

The package is available as source in the RememberStack repository. It has not
been published to npm. Build a local tarball:

```bash
git clone https://github.com/writeitai/remember-stack.git
cd remember-stack
uv sync --group dev
cd packages/typescript-client
npm ci
npm run build
npm pack
```

In your application, install the actual tarball that command produces:

```bash
npm install /absolute/path/rememberdev-client-0.1.0.tgz
```

TypeScript consumers need their usual Node types installed (`@types/node`).
The tarball exports the client and its types from `@rememberdev/client`; it has
no command-line executable or MCP server.

## Connecting

```ts
import { Client } from '@rememberdev/client';

const client = new Client({
  apiKey: process.env.REMEMBER_API_KEY,
  baseUrl: 'http://127.0.0.1:8000',
  timeoutMs: 300_000,
});
try {
  const info = await client.deploymentBuildInfo();
  const receipt = await client.ingestFile({
    filePath: '/sources/note.md',
    sourceKind: 'feeder',
    sourceRef: 'sources/note',
  });
  await client.waitForReadiness({ versionIds: [receipt.version_id] });
  const result = await client.factsContext({ query: 'What changed?' });
  console.log(info.build_revision, result.grain);
} finally {
  client.close();
}
```

`Client`, `MemoryClient`, and the `RememberClient` alias share the memory methods.
`Client.fromEnv(overrides)` uses the ordinary constructor's precedence;
`Client.ingestFile` is a file-path convenience, and `client.account` exposes
`get`, `whoami` and named project and key methods for a signed key's issuer
account API. Account access requires an endpoint advertised by that issuer.

Explicit `apiKey`, `baseUrl`, and `project` take precedence over
REMEMBER_API_KEY, REMEMBER_API_URL and REMEMBER_PROJECT, then the existing
version-2 credential file. `resolveConnection` additionally accepts `issuer`
and `mcpUrl` with REMEMBER_ISSUER/REMEMBER_MCP_URL precedence. Empty environment
connection values are unset. Empty configuration-directory values retain Python's
current-directory behavior. Bare keys and Bearer-prefixed keys are accepted.

Signed-key claims are decoded for routing only; the server verifies signatures.
The issuer supplies secure metadata and a covered project's engine URL. The
first project id stays pinned while deployment mappings refresh after ten
minutes or apparent movement. Without a signed key or configured URL, the
self-hosted default is `http://127.0.0.1:8000`.

The shared file is REMEMBER_CONFIG_DIR/credentials.json, otherwise
XDG_CONFIG_HOME/remember/credentials.json, otherwise ~/.config/remember/credentials.json.
Only required precedence fallthrough reads it. Explicit key and URL settings
bypass a stale file. POSIX reads refuse symlinks, nonregular files and files
readable by other users; Windows refuses automatic file reads. A file-loaded
key is sent only to its recorded, issuer or resolved deployment origin.
`SecretString`, `StoredCredentials` and `Connection` redact credential display;
`getSecretValue()` and `connection.authorization` deliberately access a secret.

Connector-management methods require an engine composition that serves those
optional routes. None of the released or candidate profiles checked by this PR
serves them; calling them there returns an explicit unsupported HTTP error.

### Ingest and readiness

`ingest` accepts `content: Uint8Array`, or `source` as bytes or a file path.
Bytes require `filename`. File MIME is inferred from the real path before a
filename override; explicit `mime` wins. Lineage `sourceKind`/`sourceRef` must
be supplied together. `sourceModifiedAt`, `sourceVersionRef` and living mode
require that pair; `sourcePath` records upstream location metadata. `versionKey`
is the immutable caller name for an edition. `effectiveFrom` and optional
`effectiveUntil` declare a half-open UTC period and require a snapshot lineage;
use `setEffectivePeriods` to replace declarations or `clearEffectiveTime` to
leave declared effective time. An empty period set retracts that version's
periods while retaining the document's declared effective-time mode.
`allowForgotten: true` adds back content of a forgotten document for that one
call (see [Adding forgotten content back](/docs/reference/http-api/ingest#adding-forgotten-content-back));
without it such content is refused with `MemoryApiError` code
`document_forgotten`, and while that forget is still erasing with
`forget_not_complete`.

`forgetDocument({docId})` erases a document for good and returns its `Forget`
record; `listForgets()` and `getForget({forgetId})` follow the erasure. See
[`POST /documents/{doc_id}/forget`](/docs/reference/http-api/ingest#post-documentsdoc_idforget).

Readiness polling starts immediately, including after `created: false` receipts.
Defaults are `timeoutMs: 1_800_000`, `pollIntervalMs: 15_000`, and `requireP3: false`.
When requested, `p3` checks the nullable publication marker of each served
version. An unrelated successful publication cannot satisfy it. A ready
single-version request exposes its export digest as `version`; aggregate
version and publication timestamps are null.

Document search's `p3_path` is relative to the corpus root and non-null only
for a served selected version with a matching marker. Raw-only, unpublished,
updating, failed and historical results carry `null`; `served_version` describes
currency independently. Re-resolve with `filters.doc_ids` after type/topic/title
moves. Only the suffix is stable; [offline lookup](/docs/self-hosting/filesystem-views#layout)
also works.
A `failed` stage has a retry pending; polling continues. A `dead_letter` stage
stops with PipelineDeadLettered and the full report. The readiness deadline
covers routing, HTTP and polling waits, retaining the last validated report.

### Tags

`listTags({ query })` lists the registered tags, ordered by name ignoring
letter case. `createTag({ name, description })` registers one; the name is
NFC-normalized and checked before sending (1 to 128 characters, no
whitespace or control characters). `updateTag({ tag, name, description })`
and `deleteTag({ tag })` take a tag name or `tag_id`; a name is first looked
up with `listTags`, and one that is not registered raises `UnknownTag` with
status 404. `updateDocumentTags({ docId, add, remove })` or
`updateDocumentTags({ docId, set })` changes one document's tags in one step
(`set: []` removes every tag) and returns its tags afterwards. `ingest`
takes `tags`, an array of tag names or ids added to the document.
`searchDocuments` takes `filters.tags`, and `searchClaims`, `searchChunks`,
`factsContext`, `claimsAndSourcesContext` and `combinedContext` take
`documents.tags`: `{ all: [...], any: [...], none: [...] }` of tag
names or ids; a tag that is not registered is refused with `unknown_tag`.
On `factsContext`, contradicting evidence from non-matching documents stays
in the answer, marked `in_documents_filter: false`; see
[The documents filter](/docs/reference/assured-operations#the-documents-filter).
What tags are: [Tag documents](/docs/guides/tag-documents).

### Archive

`archiveDocument({ docId })` archives one document: the memory stops
believing it, and it stays readable as history. It returns a
`DocumentArchive`; archiving an archived document returns the same
`archived_at` with zero counts. `unarchiveDocument({ docId })` undoes the
archive exactly and returns a `DocumentUnarchive`. Both need a `write`
credential; an unknown `docId` raises MemoryApiError with statusCode 404
and detail `document_not_found`. Archived documents are left out of reads unless you
ask: `listDocuments({ includeArchived: true })`,
`filters.include_archived` on `searchDocuments`, and
`documents.include_archived` on `searchClaims`, `searchChunks` and the
context operations. See
[`POST /documents/{doc_id}/archive`](/docs/reference/http-api/ingest#post-documentsdoc_idarchive).

### Version history and references

`searchClaims`, `searchChunks`, `searchDocuments` and `claimsAndSourcesContext`
accept a `time` scope. A time-scoped claims/chunks search uses POST; the ordinary
unfiltered search retains GET. Nested scopes use the engine's wire names:
`{ mode: 'at', at: '2026-01-01T00:00:00Z' }` or
`{ mode: 'overlap', from: '2026-01-01T00:00:00Z', to: '2026-07-01T00:00:00Z' }`.
ReadTime instants retain explicit offsets; ingest effective times require UTC.

`sectionHistory({ docId, sectionKey })` defaults to the complete history scope.
`documentReferences` accepts exactly one `chunkId` or `docId`, with `sectionKey`
only for a document. Prepared request variants accept snake_case DTO fields.
`setReferences({ docId, versionId, references })` replaces the complete supplied
reference set as NDJSON; an empty array clears it. `referenceGenerations` reads
its pending/active/rejected/superseded status. None of these writes is replayed.

## Transport and errors

Ordinary requests default to `timeoutMs: 300_000`. Caller cancellation raises
AbortError with the signal reason; an HTTP deadline raises RequestTimeoutError;
readiness expiry raises TimeoutError with its last report. These are distinct.

Writes are never automatically replayed. A classified read can replay once
only after issuer resolution changes its deployment URL. Network failure/421
on a write can refresh the mapping for a later operation, while the original
error is surfaced. Timeouts and caller cancellation do not refresh or replay.

The default adapter uses Node HTTP/HTTPS with per-client agents, no automatic
redirects/retries and one transmission per invocation. Engine redirects are
refused. Issuer/account redirects allow at most three hops on the same origin
and preserve their method. Discovered URLs require HTTPS except loopback HTTP.
Account paths reject absolute URLs and traversal, including encoded traversal.

A caller-owned `client: HttpClient` takes relative paths and its own base URL/headers;
it cannot be combined with apiKey/baseUrl/project/transport/agents settings.
`transport: HttpTransport` takes absolute URLs and retains SDK routing/headers.
Alternatively borrow `agents: {http?, https?}` for the default single-send adapter.
These modes are mutually exclusive. Both injected adapters must send once,
honor AbortSignal and return redirects unfollowed. Fetch-standard adapters are
unsuitable: they resend reusable requests after HTTP 421.

SDK-owned agents ignore environment proxies, including NODE_USE_ENV_PROXY.
Node 22.0 lacks proxyEnv, so explicit injection keeps selection deterministic.
Node TLS defaults and NODE_EXTRA_CA_CERTS apply; a caller-owned HTTPS agent can
supply ca material, and an operator-configured http.Agent subclass or conforming
transport can handle proxies. SSL_CERT_FILE is not read. Idle sockets retire
after four seconds; 421 connections are retired before they can serve queued
requests. An active response may take longer than four seconds.

`timeoutMs` is a total operation deadline including routing/upload/body reads,
and bounds injected calls too. Raise the 30-second default for slow or large
uploads (50 MB at 5 Mbit/s takes about 80 seconds). Timeouts can leave an unknown
write outcome and never authorize replay. Close destroys only SDK-owned engine
agents and cancels this client's waiters/requests; borrowed resources and shared
discovery remain available. The closed facade refuses later calls with AbortError.
Pending lookups share only identical transport objects; completed successes
may be reused across transports.

MemoryApiError contains statusCode/detail/code, response when available, and
optional retryable/requestId diagnostics. RateLimited also has retryAfter in
seconds. Hints are carried for callers; the client does not interpret them as
permission to retry writes. ProjectResolutionError, StoredKeyRefused,
AccountApiUnavailable, IssuerError, NumericPrecisionError and RequestTimeoutError
extend MemoryApiError, as does LayerUnavailable (status 409, code
`layer_unavailable`, with the missing `layer`), and UnknownTag (code
`unknown_tag`, status 422 or 404, with every unregistered tag in `tags`). The
tag refusals `conflict` and `tag_limit_exceeded` keep their code on
MemoryApiError. InputValidationError and CredentialError are TypeErrors.
PipelineDeadLettered, TimeoutError, ConnectorNotFoundError and AbortError are
outside MemoryApiError.

The optional `/connectors` routes are not part of the standard exported engine
profile. They require a deployment composing connector ports; otherwise the
client propagates that deployment's refusal.

## Tool support and separate executable packages

The base package exports `ToolDefinition`, `Permission`, `memoryTools`, `tool`,
`renderToolsList`, every catalogue name constant, and `PROJECT_ARGUMENT`.
Definitions carry routes, versions, permissions, schemas and annotations.
`OPEN_QUERY_TOOL_NAMES`, `OPERATION_TOOL_NAMES` and `MEMORY_WRITE_TOOL_NAMES`
identify the source-defined groups. Individual constants include
INGEST_TOOL_NAME, PIPELINE_READINESS_TOOL_NAME, ARCHIVE_DOCUMENT_TOOL_NAME,
UNARCHIVE_DOCUMENT_TOOL_NAME, SEARCH_DOCUMENTS_TOOL_NAME and

`TAG_WRITE_TOOL_NAMES` and `TAG_TOOL_NAMES` group the five tag tools.

`validateArguments` checks every memory tool and returns parsed arguments.
`validateSavedQueryIdentifier` checks saved-query names. `ToolError`,
`ToolArgumentError`, `invalidArguments`, `mapError` and `errorResult` supply a
common structured failure shape. `ToolError.asDict()` renders its envelope.
ToolDefinition exposes `mutates` and `annotations`. No MCP host settings are loaded. Text/base64
bodies are resolved locally; a path is refused unless a caller supplies a
`PathBodyResolver`. That separate host owns root containment, symlink checks,
regular-file checks, size limits and MIME policy.

Credential/routing helpers include `configDir`, `credentialsPath`,
`loadCredentials`, `environmentIssuer`, `normalizeKey`, `resolveProject` and
`clearHostCache`. Issuer helpers include `KeyClaims`, `IssuerMetadata`,
`isLoopback`, `requireSecureUrl`, `origin`, `sameOrigin`, `normalizeIssuer`,
`metadataUrl`, `sendSameOrigin`, `fetchIssuerMetadata` and `clearMetadataCache`.
`NormalizedOrigin` describes canonical origin comparison. `version` is this npm
package version; `pythonCompatibility` identifies its Python source/baseline.
`signedKeyClaims` decodes routing claims without verification. KeyClaims supplies
`covers`/`expiresAt`; IssuerMetadata supplies checked `endpoint` lookup.

CLI/MCP hosts and connector adapter packages have separate design, execution,
security and release contracts. This client exports their reusable client-side
contracts, not backend protocols or a server implementation.

## Drift checks

`npm run check:generated` re-exports the engine API offline and compares
committed schemas, source inventories and pinned type generation without
changing git. `npm run check:parity` executes current Python methods and
compares source-recorded requests, defaults, results, malformed responses,
every catalogue validator and structured error mappings. `npm test` executes
those shared fixtures plus actual HTTP failure/cancellation scenarios.

`npm run check:package` installs the tarball in independent ESM/CommonJS
consumers and typechecks imports. CI runs Linux/Windows and supported Node
versions, plus released/candidate live-engine profiles. A new Python method,
schema field or semantic validator requires reviewed client/fixture updates.
Provider repositories check their issuer schemas against the public provider
contract; private cloud DTOs are not copied into the client.

Timeouts and poll intervals must be finite, greater than zero and at most
2,147,483,647 milliseconds (Node's timer limit). Invalid values raise
`InputValidationError` before HTTP. Use `pipelineReadiness` for a single poll.
Connection and configuration-directory environment names are case-insensitive, matching Python. On Windows,
argument or environment signed keys without a URL use issuer routing without
reading an unavailable credential file. Unsigned keys without a URL refuse a
present file and use the localhost default if the file is absent.

Timestamp strings for ingest, graph reads, effective periods and date filters
require `Z` or a numeric UTC offset. The SDK converts them to UTC and
preserves microsecond precision. For example, `2026-11-20T14:03:11+01:00`
becomes `2026-11-20T13:03:11Z`. Top-level options such as
`sourceModifiedAt` and `validAt` also accept a JavaScript `Date`.
The SDK raises `InputValidationError` before sending a request for a typed
timestamp string without an offset.
