Each replay matched every column of `chunks`, `chunk_search`, and
`selection_results` after aligning the creation clocks and IDs to the
checkpoint. The 272 embedding requests matched the pinned plain `nebius`
routing, dimensions, and ordered input hashes. The checker re-ran Selection
from the 2,229 persisted replies, compared its output, cards, and truncation,
and recomputed each D122 producer order and input stamp. It observed zero
splits and zero live provider calls.

Run the checker on each local restore. For Full-v45, start PostgreSQL 19rc1
and SeaweedFS 4.44 from the backup, export the artifacts using their original
object keys, and migrate the local database before the replay clones it.

```bash
REMEMBERSTACK_DATABASE_URL="$LOCAL_CHECKPOINT_DB" uv run alembic upgrade head
uv run python -m benchmarks.d162_replay \
  --database-url "$LOCAL_CHECKPOINT_DB" --artifacts "$FROZEN_ARTIFACTS" \
  --routing locomo-v45 --checkpoint-only
```

The Full-v45 backups contain the stored vectors and Selection payloads.
Original extraction wire requests and Claimify replies are unavailable in
these backups. The 9,687 historical claim rows and occurrence links were
inventoried, with Claimify grounding and occurrence-span equality still
unverified. The review's persisted-output check is implemented in strict mode
(`--wire-tape` in place of `--checkpoint-only`). It fails on an unused or
different ordered request, an output row change, or a split. The PostgreSQL
[recorded-wire test](../src/tests/benchmarks/test_d162_replay_pg.py) exercised
strict mode with a frozen local response that produced a claim and its
occurrence. Both full rows, including the evidence spans, matched.
