# Completing the engine storage-capture consumer

**Status: non-binding analysis.** This records the decision boundary for the
engine consumer of genuine provider storage evidence. It is not an implemented
collector, accepted financial mapping, populated measurement profile or
permission to enable managed storage charging.

Project's raw, artifacts, corpus and forget filesystems, not a new filesystem

lowercase unpadded base32; hashing frames its decoded sixteen bytes.
Organisation and engine UUIDs keep their separate UUID32 representation.
No working public capture caller or manifest store follows from acceptance.

Private provider components are being assembled at fsit draft
[#575](https://github.com/writeitai/fsit/pull/575), source

## Narrow contract to settle

1. The engine owns a complete capture manifest: exact deployment/store
   bindings, requested instant and clock bracket, schema/classification
   identities, native physical component evidence, provider manifest identity,
   classified references and exact independent storage evidence membership.
   A maximum processing sequence cannot stand in for that set.
2. The provider adapter validates one D63 result and every page under the same
   exact four-set request. It matches opaque provider path identities to the
   engine's known keys in both directions. Unknown entries, missing pages,
   unresolved aliases or changed ownership cannot silently become zero bytes.
   Provider chunk/part/accounting counters retain their own observation bracket
   and never become an all-resource physical byte count at the cut.
3. The short engine physical/mutation guard and the provider witness cover the
   same possible values of the requested instant. The original bounded engine
   view survives paged extraction after those short guards release. No lock is
   held while waiting for delivery, customer funding or acknowledgement.
4. Customer quantity is separate from substrate evidence and resource
   obligation. The existing allocated PostgreSQL quantity cannot become a
   row-length estimate, nor can mixed-purpose physical pages be assigned by
   a name prefix or guessed fraction. The profile must state its complete
   purpose mapping and qualified physical mechanics.
5. Capture identity and acknowledgement name the exact immutable manifest and
   membership. A failed historic cut stays missing; a forward cut cannot
   backdate current bytes. Current-terms operator settlement must replace its
   old processing-watermark eligibility path atomically with the selected
   independent storage contract, with no compatibility fallback.

The existing proposal records independent intent/authority and disposition
shapes and the cost/enforcement vectors. This leaf must select the consumer
contract, explain its source-compatible operator mapping, and reconcile
affected binding designs. It must not hide an unchosen business policy inside
a typed interface. Measured allocated relations are not a populated
maintenance proof; a P3 serving role is not automatically an additional
physical copy; a failed processing outcome does not prove retained resources
disappeared.

## Work and limits

The implementation-facing design is being completed alongside the provider's
typed materialiser boundary. It will choose no new price, arbitrary upload/
entry/churn cap, free interval, minimum charge, cross-meter subsidy or release
coordinator. If a qualified current workload exposes a positive cost with no
permitted funding source, that exact vector goes to an explicit operator
decision; a guessed number is not evidence.

This checkpoint changes analysis and navigation only. No implementation,
schema, credential, live resource, public documentation, paid reuse input or
customer-facing claim has changed.
