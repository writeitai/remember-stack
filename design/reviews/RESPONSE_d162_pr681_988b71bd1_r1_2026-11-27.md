# Response to PR #681 follow-up design review, round 1

Review of `988b71bd1`. All three findings accepted.

## P1

- **Delivery and completion for one packing grid.** The ledger key omits
  the payload, and the base embed component version omits packing parameters.
  E2 uses its configured generation and the layer helper independently looks
  up the latest grid. CHUNK and `embed_chunk` now carry the representation
  and full generation under a key bound to that grid. The existing key stays
  with its grid. Additional grids include the pair in the component version.
  Claims admission, Selection, Claimify and readiness use the same binding,
  including deferred admission and empty completion. The design specifies
  tests for parameter-only repacking and recovering an older failed grid
  with a newer grid present.

- **Effective dates in private recovery.** The D140 migration leaves
  the origin date and date-free key unset on pre-D140 chunks. E2 uses the
  version's source modification date or publication date for those rows.
  Recovery stamps that effective date on rebuilt rows. The rebuilt
  Selection key, E2 header and fresh `asserted_at` use the same value.
  A genuinely undated row keeps an unknown date. The specified regression
  covers both version-date fields, unknown dates, and an otherwise identical
  undated occurrence whose key must differ from the recovered dated one.

## P2

- **Legacy `context_prefix` in the retrieval envelope.** The reader returns
  the D80 `location_header` when present and nonempty, with the stored
  legacy `context_prefix` as fallback. The envelope contract now states
  both cases.
