| Finding | Fix | Test (result on `3419f295`) |

| **P1-1:** ordinary apply can stamp a new period basis onto a decision made against old periods | Period writers do not take the period fence, so an application no longer trusts the fence for this. Before writing, it reads which candidate facts already have a stale basis, and the in-force periods of every claim its bases can cover: the shown claims and **all** evidence of its candidate facts, not only the 100 claims shown. It records a basis only for changed facts that were current. After recording, it re-reads those periods; any change rolls the whole application back for a fresh attempt. A fact that was already stale keeps its stale basis, so the review its change queued still happens. In a deployment that never declared a period, nothing is read or recorded (one existence probe, as before). | `test_ordinary_apply_never_certifies_periods_its_decision_did_not_see`: a correction to a **shown** claim commits between validation and recording (fails: DID NOT RAISE). `test_ordinary_apply_never_certifies_evidence_periods_it_was_not_shown`: only the incoming undated claim is shown, and a correction to the supported fact's **unshown** dated evidence commits in the same gap. The apply rolls back, and the retry leaves the basis stale, so the correction's fan-out queues the review (fails: DID NOT RAISE). |
| **P1-2 (owner invariant):** production entity-profile repair still re-embeds | **Decision:** entity profiles keep displaying fact windows. That is D118 presentation, and their embedding input policy is unchanged. A profile is re-embedded **only when its rendered text changed**. A review's repair no longer clears the endpoint entities' vectors (`invalidate_profiles=False`). The production `EntityProfileRefresher` already embeds only when the rendered input's hash differs from the attested one, so it calls the model only for a profile that shows the reviewed fact. No vector keeps a false attestation: the profile text and its hash change together. | `test_a_review_whose_window_leaves_profiles_unchanged_embeds_nothing`: eight better-supported facts fill the profile, the reviewed fact's window moves, and the production `LabelFactsHandler` + `EntityProfileRefresher` run the queued repair. It asserts zero embedding calls and an unchanged profile (fails: 2 == 1, because the cleared profile was re-embedded with identical text). The owner regression `test_periodised_new_version_reextracts_only_the_edit_and_a_period_change_none` now uses the **production refresher** with a pre-built profile. It asserts exactly one embedding call, for the profile whose displayed window changed ("…through 2025-06-30"), with zero fact, chunk or claim embeddings and no extraction. |
| **P1-3:** a transient provider failure leaves an unfinished claim that exhausts retries | A claim records its owner, the job's call key, which is stable across the job's retries. A failed inference releases the job's own claim. A job that resumes its own claim proceeds. Another job's live claim with no answer raises `ReviewDeferred`. The handler then returns a deferred copy of the job, due when that claim goes stale, so it neither pays twice nor spends its retries. The migration adds `claimed_by`. | `test_a_failed_inference_releases_its_claim_so_the_retry_succeeds` runs the real `Worker` and `WorkLedger`: one `RETRY_SCHEDULED`, no dead letter, the model is asked again, and the window is replaced. It fails there: the job's own claim blocks every retry ("another job is reviewing this fact window"), so the job retries twice and is then dead-lettered. `test_another_jobs_live_claim_defers_instead_of_paying_or_failing`: another owner's claim yields a deferred follow-up with `not_before` and no model call (fails: no `claimed_by` column on the old schema). |
| **P1-4:** an invalid cached citation poisons retries | Citations are checked against the supplied handles **before** an answer is stored. An answer citing anything else is never stored, the claim is released, and the retry asks again. | `test_an_answer_citing_an_unsupplied_claim_is_never_replayed`: `C999` and then a valid answer. Two model calls, and the window is replaced (fails: the stored answer replayed `C999`). |
