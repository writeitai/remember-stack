# Response to the D163 design review, round 3

Review of PR #682 at `e6bd378d9`. All findings accepted after checking the
deployed migrations, benchmark entry points and pinned LoCoMo evaluator.

| Finding | Resolution |
| --- | --- |
| P0 · Benchmark binding through the last checkpoint | BEAM builds a client for each question. LoCoMo's Codex MCP child resolves its own engine connection. The launcher holds the shared store lock, serves a frozen store from a private instance without setup or writers, and binds every reader to it until the final checkpoint and child exit. A synchronized test attempts replacement, migration and writes after admission and during answering. [BEAM client](../../benchmarks/rs_harness_beam/answer_agent.py#L692) · [MCP child](../../benchmarks/locomo/ablation.py#L1821) · [Store lock](../../benchmarks/locomo/sharding/store_backup.py#L247) · [Design](../../plan/designs/shared_retrieval_eligibility_design.md#benchmark-admission-and-lifetime) |
| P1 · Historical LoCoMo resume | The native command checks the prepared Git revision. Ablation checks the evaluator revision in its output fingerprint. The launcher verifies the store and serving build before dispatching the recorded evaluator, which runs its original checks on the existing checkpoint. Require successful resume of a historical partial checkpoint through both paths. [Native guard](../../benchmarks/locomo/runner.py#L1660) · [Ablation fingerprint](../../benchmarks/locomo/ablation.py#L1019) · [Design](../../plan/designs/shared_retrieval_eligibility_design.md#benchmark-admission-and-lifetime) |
| P1 · Full hydration work | Key the live claim join used by D54 counts and probe representative evidence from confirmed fact IDs. Reuse keyed occurrence and version lookups for scope, document matching and displayed coordinates. Keep exact per-stance counts, matching totals and representative order. Require executed plans and oracle comparisons for full hydration, including document filters, as unrelated claims and occurrences grow. The live claim view gets its own migration revision. [Live evidence join](../../src/rememberstack/spine/migrations/versions/p9_48_0069_shared_eligibility.py#L234) · [Evidence hydration](../../src/rememberstack/surfaces/query_engine.py#L6356) · [Design](../../plan/designs/shared_retrieval_eligibility_design.md#representative-evidence-and-document-filters) |
| P2 · Per-sample store pins | The shard prepares one run directory and changes stores between samples. Bind each sample to its deployment and verified restore digest as its scoring store is frozen. Require a two-sample test that accepts each correct restore and rejects the other's. [Shard store switch](../../benchmarks/locomo/sharding/run_shard.sh#L454) · [Design](../../plan/designs/shared_retrieval_eligibility_design.md#benchmark-admission-and-lifetime) |
| P2 · Model-free replay inputs | Tool records omit embedding vectors and may omit internal clocks. Replay uses the captured model inputs and vectors, applied read instants and SQL clocks with provider access disabled. A missing input fails the comparison. Where historical inputs are incomplete, qualify a separately identified fixture. [Tool record](../../benchmarks/locomo/model.py#L373) · [Embedding call](../../src/rememberstack/surfaces/query_engine.py#L4838) · [Design](../../plan/designs/shared_retrieval_eligibility_design.md#model-free-qualification-for-benchmark-adoption) |

[Schema](../../src/rememberstack/spine/migrations/versions/p0_02_0004_claims_facts_evidence.py#L25) · [D163](../../decisions.md#d163-drive-fact-eligibility-from-its-own-evidence) |
