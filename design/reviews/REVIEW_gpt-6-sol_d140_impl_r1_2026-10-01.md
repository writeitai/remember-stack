# D140 implementation review — PR #500, c57c723

Compared `origin/main...HEAD` against the binding D140 design and WP-ET.1–6 delivery plan. CI is green as reported. WP-ET.7 and WP-ET.8 are outside this PR.

## Deviations verdict

- **(a) Reject.** `src/rememberstack/surfaces/graph_queries.py:182` and `:297`: the evidence gate runs after the graph helper has applied its expansion and result budgets. A one-result page whose first path is out of force can omit a second eligible path; the shallow path also computes its continuation from the already-cut page, so marking the answer truncated does not let the caller recover the missing path. `:689` opens a separate connection, so traversal and eligibility can observe different database snapshots. **Fix:** expose a narrowly granted, deployment-bound evidence predicate to the graph role and apply it to edges inside the helper before expansion, ordering, offset and limit, in the traversal transaction. Test an excluded first path followed by an eligible one at `limit=1`, and a concurrent evidence change.
- **(b) Accept.** `plan/plans/effective_time_and_section_references.md:13` and `:22`: WP-ET.1 and WP-ET.6 require HTTP and SDK period/reference writes, plus MCP ingest periods and MCP *read* operations; they do not require MCP period mutation or supplied-reference tools. `website/src/app/docs/project/not-built-yet/page.mdx:49` states the shipped boundary. The read tools still need D136 catalogue parity, which this omission does not remove.

## P1

- `src/rememberstack/core/text_scope.py:247`: `fact_in_scope` returns true when there is **no** live supporting occurrence (`NOT EXISTS ... OR in_scope`). The binding §8.1 gate requires at least one in-scope supporting claim. A fact with only retired/deleted support, or no supporting claim, remains eligible in fact nomination and confirmation and can consume a top-k slot. **Fix:** remove the vacuous-success arm; require an in-scope supporting occurrence in both current and pinned-belief paths. Test a fact with no live supporting occurrence against every nomination channel and confirmation.
- `src/rememberstack/core/text_scope.py:220` and `src/rememberstack/spine/migrations/versions/p9_38_0059_d140_effective_time.py:1021`: the fact-support probes join `chunk_claims` to chunks and the selected version, but do not require the chunk's `representation_id` to be that version's current ready representation. After a D65 swap, an occurrence only in the old reading can make an otherwise unsupported fact pass the gate, including `memory_v1.fact_in_scope_support` at pinned belief. **Fix:** join the version/current representation and require matching coordinates in both predicates; test a representation swap that leaves an old occurrence behind.
- `src/rememberstack/spine/effective_time.py:337` and `src/rememberstack/spine/document_search.py:120`: ledger rows receive `clock_timestamp()` **before commit**, while page one pins `now()` as its belief instant. If a writer stamps a declaration, page one starts before that writer commits, and the writer commits before page two, page one sees the old state but page two includes the newly visible declaration because its stamp is earlier than the pinned belief. The existing correction-between-pages test starts after the first transaction has committed and cannot detect this interleaving. **Fix:** pin a commit-visible ledger snapshot/watermark (including retractions and mode events), rather than comparing pre-commit wall-clock stamps alone; add a two-session test with the writer held between stamp and commit while page one runs.
- `src/rememberstack/spine/document_references.py:1189`: `_SELECT_CHUNK` accepts any chunk of a non-deleted version, even an old representation or a version that is no longer ready. `_chunk_plan` then maps that chunk's `block_start` through the **current** structure generation (`:467`), which can return references of a different section. §3.3 permits chunk handles only from the version's current ready representation. **Fix:** require `v.status = 'ready'`, a ready current representation, and `c.representation_id = v.current_representation_id`; resolve the section from the accepted chunk's current-generation coordinate. Test an obsolete chunk ID after a representation swap and a processing version.
- `src/rememberstack/surfaces/query_engine.py:4602`: fact evidence is selected through `v_memory_fact_claim_live` and then `memory_v1.claims_live` (`:4633`), both of which require the claim's **origin** version to remain live. D140 §3.4/§8.1 requires evidence from an occurrence in the selected version even after the origin version is deleted. `test_claim_occurrence_survives_deletion_of_the_claims_origin_version` covers `search_claims`, not fact hydration. **Fix:** form the fact's eligible claim set from live, current-reading occurrences in selected versions and hydrate those occurrences; test `facts_context` with a reused supporting claim whose origin version is soft-deleted.
- `src/rememberstack/surfaces/query_engine.py:1539` and `src/rememberstack/spine/document_search.py:156`: `scope_pending` is probed only for returned claim/chunk documents (or explicit document IDs), and ranked document search probes only successful picks. When the only matching lineage has an in-force edition still processing, it is excluded before ranking, so the answer is empty with `scope_pending = null`—indistinguishable from no in-force match, contrary to §3.7's purpose. **Fix:** retain a bounded set of candidate lineages touched by nomination before readiness exclusion, then probe pending scope for those lineages without allowing pending rows into top-k. Add empty-result tests for unfiltered chunk/claim and ranked document searches.

## P2

- `src/rememberstack/spine/document_search.py:421`: the filter-only keyset order uses the newest **non-deleted** version at `as_of`. Soft-deleting that version between pages changes the lineage's walk key, so a lineage returned on page one can reappear later. §3.6 requires an order built from immutable values. **Fix:** derive the walk key from the newest version ingested by `as_of` regardless of later tombstoning, and apply liveness only while judging the candidate; test deletion between pages.
- `src/rememberstack/spine/document_search.py:891`: a filter-only cursor pins `believed_at`, but `_SCOPE_PENDING` reads the current `document_version_scope` projection (`:931`) rather than the ledger at that belief. A retroactive correction between pages can therefore change the pending signal while the page's selected editions remain pinned. **Fix:** for pinned pages derive pending status for examined lineages from belief-time intervals plus current readiness, as selection does; test correction and clear/redeclare between pages.
- `src/rememberstack/spine/migrations/versions/p9_38_0059_d140_effective_time.py:1166`: the downgrade guard ignores D140 section keys/hashes and `chunks.text_origin_at`/`reuse_identity_hash`. A deployment can write those after upgrade without a period, key or reference generation and then downgrade, silently dropping immutable text-origin data. **Fix:** refuse downgrade when those columns contain D140 data, or provide and test an explicit lossless conversion.
- `plan/plans/effective_time_and_section_references.md:75`: the required 1M-lineage/5M-version/50M-chunk scale measurement and 1,000-version projection rewrite measurement are absent. Green functional CI does not establish design §3.2's latency target. **Fix:** run and record the specified benchmark with baseline and scoped p95, plus projection rewrite timing, before approval.
