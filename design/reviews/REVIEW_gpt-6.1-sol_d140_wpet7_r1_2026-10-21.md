## P1

1. **The first periodised fact bypasses window adjudication and is permanently marked current.** `src/rememberstack/spine/fact_adjudication.py:866` (also `:730`). The empty-candidate shortcut always supplies `_sole_new_fact`, with no window decision. Creation therefore copies only the raw claim window, or leaves it unknown. The new code nevertheless records the complete current `period_basis`. For an undated claim saying “VAT is 15%” whose editions are in force during 2015–2023, no model ever considers those periods; the completion fan-out finds matching bases and skips the fact. A focused PostgreSQL probe produced `(NULL, NULL, unknown)`, a non-NULL basis, no fan-out, and review outcome `unchanged`. **Fix:** retain the shortcut for undated inputs, but perform semantic window adjudication for new facts with periodised evidence, including the JEV/new-fact path. Record the basis only after that decision. Test a single fact with no subsequent assertion to repair it.

2. **The fingerprint check does not serialize with period writers; stale windows can commit with no remaining review job.** `src/rememberstack/spine/fact_window_review.py:232` (also `src/rememberstack/spine/fact_adjudication.py:866`). `application_block` coordinates forget, identity and entity adjudication; the fact row lock does not block `set_effective_periods`, ingest declarations, or occurrence/projection changes. Those inputs can change after the final fingerprint read and before commit. Concrete reproduced interleaving: stored basis A; review prepares and rechecks B; a writer reverts periods to A and its fan-out sees stored A, so queues nothing; the review then commits B's window and basis. Ordinary apply additionally recomputes the basis after applying the answer, potentially certifying periods the answer never consumed. **Fix:** add a common period/occurrence fence, participated in by all relevant writers, covering final validation through commit, with a documented global lock order. Record the basis from the validated inputs. Add concurrent revert, declaration, representation-change and deletion tests; keep remote inference outside locks.

3. **Period declarations made through ingest never enqueue review.** `src/rememberstack/spine/effective_time.py:146` (missing corresponding hook in `declare_at_ingest_on`, `:252`). Only the standalone period API receives the new enqueue. `DocumentCatalog.ingest` also writes declarations, including on an identical-bytes D55 no-op. Its existing convert/reconcile work remains succeeded, so completion cannot rescue this case. Correcting `effective_until` on that already-processed version changes the periods but leaves existing fact windows untouched indefinitely. A focused execution of `declare_at_ingest_on` retracted/replaced the declaration while review-job count remained zero. **Fix:** enqueue transactionally from the ingest declaration writer whenever it changes a declaration; preserve its identical-declaration no-op. Test period correction and first declaration through identical-bytes ingest, with no extraction or embedding work.

4. **Returning to an earlier correction state strands projection repair.** `src/rememberstack/spine/fact_window_review.py:529`. Relabel work is keyed only by the input digest. A → B → A → B corrections can reproduce the same digest, including stored basis and previous window. The final replacement clears labels/vectors, but `enqueue_on` collides with the first B review's already-succeeded repair row. The probe produced repair-job totals/pending counts `(1,1)`, `(2,1)`, `(2,0)` across the three corrections. The final fact consequently has no new repair work. **Fix:** identify repair work by the committed review/adjudication receipt UUID and fact identity, reusing that receipt only for retries of the same application. Test the complete correction cycle after each previous repair succeeds.

5. **A period-only correction re-embeds unchanged fact text, violating the requested owner invariant.** `src/rememberstack/spine/fact_window_review.py:455` (also `:520`). Every accepted replacement clears the fact vector and embedding attestation and queues `LabelFactsHandler`, which calls the embedding provider again. This occurs even though relation prose and observation statements are unchanged. Running the production label handler on the replacement state embedded “VAT on books is 15%” again. Profile repair also invalidates entity vectors. The supplied reuse test chooses `keep`, avoiding this branch entirely. **Fix:** preserve reusable vectors when their actual embedding text and generation are unchanged; update window/projection metadata separately under the existing embedding policy. Ensure period-only work satisfies the stated no-re-embedding invariant, and exercise an actual replacement with fully populated embeddings and all resulting workers enabled.

6. **Fan-out and per-fact preparation are unbounded in memory and transaction size.** `src/rememberstack/spine/period_adjudication.py:350`, `src/rememberstack/workers/fact_window_review.py:77`, `src/rememberstack/spine/fact_window_review.py:298`. One lineage job materializes every affected fact, every evidence row and all associated claim intervals, then creates every follow-up in one tuple. `WorkLedger.complete` inserts those jobs individually in one transaction. A heavily versioned act can therefore require an arbitrarily large allocation and transaction before any progress is durable. The 40-claim limit does not bound preparation: every claim's text is fetched and sorted before slicing. **Fix:** use bounded keyset pages with durable continuation work, compute bases per page, and stream/aggregate complete evidence fingerprints while fetching only bounded model payloads. Add a large-lineage test that verifies page/transaction limits and restart progress. Reconcile §8.2's cost explanation with that concrete mechanism.

## P2

1. **Completed model answers are not durable or shared across duplicate reviews.** `src/rememberstack/spine/fact_window_review.py:204`. The “receipt key” is only a cost-meter key. There is no stored prepared attempt or completed response between `generate` and apply. An apply failure repeats a successful paid inference; concurrent fan-outs can both prepare the same moved basis and both call the model, after which one fails fingerprint validation. This contradicts D118 §4's completed-answer reuse requirement and §8.2's claim that duplicate triggers are free. **Fix:** persist and coordinate a per-fact, per-fingerprint review attempt and its completed response, reuse it after apply retries, and cover it with existing forget fencing/scrubbing. Test concurrent duplicate jobs and failure after inference but before apply commit.

2. **Deletion review enqueue is not crash-safe across deletion paths.** `src/rememberstack/workers/reconcile.py:573` (also `:472`). Version deletion commits its tombstone and cascade before profile refresh and the new enqueue; a crash or refresh failure loses the review request. The source-deletion recovery/finalization path calls `cascade_lineage_removal` without enqueueing review at all. Surviving facts with other support can retain windows based on the removed periods. The public `DocumentDeleter` correctly enqueues inside its transaction, but that does not cover these paths. **Fix:** put the review request in the transaction that changes period visibility for each ordinary deletion path, including source tombstones/recovery, and keep hard-forget's fencing and purge semantics intact. Test interruption and source deletion with surviving support.

3. **The period-correction half of the owner regression is vacuous about the change it claims to test.** `src/tests/workers/test_d140_period_reuse_pg.py:192` (also `:94`, `:233`). The first half genuinely measures incremental Selection/chunk embedding work. The second seeds a fact with NULL `period_basis` and deliberately selects a claim shared by both versions. Moving their common boundary leaves that claim's union `[2024-01-01, open)` unchanged. The fact would need review before the correction solely because its basis was never recorded; the canned `keep` answer also creates no repair/embedding work. Moreover, `_ReuseRig.drain` runs only E0–E2, excluding the real review/label chain. **Fix:** establish and assert the pre-change basis, prove the pre-change fan-out is empty, select evidence whose interval actually moves, require a replacement, and drain review plus projection repair while checking all provider calls and reused hashes/vectors.
