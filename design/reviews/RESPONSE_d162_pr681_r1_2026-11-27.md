# Response to PR #681 design review, round 1

Review of `772268727`. All findings accepted.

## P1

- **Split IDs across packing generations.** The same representation can be
  packed again. P1 upserts by chunk ID within the deployment, and E2 targets
  that ID in the work ledger. The UUIDv5 name now includes the full packing
  generation, including parameter values, alongside the split-rule version
  and span. A same-span repack gets distinct IDs across generations.
  [Repack test](../../src/tests/workers/test_reuse_lifecycle.py#L1040-L1114) ·
  [P1 upsert](../../src/rememberstack/adapters/postgres_p1.py#L262-L280) ·
  [E2 enqueue](../../src/rememberstack/workers/e1.py#L855-L871) ·
  [D162 §2](../../plan/designs/split_oversized_chunks_design.md#2-refine-only-failing-candidates).
- **Empty producers and Claimify reuse.** Selection completes ineligible
  notebook code with zero cards, and D122 hashes those producers in order.
  Ineligible split pieces now key Selection on the exact slice and
  eligibility policy version. Each piece records its own empty completion
  and participates in the window. The specified Rule 4 regression edits only
  Appendix and checks claim reuse with zero paid calls for unchanged Results.
  [Notebook labels](../../src/rememberstack/adapters/converters/notebook.py#L75-L92) ·
  [Empty Selection and Claimify inputs](../../src/rememberstack/workers/e2.py#L540-L606) ·
  [D162 §2](../../plan/designs/split_oversized_chunks_design.md#2-refine-only-failing-candidates).

## P2

- **Offline Claimify stamp.** E2 stamps completed rows, including empty
  results. The offline check must derive `chunks.claimify_input_hash`
  from the candidate's target and ordered producer Selection keys through
  the existing D122 function. Rows without a recorded D122 completion keep
  SQL NULL.
  [E2 stamp](../../src/rememberstack/spine/claim_catalog.py#L388-L394) ·
  [D122 function](../../src/rememberstack/core/selection_references.py#L70-L86) ·
  [D162 §5](../../plan/designs/split_oversized_chunks_design.md#5-offline-benchmark-check).
- **Recovery readiness.** E0 sets `ready` before CHUNK. The recovery rule
  now uses success of the grid's `embed_chunk` ledger work as the E1
  completion signal and requires independent proof of uninterrupted reader
  isolation.
  [E0 status write](../../src/rememberstack/spine/document_catalog.py#L1338-L1359) ·
  [E1 ledger check](../../src/rememberstack/spine/processing_layers.py#L624-L644) ·
