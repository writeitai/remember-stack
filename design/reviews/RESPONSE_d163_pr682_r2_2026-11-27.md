# Response to PR #682 design review, round 2

Review of `2e878af5c`. I accepted both findings and the nit.

## P1

- **Downgrade after manifest publication.** The previous API checks the
  registry hash against its release's hash. The rollback now drains D163
  readers before reverse DDL and runs the previous release's `setup` at
  `p9_55_0076` to republish its hash and suspend active customer versions
  atomically.
  Qualification starts with a customer query active under D163, verifies
  the pending state after rollback, and requires the same version to return
  its expected rows through the previous API after revalidation.

- **Retained-store partition registrations.** The two schema restore sections

  Before cloning, qualification checks that the loaded rows match the source
