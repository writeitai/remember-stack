## P1

1. **R2-P1-1 — `plan/designs/postgres_p1_search_projection_design.md:341` and `:373`: the selected extension does not use the same BM25 scorer for index nomination and the standalone exact tier.**

   **Problem.** Holding one scoring generation fixes statistics and continuation, but does not make these scoring functions equivalent. I inspected v1.5.1, resolved to commit `fa142d049d08eac45a263f5abc250c8877ae076e`. Its index scorer obtains the **raw document length** for unspilled rows and scores it directly ([BMW memtable scorer](https://github.com/timescale/pg_textsearch/blob/fa142d049d08eac45a263f5abc250c8877ae076e/src/scoring/bmw.c#L438-L454)); insertion passes the raw summed frequencies into that store ([insertion](https://github.com/timescale/pg_textsearch/blob/fa142d049d08eac45a263f5abc250c8877ae076e/src/access/build.c#L2082-L2135)). The standalone operator instead always quantizes length through `decode_fieldnorm(encode_fieldnorm(raw_doc_length))` ([standalone scorer](https://github.com/timescale/pg_textsearch/blob/fa142d049d08eac45a263f5abc250c8877ae076e/src/types/query.c#L959-L966)). Its length table maps both 40 and 41 tokens to 40 ([fieldnorm table and encoder](https://github.com/timescale/pg_textsearch/blob/fa142d049d08eac45a263f5abc250c8877ae076e/src/segment/fieldnorm.c#L52-L69)). There are also different floating-point evaluation/accumulation paths, so merely quantizing the memtable length is not a complete equality proof.

   A source-derived counterexample also defeats the stopping rule, independently of whether the SELECT projects the index score or evaluates the standalone expression. Create the index before inserting rows, leave them unspilled, and use one query term. There are three copies of A, one C and one B; all are eligible positive matches. Five nonmatching rows of lengths 147, 147, 147, 147 and 151 make the corpus average length exactly 100. With default k1/b, the score calculations give these approximate values divided by the shared IDF:

   | Matching rows | Raw token length | Query-term frequency | Index score / IDF | Standalone score / IDF |
   | --- | ---: | ---: | ---: | ---: |
   | A × 3 | 48 | 5 | 1.919051 | 1.919051 |
   | C | 50 | 5 | 1.913043 | 1.913043 |
   | B | 67 | 6 | 1.912212 | 1.919721 |

   The index orders A, A, A, C, B; standalone scoring quantizes B's length to 64 and makes B the winner. At k=1 the first `FETCH 4` includes a strictly worse lookahead C, so the specified loop can stop `k_filled` without ever fetching B. Separately, lengths 40 and 41 with the same frequency produce a standalone tie but distinct unspilled index scores, breaking stable-ID equivalence too. These discrepancies require neither zero-score rows nor changing statistics. Block-Max WAND can be exact for its own scorer while disagreeing with the standalone oracle; the missed winner also changes lexical RRF membership.

   **Concrete fix.** Bind one canonical scoring implementation, including length normalization, arithmetic precision and tie equality, across the index, exact tiers and oracle. Require a tested upstream version or reviewed patch that actually supplies it, or specify a bounded reconciliation method whose stopping proof is valid for the canonical scores. Do not assume that rescoring only the fetched prefix repairs a different ordering. Add the 40/41-token fixture with reversed stable IDs, mixed spilled/unspilled rows, multi-term near-ties and both sides of the exact-tier threshold to WP-RS.1/WP-RS.7. If an index-score ranking change is deliberately accepted instead, specify and gate that additional change explicitly and make the standalone tier implement the same ranking. The already-decided positive-match-only policy does not resolve this discrepancy.
