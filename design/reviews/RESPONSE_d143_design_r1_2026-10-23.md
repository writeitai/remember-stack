# Response to GPT-6.1 Sol D143 design review, round 1

Review: [REVIEW_gpt-6.1-sol_d143_design_r1_2026-10-23.md](REVIEW_gpt-6.1-sol_d143_design_r1_2026-10-23.md)
(reviewed head `e139f3e6`). "Design" means `plan/designs/processing_layers_design.md`;
"analysis" means `plan/analysis/processing_layer_toggles.md`. Every finding was accepted. Several
were resolved by simplifying the model rather than adding protocol: switching off now drains
instead of holding, coverage is derived instead of stored, the claims-mode reconcile runs the full
logic minus the fact follow-ups, living lineages are backfilled at their current version only, and
no response field is added.

| # | Finding | Resolution |
| --- | --- | --- |
| 1 (P1) | `Envelope.layers` changes result schemas, descriptors and the manifest hash | Dropped the field. Disclosure uses the existing contract: `boundary` instead of `known_empty` when a channel was not consulted, existing sandbox codes and `QueryResult.warnings`, a new `GET /processing-layers` route (no existing response model changes; `GET /deployment` unchanged), catalogue filtering. Byte-identical default descriptors, manifest hash, catalogues and LoCoMo pins are acceptance test 1. Design §7.3–§7.4, §8, §9.1; D136 refinement note. |
| 2 (P1) | Oldest-first backfill of a living lineage retires claims the current version later reuses | Living lineages are backfilled at the current version only; older gaps are discharged (`skipped` in readiness). A reconcile skips living supersession while the current version has an open claims gap (covers versions arriving during a backfill); unchanged without gaps. Design §4.2, §5.3; evidence lifecycle §5; test 7. |
| 3 (P1) | Gapless in-flight predecessor bypasses ordering | Switching off now drains, so no layer work is held: every version ends complete or with a gap. Advance requires every earlier sources-complete version to be complete (or discharged), so a still-draining predecessor makes the backfill wait for its completion, which advances again. Design §4.3, §5.2; test 8. |
| 4 (P1) | Switching facts off strands the claims tail; previously ready versions need the claims reconcile | Drain (finding 3) means a version that entered facts finishes its full chain. With facts off, readiness accepts `reconcile` at either component version. Design §4.3–§4.4; tests 2, 4. |
| 5 (P1) | Locking is not race-free (no row to lock; last-two-gaps coverage race; writer ownership) | One deployment-scoped advisory *layer fence* (shared for boundaries/advance/seed, exclusive for `setup`), present without a row; fixed lock order. Coverage is derived from open gaps (one indexed `EXISTS`); the stored coverage columns are gone, so `setup` is the sole writer of the configuration table. Design §3.2–§3.4, §5.4; test 8. |
| 6 (P1) | Deleting a blocking head strands successors; late boundaries recreate gaps | Deletion deletes gaps and advances the surviving lineage in the same transaction; boundaries check liveness under the D135 lineage lock and never record a gap for a deleted version. Design §4.1, §5.2, §6.3; test 8. |
| 7 (P1) | Deletion cleanup needs an ungated path | Both reconcile modes run the D135 deleted-testimony path in full (bindings, recount, closure, profiles); there is no claim gate on version-chain work, and drain lets any in-flight E3 finish into the full reconcile. Design §4.2, §6.3; test 11. |
| 8 (P1) | Imported transitions after cycle finalization never close facts | The claims-mode reconcile now runs the same recount/closure/cycle-deferral logic as the full one, so counts are right before the cycle finalizes; no transition import exists. Design §4.2; analysis §5.1; test 9. |
| 9 (P1) | Argument-dependent reads (entity filters) bypass the layer map | Reads have channels and mandatory dependencies, validated after decoding arguments and bound filters and before any embedding or planning; `entity_ids` and the claim search's `entity_id` filter need facts (409 disabled, 422 excluded; sandbox `invalid_parameter`). Design §7.2, §7.5; test 5. |
| 10 (P1) | "E3 reads only current testimony" is false | Corrected (analysis §2). The living policy (current version only, finding 2) means E3 never sees retired testimony during a backfill; snapshot lineages have no retired testimony. Design §5.3. |
| 11 (P1) | Receipt completeness certified against the wrong profile | `profile_complete` certifies the measured profile's layers; a version that can no longer complete them gets `failed` / `processing_profile_changed`; later-enabled layers do not delay a receipt. Design §4.5; test 10. |
